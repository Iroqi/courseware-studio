# 舞台与逐句渲染

## 1. Renderer 的职责

renderer 接收一个句序号：

```js
renderScene(step)
```

输出这一句应该看到的 SVG / DOM 状态。

主循环负责：

```text
audio.currentTime
  ↓
sentAt(t)
  ↓
如果 scene / index 变了 → begin() → RENDER[scene](index) → worldFor() → camSet()
```

**renderer 必须是 (scene, step) 的纯函数**：同一句在任何路径上都画出同一张图。
这条不是洁癖——`export_video.py` 导 mp4 时**每帧开一个新浏览器**、直接 seek 到那一
秒，只跑这一步的 renderer。任何"记住上一步演到哪儿"的写法（模块级可变状态、按
历史推导出来的姿势）都会把第一句的画面漏进后面每一帧。范本实测过：开场那排影子
挂满了整节课。

## 2. 四条纪律

### 纪律 1：不在 renderer 里计时

renderer 不拥有时间语义。禁止用 `setInterval(...)` / `setTimeout(...)`
排程后续视觉状态——句序号是唯一驱动源，`check_gates.py` 会把它报成错误。

要"动"就声明**目标状态**，让 CSS 去补间（§3.5）——renderer 里既不排程也不轮询，
一次性 `requestAnimationFrame` 也不需要。`check_gates.py` 对 renderer 体内的
`requestAnimationFrame` 仍报警告（不报错）：那是在用 JS 手搓补间，回到声明式写法
即可，警告行就是人工确认入口。

### 纪律 2：句号决定步数

一幕有 6 句旁白，就按 6 个主要视觉步设计。不要凭感觉再造第 7 个中间状态。

### 纪律 3：字幕不属于 renderer

renderer 画图，时间轴写字幕。

图元上的文字只能是**短标注**：公式、代码、记号（`🔤 [10,9,1].sort() → [1,10,9]`、
`只看符号`）。检查器会把三类素材与旁白原句做**形状**比对：renderer 体内名为
`txt()` / `badge()` 的写字函数调用、`textContent` / `innerHTML` /
`createTextNode` 直接赋值的字符串字面量、以及页面除字幕钩子外的静态 SVG
`<text>`（按函数名匹配——自造 helper 起这两个名同样被覆盖；机制细节见 runtime.md
§8 第 2 条）。判据是形不相似，不是意不相似：
把标注写成短语 / 代码而不是完整句子，天然安全；把旁白那句话原样抄进图里必踩。

### 纪律 4：图形表达优先于装饰

| 结构 | 常见形式 |
|---|---|
| 顺序 | 流程图 |
| 关系 | 关系图 / 连线 |
| 系统组成 | 分区 / 架构图 |
| 对比 | 双栏 / 对照矩阵 |
| 状态 | 状态块 / 状态图 |

装饰可以有，但不要因此再造一个时间系统。

**结构之外还要先选表现方式**——真实体可以上照片、抽象概念可以生图，见 §8；
内联 SVG 仍是默认形态。

## 3. 舞台模型：常驻图元 + 世界层 + 相机

一幕一屏、每步重建节点的写法有两个天花板：节点是新的，所以东西**没有"从哪儿来"**
（只能凭空出现）；场景是孤岛，所以**上一幕的主角走不进这一幕**。模板把舞台换成三层：

```text
<g clip-path="#frameClip">   ← 取景框：字幕带以上才是画面（硬边界）
├ <g id="depth">             ← 远景视差层（纯装饰，比 #cam 慢一拍）
└ <g id="cam">               ← 唯一的相机，camSet() 每步声明一个取景窗
  ├ <g id="world">           ← 跨幕常驻的主角：POSE 给姿势，WORLD 给哪一步用哪个
  └ <g id="stX"> / <g id="x-body"> ← 这一幕的局部图层
```

### 3.1 建档 / 写状态 / 撤走

| 调用 | 作用 |
|---|---|
| `begin()` | 主循环每步一次，开一个世代号 |
| `put(parent, tag, key, attrs)` | **写目标状态**：这个 key 没见过就建档（入场），见过就地改属性 |
| `txt(parent, key, attrs, s)` | `put` 的写字形状 |
| `badge(parent, key, x, y, s, col)` | 短标注：药丸底 + 居中字 |
| `sweep(parent)` | 本步没被写过的 key 撤下台（递归整棵子树） |

规则只有一条：**这一步看到的每个图元，都要在这一步被写过一次**。写了就留下，
属性变了就补间，没写就被撤走。所以"淡出"是把 `opacity:0` 再写一步、下一步不再
引用——不是自己消失。

节点复用是这一切的前提：同一个 key 在下一步拿到的是**同一个 DOM 节点**，CSS
transition 才有"上一状态"可补间（实测：相邻两步 `getElementById(key)` 同一对象）。
key 同时写进 `id` 与 `data-key`，所以嵌套建档只要父节点那一步写了 key 就够。

### 3.2 世界层：跨幕常驻

段与段之间最贵的不是新画面，是"刚才那三个数去哪了"。把主角写进世界层，它就
被观众一路认出来：收上台当参照物、被搞乱、最后回到台上回答问题。

```js
var POSE  = { bench:{y,xs,k,op,quoted,tone,order}, shelf:{…}, messed:{…} };
var WORLD = { 'seg-1': ['bay','bay','sorted','shelf'], 'seg-5': ['off','off','off','off','messed','messed'] };
```

- 姿势是**整步的快照**：位置、缩放、灯亮不亮、染色、顺序一次给全，段内不换姿势就
  不会在两句之间漂一下重心；
- `WORLD[scene]` 里没写到的那一步**沿用本幕最近一个写过的姿势**（画面上就是站着
  不动）；整幕没写 = 主角不在台上（`off`）。沿用是**在这一步就地回推**的，不是记
  住"上一幕演到哪儿"——那是 §1 纯函数约束的头号反例；
- 局部图层不要在世界层里重画主角。范本舞台 B 只画两行逐位比较，被排的那三个数
  始终由 `#world` 承担。

### 3.3 相机：取景窗就是构图声明

```js
var CAM = { 'seg-2': [ FULL, [230,61,580,120], [300,72,460,110], … ] };
```

窗是**世界坐标** `[x, y, w, h]`；没写的那一步 = `FULL`（identity，与"不做任何变换"
等价，不会莫名缩放）。`camTo()` 把窗的中心钉到画布可用区中心，倍率钳在
`0.85–1.8`：低于下限会把内容裁掉，高于上限字会糊到画布外。三件事一并解决：

- **运镜**：旁白说到哪一位，窗就框到哪一位（`#cam` 的补间时长由这一趟真的走了多少
  现求，`.5s–.78s` 之间，0.24.0 之前是恒定 0.6s，见 §3.4 位移定拍）；
- **重心**：声明了窗就等于声明了构图中心——§6 那条"逐场景量 `getBBox()` 配平"
  从人工活变成读表活，一眼就能看出哪一步把内容丢在了画外；
- **窄屏兜底**：窄屏下没声明窗的步按 `contentBox()`（可见内容并集包围盒）居中，
  桌面不动镜头。

取景框是**硬的**：`#cam` 外面套了一层 `clip-path`。镜头推近后可见区仍然是整个
`viewBox`（比窗大），不裁的话被留在身后的内容会一路画到字幕带上、字压字——实测
踩过。所以任何落在字幕分隔线以下的内容都会被裁掉：排版时把它当画布下沿。

建档即入场，所以**要动的东西在它该动的那一步才建档**：早一步建好压着
`opacity:0`，动画会在没人看见的那一步跑完，轮到时只剩淡入。
**一屏一个话头（0.28.0 动效目的审计）**：每个镜头先问"这一屏最想让人看懂
的一件事"，其余内容按先后排——没轮到的退居参照（`data-dim` + opacity .45，材质
弱化是"退居背景"不是"淡出到一半卡住"，见 0.13.0），不跟话头抢同一拍淡入。四个
目的（引导视线 / 展示变化 / 推进叙事 / 操作反馈）是审计的口径：每一个动效都要
能回答"它为什么在这"，回答不上来的漂浮、乱弹、机械逐字一律砍。两处实例：
① renderB 的第二对（"10","9"）s4 才被点名，s0–s3 整行退居参照——但 flip 包装
必须 s0 就在场（翻面是"两个状态之间的过渡"，补间开始前节点要已建档），所以是
压暗不是删除；② 磁吸 / 涟漪 / 掠光 / 橡皮筋是**操作反馈**（网页保留），decode /
换场 / 翻面 / 弧凸是**推进叙事**（成片保留），两者在 reduce 与导出下各自关闭，
互不牵连。

inOut。悬浮/幕布/元素淡入这类"本来该有手感却写成魔法数"的地方也一律走令牌
（0.13.0 收的口）。**唯一的例外是 `.flip`**：翻面要求"角度对时间居中"，只有对称的
`--ease-in-out` 成立，用 `--ease-out` 实测背面要倒着走 235ms（见本节末 0.20.0 那条）。

**错峰入场**：`.in` 支持 `--delay`（`animation-delay:var(--delay,0s)`），
现成档位 `.st1/.st2/.st3`（60/120/180ms），也可以直接写在元素上
（`style="--delay:.55s"`）。一组同幕图元按序上浮是前沿动效最常见的节奏手法；
**错峰只建议用于同一步的一组图元，最晚元素延迟 ≤ 180ms**——单独截一帧仍然讲得
清。0.18.0 起这件事有了一条不用数个数的写法（`.stag`，见本节末），模板门禁卡片
原来那三份 `nth-child` 魔法数已经换成它。**一处行为收窄**：`--delay` 自 0.18.0 起
注册成 `inherits:false`，写在**外层包装节点**上不再传给子节点的 `.in`（以前作为
未注册 token 会继承下去）——这是刻意的，见下面 `.stag` 那条的第 ② 边界；要让一组
图元整体错开就挂 `.stag`，要让某个图元单独错开就直接写在它自己身上。

**微动效（0.11.0，现代交互的"手感层"）**：三处小动画，全部只动
transform/opacity——检查器判字幕可见性走 opacity/visibility 链，动效
不影响判定；导出页禁动效，成片不受影响：

- **进度条平滑补间**：`.bar-fill` 有 `transition:width var(--dur-fill) linear`
  （`--dur-fill:.25s`），播放与拖动时进度不再每拍跳变，而是连续滑动；
- **字幕翻句微动效**：`#cap-text` 文本真的变化时由 `capShow` 重触发
  `.capLift`（`capLift` keyframes 只上浮 6px，`--dur-cap:.22s` + `--ease-out`）。
  同句重显（pause 后恢复）不重放，空档保留上一句也不误触发；
- **门禁反馈微动效**：答对 `fbOk` 轻弹入场（淡入 + 上移 4px）、答错 `fbBad`
  横向抖动（±4px 两摆），`--dur-fb:.32s`。runtime 每次尝试都 remove+add
  状态 class，动画天然重触发——这是现代表单反馈的标准手感。

以上三条一并纳入 `prefers-reduced-motion` 兜底（`animation/transition:none`）。

**播放器动效体验（0.12.0）**：进度条是播放器里最常被碰的控件，动效落在"手感"
而非花哨上——**弹簧缓动令牌 `--ease-spring`**（`linear()` 逐点近似过冲回弹，
前沿缓动技术；浏览器不支持 `linear()` 时声明作废、自动回退上一值，已应用于答对
反馈 `fbOk`）；**拖动跟手**（`.bar[data-drag]` 把填充过渡缩到 50ms、松手恢复
`--dur-fill` 滑行到位）；**当前章节刻度点亮**（`.tick.on`，常驻"你在哪"位置 cue，
纯颜色变化非循环动画）；**窥探气泡改 pointer 事件**（指针捕获期间兼容 mouse
事件不可靠，pointermove 悬停/拖动都稳定触发）。

**焦点弱化 / 按压手感 / 运镜模糊 / 章节翻场（0.13.0）**：这一轮把"注意力"和
"手感"两件事做成了原语，四项都在真实 Chrome（CDP）里量过才写进范本：

- **焦点弱化 = 材质变化，不是消失**（前沿做法：注册自定义属性补间 filter）。
  `@property --dimmer{syntax:'<number>'}` 把 `--dimmer` 注册成数字，`transition`
  才能逐帧补间它；`[data-dim="1"]` 用它驱动
  `filter:saturate()/brightness()`。**只碰 filter，不碰 opacity**：CSS 的
  opacity 会盖掉 renderer 写在呈现属性上的逐句档位（`.45` / `.7` 是作者的话，
  两者打架过）。renderer 侧只写档位：
  `put(parent,'g',key,{'data-dim': dimmed?1:0, opacity: dimmed?.45:1})`——
  弱化退到背景的东西仍能被看见当参照，比"淡出到一半卡住"更像"退居背景"。
  浏览器没实现 `@property` 时 `--dimmer` 不补间、filter 直接跳档，**终态一致**。
  注册名**必须避开调色板已有的 `--dim` 色值**：`@property` 的作用域是整页，
  一旦把 `--dim` 声明成 `<number>`，那十几处 `color:var(--dim)` 的灰字会在计算值
  阶段判为非法、整条作废回落到继承色（实测 `#8d95a8` 变 `#e9ecf3`）。这类
  "注册一个同名属性"的改动，动手前先全仓 grep 一遍同名令牌。
- **按压手感**：可点的东西都有 `:active{scale:.9/.94}`（独立变换属性，不写进
  `transform`）。注意独立 `scale` **先于** `transform` 合成，会连 transform 里的
  位移一起缩放——实测 `.hs` 用 `transform:translate(-50%,-50%)` 居中时按下去
  漂 2.2px，改成 `translate:-50% -50%`（独立属性不参与缩放）后位移为 0。
  SVG 里同理：同节点写 `transform` 属性 + `scale` 会漂 50.4px，`transform-box:
  fill-box` 救不了，得外层位移、内层缩放。
- **运镜运动模糊**（"速度决定模糊"的真实摄影机手感）：`camBlur` 0%/100% 都是
  `blur(0)`，只在中段糊一下——与循环动画 `0%` = 静止态那条导出纪律同源，截图页
  一刀切掉 animation 落在清晰定格上。只在**真的挪了一次镜头**时触发
  （`camBlurOK`：位移 > 180 世界单位，或倍率相对变化 > 22%）；冷启动第一步、
  进度条擦洗期间、`__coursewareShotMode` 下一律不糊；不达标的这一步必须主动
  `remove`，否则上一次的 class 还挂着，下一步小移动会再跑一遍。
- **章节头翻场**：`#chapter` 换节时重放 `.chFlip`（6px 上浮，`--dur-ch:.22s`）。
  判据是"换节"不是"换句"——`tick()` 那个分支每句都进，所以另存 `lastSceneIdx`
  比对；写成每句抖一下就是闪烁。重触发口径与字幕翻句同款：remove → 读一次几何
  → add。

以上四条一并纳入 `prefers-reduced-motion` 兜底（`#cam.blurpass` /
`.chapter.chFlip` 关动画）；按压手感与焦点弱化本来就是"状态即终态"，过渡被
`transition:none` 收掉后直接落档——关掉动效，画面信息一格不少。

**空间与连续性（0.14.0）**：0.13.0 管的是"注意力在哪"，这一轮管"画面是有深度的
空间"和"换节是有方向的行进"。三项同样在真实 Chrome（CDP）里量过才写进范本：

- **远景视差（`#depth`）**：镜头每落一次，远景按 `--par-far`（.45）**同向**漂一小段。
  方向要与镜头同号、幅度更小——写成反向或等幅，读起来分别是"背景在逃"和"同一张纸"。
  远景**只跟着漂、不跟着放大**，这一条恰恰是"它很远"的线索。两个工程约束：
  ① 它必须是 `#cam` 的**同级兄弟**（同一个世界坐标系、位移量直接可加），塞进 `#cam`
  会顶掉那层 `transform` 属性值；② 位移量取 `camTo()` 回传的 `tx/ty`，**不要在别处
  重算钳位公式**（倍率钳位只有那一份口径）。系数由 JS 从令牌读
  （`getPropertyValue('--par-far')`），令牌被改名时 `parseFloat` 得 NaN、落回默认档。
  位移挂在父层 `transform` 上，**不改变子节点的 `getBBox()`**（实测推到 `translate(-420,-260)`
  世界层包围盒一格没动），所以相机取景、窄屏兜底与 QA 几何判定都不受影响。
- **方向感换场（`.el.swF` / `.swB`）**：前进从右侧进、后退从左侧进——章节头已经报了
  "换节"，画面这一层再给出"往哪儿换"。判据与 `.chFlip` 同源（`lastSceneIdx` 比对，
  **换节不是换句**；挂在换句分支上就是每句推一下的闪烁），冷启动第一步不演（没有
  "上一节"可比），擦洗与 `__coursewareShotMode` 下一律不演（与运镜模糊同一口径）。
  位移写在**独立 `translate` 属性**上（理由同 0.13.0 那条 `.hs` 教训：独立属性不
  参与缩放、也不顶掉作者写在 `transform` 属性上的位移），且不进 `getBBox()`。
  **一个必须记住的重放坑**：换幕时退场的那一幕要把 `swF`/`swB` 一起摘掉（范本在
  `only()` 里做）——class 滞留的话，下一次入镜会把旧动画重放一遍；正常播放时
  `sceneSlide()` 自己摘重挂看不出来，而导出是**每帧一次冷启动**、那一帧就停在
  半推半进的位移上。
- **结论句划重点（`#cap-hl`）**：`hl:true` 那一句除了换主色，再沿自己的字宽划一道
  半透明色带（kinetic typography 的克制版：一个连续动画，而不是只换个颜色）。
  几何**从字幕自己量**（`capShow()` → `capHl()` 取 `getBBox()`），因为字号有桌面 17 /
  小屏 26 两套档位，写常数必错位；色带写在 `#cap-text` **之前**，字压在上面。
  `x`/`width` 是 SVG 的 CSS 几何属性（Chrome 152 实测可补间），同时把值也写进呈现
  属性作兜底——不支持的浏览器直接落终态。**非结论句一律写 0 宽**：收起与生长起点
  是同一次写，否则上一句的色带会赖在下一句下面。色带承担"这是结论"的强调，属
  **状态**不属装饰，所以 reduced-motion 下只关 transition、终态照留。

`prefers-reduced-motion` 兜底同步：`.el.swF` / `.el.swB` 关动画、`#depth` 关补间、
`#cap-hl` 关过渡（终态保留）。时长与系数新增 `--dur-swp` / `--dur-hl` / `--dur-tick` /
`--dur-rack` / `--par-far` 五个令牌，顺带把刻度点亮与窄屏/全屏播放器行那几处残留
魔法数收进令牌。

**生长与揭示（0.15.0）**：前面几轮动的是"位置、颜色、层次"，这一轮动的是**形状
本身**和**出现的方式**。三件事都在 Chrome 152 里逐项量过边界才写进范本，量不到
的边界一律写成"别这么干"：

- **SVG 几何属性补间（`.nt` 的 width/height/x/y/rx/ry/cx/cy/r/d）**：Chrome 把这些
  几何属性收进了 CSS，写呈现属性就能补间——框可以**跟着字长大**，不用再靠
  `transform:scale()` 假胖。清单**不是全几何**：`rect` 的 x/y/width/height/rx、
  `circle` 的 cx/cy/r、`ellipse` 的 rx/ry、`path` 的 `d` 在列（`d` 要两条路径命令
  序列同构，否则整条跳档）；**`<text>` 的 x/y 与 `<line>` 的 x1/y1/x2/y2 不在列**
  （计算值恒为 0px / 空）——文字的位移只能靠 `transform` 或独立 `translate`，
  连线要动就用 `.draw` 或挂父层，写成 transition 是白写。
  范本的 `poseWorld()` 因此改成**现量**：先落一个够用的占位框，`getBBox()` 量出标签
  字宽，再写终值（`width = max(74, 字宽 + 28)`，圆角跟着宽度走）。顺带修掉范本的
  真实缺陷：写死的 96 只算过不带引号的字形，quoted 姿势加引号后桌面档 '10' 字宽
  96.3 就压过边、小屏档（字号由 `put` 统一放大到 52）顶到 125.1，字整个糊到框外。
  **占位框只给新建档写**（`if (!REG[boxKey])`）：复用节点再写一遍占位宽，会被当成
  一次真实状态变化，画面先补向 96 再掉头补向终态——那是肉眼可见的抖动，不是生长。
- **擦除揭示（`.reveal` / `.revealL`）**：不是"淡进来"，而是用 `clip-path:inset()`
  **从一侧扫出来**（左→右读作"往后推演"，右→左读作"回溯"——方向本身带信息，
  这是比淡入多出来的那半句）。范本两个消费者都在"这一行是刚串出来的"场合：
  舞台 B 的结论记法用 `wipeR`，舞台 C 的降序行用 `wipeL`。四条边界：① 只裁剪
  不位移，`getBBox()` 全程恒定（取景、窄屏兜底、QA 几何判定都不受影响），但
  **命中测试跟着裁**，还没擦到的那半截点不着，不留"看不见却点得着"的幽灵区；
  ② 挂在**包装 `<g>`** 上而不是图元本身（`clip-path` 与 `.nt` 的 transform 补间
  同节点会互相干扰）；③ **两端都要写成 `inset()`**——只写 `from` 时隐式 `to` 取
  元素自身的 `clip-path:none`，而 `inset()` 与 `none` **不可插值**，浏览器按
  discrete 处理，画面只剩"全遮"和"全显"两格中间硬跳一下（这轮第一版就是这么写的，
  量出来才发现）；④ 与 `.in` 一样用 `backwards`，不写 `forwards`。导出截图页一刀
  切掉 animation 后落回 `none` = 完整揭示的定格。
- **折叠面板（`interpolate-size` + `display` 参与过渡）**：侧栏 `note-body` 从
  `display:none` + 一段淡入，换成 **0↔auto 高度连续开合**。三个口径，前两个都是坑：
  ① `:root` 的 `interpolate-size:allow-keywords` 让 `height:auto` 参与插值——不用
  猜 `max-height` 魔数，也不用 JS 量 `scrollHeight`；不支持的浏览器整条作废，
  退回"瞬间开合 + `noteIn` 淡入"，仍讲得清；
  ② **`display` 必须同时出现在 `transition-property` 清单里**——
  `transition-behavior:allow-discrete` 只管"已经在补间的属性"，没列进去就还是
  即时切换，实测开合半边有动画、半边是跳的。语义正好是想要的：展开当帧就
  `block`（没盒就没得演），收起撑到补间结束才 `none`（collapse 演得完，又不把
  hidden 内容留在可访问树和 Tab 序列里）；
  ③ `transition-behavior` **单独一行写**：塞进 `transition` 简写里出现浏览器不认的
  关键词会**整条作废**，把 height 补间一起带走；分开写的最坏情况只是 display 立刻
  切换，降级仍有得看。起点靠 `@starting-style` 给（从 `none` 切 `block` 那一帧
  没有"上一状态"，不写它动画不跑）。`noteIn` 那档淡入留着——它是内容层面的提示，
  与面板高度的连续运动是两件事，reduced-motion 下各自关。

`prefers-reduced-motion` 兜底同步：`.reveal` / `.revealL` 关动画（关掉后内容直接
完整在场，没有"半截揭示"留在定格上）；几何生长挂在 `.nt` 上，已被那条
`transition:none` 收掉，框宽照旧落属性、一步到位；折叠两头都关。
**折叠那条兜底要多带一层元素选择器**（`li.note .note-body`）才真的落上：
`.note-body{...transition:...}` 那条基础规则在源序上排在媒体块**之后**、特异度又
同为 (0,1,0)，后来者胜——单写 `.note-body{transition:none}` 会被顶掉，这时兜住
画面的只是全局那条 `.01ms!important` 的时长钳制，不是这一行。

**时间刻度层（0.16.0）**：前面几轮的动效都在回答"这一步发生了什么"，这一轮回答的是
**"现在到哪儿了"**——把"进度"这件事做成可以看见、也可以摸到的刻度。三件事的分工很
不一样，一条是状态、一条是读数、一条是纯装饰，所以兜底方式各走各的：

- **擦洗态变厚（`.bar` / `.bar .tick`）**：平时进度条是一根 6px 的发丝线，只管"读到
  哪儿了"；指针落上来 / 键盘聚焦 / 按下拖动时它升到 9px、刻度从 12px 长到 16px——
  **把"现在可以拖"画在你正要指的地方**，而不是在旁边再摆一个可见把手（frontier 做法
  里的 affordance-on-intent）。三条边界：① 只长高、不加 margin，轨道自己占住那几 px，
  `.rack` 行高不跳，读数与倍速钮一格不动；② 圆角跟着高度走（6/3 → 9/4.5），填充写
  `border-radius:inherit`，否则 9px 的条顶着一式为 6px 定的圆角、两端发方；③ 过渡清单
  只给 `height` / `border-radius` 这两条**几何**，不给 `width`——填充的补间是
  `--dur-fill linear`（"进度连续滑动"的口径），两套混进一条清单就等于给进度装了第二
  个时钟。刻度纵向用 `top:50%` + 独立 `translate` 居中，所以"条变厚、刻度一起长"这两
  种高度共用一条居中公式（各探出 (刻度高 − 条高)/2），不必为第二种高度再补一套数字。
  Chrome 152 实测逐帧采到 6 → 7.13 → 7.92 → 8.41 → 8.84 → 9。
- **句内进度细线（`#cap-prog`）**：结论色带说"这句是结论"，这条细线说"这一句念到哪儿
  了"（karaoke / now-playing 的做法），但它落在字幕自己的宽度上，不新增一行常驻 UI。
  它**不是动效，是时钟的逐拍读数**，所以口径全部相反：只写**呈现属性**、不写 `style`、
  不挂 `transition`、**不进 reduced-motion 清单**（关了动效它也得跟上嘴）。几何
  `capShow()` → `capMeasure()` 现量一次存进 `capGeo`，`tick()` 每帧只按
  `(t - sent.start) / sent.duration` 写 `width`——把 `getBBox()` 留在每帧路径上就是给
  逐帧循环加一条同步重排（§5）。两个必须记住的位置约束：**调用点排在换句分支之后**
  （`capShow` 才写 `capSent`/`capGeo`，写在前面会拿上一句的宽配这一句的进度；导出是
  每帧一次冷启动、那一帧往往就是换句帧，实测那样截出来的是空线）；**空档不清零**
  （gap-hold 同一口径，字幕停在上一句，细线停在满格），`ended` / 开场前才归零。
- **侧栏滚动驱动入场（`animation-timeline: view()`）**：本轮唯一"前沿"做法，也是唯一
  一条**不归 JS 管**的运动——没有 scroll 监听、没有 IntersectionObserver、没有 rAF，
  进度直接由滚动位置取。四条边界：① 整块包在 `@supports (animation-timeline: view())`
  里（Firefox 正式版未开），而隐藏态只写在 keyframe 的 `from` 里，所以不支持的浏览器
  整块跳过、文字一格不少——渐进增强的正确姿势是把风险放在装饰那侧，**绝不把内容锁进
  一个可能不跑的门里**；② `animation-duration:auto` 显式写（滚动时间线按进度而非秒
  分配），长写放在简写之后；③ `animation-range:entry 0% entry 60%`——**第一版写的
  `entry 0% cover 32%` 是错的**：entry 段只占 cover 全长的 e/(e+v)（条目 45px、栏
  533px → 约 8%），cover 32% 远在"完全进入"之后，于是侧栏**根本不溢出**时下面三条仍
  停在 0.998 / 0.974 / 0.845，一条装饰性入场把常驻内容留在了半透明那一格。改进取
  entry 段内（进度以条目自身高度算），静止时全部落 1；④ 位移挂独立 `translate`。
- **气泡弹簧落定（`.tip.tipPop` + `--ease-spring`）**：窥探气泡出现时轻弹 7px 落住，
  与刻度长高是同一个动作的两半。`transform` 里**每一帧都要重复写 `translateX(-50%)`**
  ——动画期间的 transform 整条接管静态值，只写 `translateY` 会让气泡在落定那一瞬往
  左跳半个身位（`left` 仍由 JS 逐点写，一个走 transform 一个走 left，不打架）。
  重触发判据留在 JS 的差分里（`data-on` 与节号），因为 `pointermove` 每帧都进这条
  处理器，无脑摘重挂就是"气泡一路抖着跟手"。

顺带修掉范本的一处真缺陷：**结束态把进度条拖回最后那句，字幕带会一直空着**——`ended`
收了整条带子并清掉 `capSent`，而回拖落进**同一句**时句号没变、换句分支不进，画面、
读数、细线都跟着回来了，只有字幕带还空着（违反"页面状态 = currentTime 的纯函数"）。
`tick()` 里按 `capSent !== hit.sentence` 补一次 `capShow`：同句不重挂、不重量，也就
不每帧多一次 `getBBox`。

`prefers-reduced-motion` 兜底同步：擦洗态几何关 **transition**（关时长即直接落
9px/16px，"可以拖"仍然看得见，只是不"长"过去）、气泡关 **animation**（`data-on`
那条 opacity 不是动效，气泡照出、只是不弹）、侧栏入场整条 **撤掉** `animation`。
撤掉那条同样要**抬特异度**（`ul.notes>li.note`）：入场规则写在 `.notes` 段里、源序
排在媒体块之后，朴素 `li.note{animation:none}` 会被它顶掉；也不能只靠全局
`.01ms!important` 的时长钳制兜住——滚动时间线要求 `duration:auto`，钳成 0.01ms 后
落在哪一格是实现说了算，装饰性入场不该把"内容看不看得见"押在没测过的边界上。
**句内细线不在兜底清单里**：它是读数不是动效。新增 `--dur-scrub` / `--dur-tip`
两个令牌。

**边缘与材质（0.17.0）**：前几轮把"注意力、空间、时间刻度"都做成了原语，这一轮动的是
**边缘的软硬**与**表面的材质**。四条都过 CDP + 像素取样，量不到的写进"别这么干"：

- **羽化揭示（`.featherR` / `.featherL`）**：与 `.reveal` 说同一句话（"这一行是刚长出来
  的"），但**边缘是软的**——`clip-path` 的边界是一条硬边，扫过去像切纸；mask 的渐变带推
  过去像光晕掠出，适合结论/记法这种不该打扰观众的内容。驱动变量
  `@property --feather{syntax:'<percentage>';initial-value:134%}`，渐变停靠点跟着它走
  （`#000 0 calc(var(--feather) - 34%)` + `transparent var(--feather)`，34% 是斜坡宽度）。
  四条边界：① **静止态必须是全显**——initial 取终值 134%（不透明段占到 100%，整条遮罩带
  已移出右侧），于是不支持 `@property`（替换后仍是合法 100%）、不支持 CSS mask（声明作废）、
  导出截图页一刀切掉 animation（落回元素自身值）这三种"动画没跑"的情形**都落在完整可见**
  上（纪律 3 的同一口径）；② **mask 不裁命中测试**——这是它与 `clip-path` 最关键的区别
  （实测把 rect 左半边遮掉之后 `elementFromPoint` 打在那半边照样命中），所以羽化层自带
  `pointer-events:none`：宁可这一层不可点，也不留"看不见却点得着"的幽灵区。**需要 Learner
  点的图元一律用 `.reveal`**；③ 挂在**包装 `<g>`** 上、不进 `.nt` 的 transition 清单（mask
  的参考盒是元素包围盒，与 transform 补间同节点会一起被缩放，0.15.0 那条 clip-path 教训
  同一课），实测 `getBBox()` 全程 [4,6,292,28] 一格不动；④ 两端都写百分比 + `backwards`。
  实测逐帧采到 0% → 88.5% → 128.8% → 133.8% → 134% 的连续值，不透明停靠点恒等于
  `--feather − 34%`（软边宽度确实挂在移动的渐变带上）。范本消费者是舞台 D 末句那行绿色
  记法（`d-fix-w`）。
- **放行键掠光（`.gate-next .go.shine`）**：答对之后"继续"出现的那一下，一道高光从左掠到
  右——CTA 的邀请语言（Stripe / Linear 那类主按钮同款）。四条边界：① 用**伪元素 +
  `background-position`**，不是 mask（这里要"加一道亮"不是"遮一块"）；② **静止态停在盒外**
  （base `background-position:120% 0`，keyframes 两端都写位置 120% → −60%），跑完与 reduced-motion
  都是"无光泽的正常按钮"（实测静止取色 27,35,48 = 纯底色，跑动中同一位置 133,137,144）；
  ③ `pointer-events:none` + 宿主 `overflow:hidden`——不抢点击、出界被圆角盒裁住；④ 只演
  "这一行从无到有"那一次，判据是 `hidden` 的**旧值**，所以 `var nextShown = !gateNext.hidden;`
  必须排在 `gateNext.hidden = false;` **之前**（写后面判据恒真，同一个键会被反复刷亮，
  那是闪烁不是邀请；差分口径同 0.16.0 气泡）。
- **排版留白层（`text-wrap:balance` + `text-box-trim`）**：两条都**不是动效**、不新增时钟。
  `balance` 让多行标题每行等长（340px 容器实测 [317,223] → [279,261]；单行两档逐值相同，
  对短标题零成本）；`text-box-trim:trim-both;text-box-edge:text` 收走行盒上下的 leading
  （`.tagline` 实测盒高 22 → 15，而 40px 字在 line-height 1.9 下墨区 38px 裁与不裁都是这
  38px——只搬留白、不动可读内容）。`text-box-edge` **只认 `text`**（`cap`/`text-alphabetic`/`ex`
  在本机 `CSS.supports()` 全 false，写上去整条作废）；`pretty` 不写（靠空格分词，中文没有
  空格）。只管 HTML 侧文本，SVG `<text>` 与字幕带完全不受影响。不支持的浏览器整条声明
  作废、一个字不少。
- **主色浅档令牌（`--key-soft` / `--key-softer` / `--key-act`）**：散在六处的
  `rgba(245,166,35,.08~.16)` 收成三档，认得 `color-mix` 的浏览器由 `--key` 现调（换主色
  底色跟着走）。实测 `color-mix(in oklab,var(--key) 14%,transparent)` 与手写 rgba **合成
  像素逐值相同**（48,39,26 / 52,42,26），所以是纯收口不是改观感。**兜底写在 `@supports`
  里，不靠"同名两条声明"**：自定义属性解析期什么都收，`--x:color-mix(…)` 在不支持的浏览器
  照样成立，坏的是**替换之后**那条 `background`——非法计算值让属性落 `unset`（背景透明），
  不是退回上一行。选区 `.28` 与刻度辉光 `.55` 各一处，不为它们造令牌（一个消费者不叫令牌
  系统）；SVG 侧那几处淡底是 amber/red/blue **三套语义色各自的底**，并进来会把"语义色的底"
  说成"主色的底"，不收。

`prefers-reduced-motion` 兜底同步：羽化 `.featherR/.featherL` 关 animation（落回元素自己的
134% = 全显，与 `.reveal` 关掉落 `clip-path:none` 对齐，没有"半截羽化"留在定格上）；掠光
关 animation、伪元素留着（静止态本就停在盒外）。**掠光那行兜底必须带 `#gate-next` 抬特异度**
——基础规则 `.gate-next .go.shine::after` 写在 §④ 播放器行那段里、源序排在媒体块**之后**，
朴素同形选择器 (0,3,0) 平手时后来者胜（0.15.0 折叠、0.16.0 侧栏入场同一课：兜底不是写了就
生效，要真的盖过基础规则）。排版与底色两条**不进兜底清单**：它们不是动效。新增
`--dur-feather` / `--dur-shine` 两个令牌。

**别这么干（本轮实测否决）**：① `@property` 数字 + `counter()` 的里程表数字——不支持
`@property` 时那一段渲染成**空字符串**，把内容锁进一个可能不跑的门，纪律 3 直接不合格
（这是研究报告列为 P0 的建议，量完退回）；② conic-gradient 扫描遮罩用在这套**被缩放的
SVG** 上——圆心与象限在 px/% 两套口径下不一致，实测 sweep_90/180/270 三档扇区全错位；
③ View Transitions / `content-visibility` / `calc-size()` 与"逐句冷启动截图"的导出模型
冲突（各自原因见范本注释）；④ `animation` 简写里引用未定义的自定义属性（`var(--e)` 没
定义）会让**整条简写**在计算值阶段作废、动画根本不跑——探针第一次就是这么"验"出羽化
失效的，写简写时缓动/时长要么给字面量，要么保证令牌在 `:root` 里。

**连线与标注（0.18.0）**：0.17.0 动的是边缘与材质，这一轮回到**连线本身**——让一条
线能"被走一遍"，并让叠在它上面的注记在镜头推拉时读数不变。四条都在 Chrome 152
（CDP 冻结采样 + 逐像素扫描）里量过，量不到 / 不该做的收进本节末"别这么干"：

- **沿线流光（`.flow`）**：一段光沿路径掠过——dash 语言的"掠光"（shimmer along a
  path），比再淡入一次多出来的那半句是"刚走通过"。口径是 `pathLength:1` 归一 +
  `stroke-dasharray:var(--flow-seg) 1`（一个光段 + 一整条空隙）+ `stroke-dashoffset`
  从 `--flow-seg` 补间到 `-1`，`linear`、`.9s`（比画线 `--dur-draw` 长一档：掠过去
  要比画出来从容，`easeOutExpo` 会把大半行程挤进路尾，读不出"一路走过去"）。
  五条实测边界：① **静止态 = 看不见**（offset 落在 `--flow-seg` 时光段整体在路头
  之外，像素扫描整条路零橙色），② **终态也 = 看不见**（补间到 `-1` 推到路尾之外，
  实测 0.16 → -0.13 → -0.42 → -0.71 → -0.999 连续）——这不是缺陷，是语义：掠光是
  **事件**不是**状态**，它不留痕迹，所以导出/关动效天然落回"一条普通线"，纪律③
  与"终态落在属性上"同时满足；③ **必须叠在一条看得见的底线上面**，范本的消费者
  全部按"底线 `.draw` + 流光 `.flow` 分两个节点"摆（同 `d`、同坐标，实测两节点
  `getBBox()` 同为 [300,137,400,41]），谁也不许单独用 `.flow`；④ **与 `.draw` 同
  节点 = 相互抵消**（两条都声明 `stroke-dasharray`，源序后者胜，实测叠一起只剩
  .16/1 的图案、线根本画不满），要"先画出来再流光"就按 ③ 分节点、用 `--delay`
  排先后；⑤ **`pointer-events:none` 是规矩不是可选项**（虚线的**空隙不可命中**，
  实测 hit 落在 dash 间隙返回的不是这条 path，于是"看不见的流光层"会在整条路上
  挡住底下的热区——装饰一律不吃命中，与 `.featherR` 同一条教训）。
- **恒定线宽（`.crisp`）**：`vector-effect:non-scaling-stroke` 把描边钉回**屏幕像素**
  宽度。相机推到 1.8 时 1px 的世界分栏线在屏幕上变 1.8px、糊成一团；实测（范本真实
  口径——SVG `transform` **属性**缩放下逐像素扫描）普通描边 0.5/1/2/3× → 2/4/6/10
  屏幕像素，`.crisp` 恒为 4。两条边界：① **它不继承**（写在相机分组那层等于没写，
  实测父层计算值 non-scaling-stroke、子节点 none），必须逐图元挂；② **只给注记/
  参照线用**——卡片边框、结论色带这些"世界的东西"跟着镜头变粗是对的（真实摄影机的
  前后关系），分栏线/刻度/辅助网格要的是恒定读数；用错对象，推近后内容显出纸片感。
  这里踩过一次测量口径：先用 HTML `<div>` 的 CSS `transform:scale()` 试，两档在 1.8×
  都变 4px 且带模糊斜坡——那是**位图放大**，`vector-effect` 不参与重绘，读数无效；
  范本的相机走 SVG `transform` 属性（每帧重算几何），必须照这个口径重测才算数。
- **自动错峰（`.stag`）**：`sibling-index()` / `sibling-count()` 现算延迟，
  `--delay:calc(min(--stagger, --stag-cap / max(sibling-count() - 1, 1)) *
  (sibling-index() - 1))`——档间距取 `--stagger`，但**总量封顶在 `--stag-cap`**：
  组越大间距越摊薄。实测同一份 CSS 在 2 / 3 / 6 项的组里得到 0s；0/.06/.12s；
  0/.036/.072/.108/.144/.18s，**最后一项永远不超过 .18s**（总量守恒）。作者加图元
  不用回头改 CSS，也不会十项排到 0.6s。三条边界：① **减号两侧必须有空格**——写成
  紧凑的 `sibling-count()-1` 时整条 `calc()` 在计算值阶段作废，而**动画照样跑**
  （`animationName` 仍是 `cardIn`），只是延迟全落 0s，控制台一句话都不报；这是本轮
  最容易静默通过的一条，静态契约用例专门锁这两处空格；② **必须锁在分组那一层**：
  `--delay` 新注册成 `@property{syntax:'<time>';inherits:false}`，`.stag>*` 只命中
  直接子节点、孙子落 0s。不注册的话它是个会继承的 token，在**每个后代**上各自重算
  `sibling-index()`，而 `put()` 的常态是嵌套建档（一个 `g` 里还有 rect 与 text），
  结果是深层小图元也各自错开——那不是错峰入场，是满屏乱闪（实测：分组层 0/.06/.12s，
  其内部后代全部 0s）；注册后 `.st1` 这类手写字面量与 `style="--delay:.55s"` 仍合法；
  ③ 分母用 `max(…, 1)` 兜住单项组（`sibling-count()` 为 1 时分母是 0，整条 `calc()`
  作废——不是退化成 0s 而是非法值）。整块包在 `@supports (animation-delay:calc(1ms *
  sibling-index()))` 里，不支持的浏览器 `--delay` 落回 initial `0s` → 整组同进，
  内容一格不少。消费者：门禁卡片 `.g-card.stag` 的三项（实测 0s / .06s / .12s），
  换掉原来三份 `nth-child` 魔法数——runtime 动态生成的交互块一旦多于三项，第四项起
  延迟落回 0 与第三项同时进；少于三项时后面的档位白占着。
- **描边光环（`.halo`）**：`paint-order:stroke` + 一圈**舞台局部底色**的描边
  （`--halo-bg:#1a2029`），让标注字直接压在弧线/图形上还读得清，不用垫一块药丸底
  （`badge` 那种底在有渐变的方向线上会留一圈看得见的边）。三条边界：① `paint-order`
  必须包在 `@supports` 里（不支持时整条作废，只剩字本身，仍可读）；② 光环色取
  **舞台那圈的渐变底色**而不是 `--bg`，取错就在字周围留一圈深色边；③ 描边宽度用
  `em`（`.22em`）跟着字号走，实测 13px 字上为 2.86px——写 px 常数会在小屏档（`put`
  统一放大字号）露出细缝。

`prefers-reduced-motion` 兜底同步：`.flow` 加进 animation 关闭清单后，静止态本就落在
"看不见"，这一层直接隐形、把画面留给底下的 `.draw` 底线（与 `.reveal` 落
`clip-path:none`、`.featherR` 落 134% 同一课：兜底落的正是终态）。`.crisp` / `.stag` /
`.halo` **不进兜底清单**——前者是线宽口径、后两者是排程与描边顺序，不是动效；`.stag`
影响的只有 `animation-delay`，而它所驱动的 `cardIn` / `.in` 已经在清单里。注意 `.flow`
那行**不需要抬特异度**（与 0.15.0 折叠、0.16.0 侧栏、0.17.0 掠光三条不同）：它的基础
规则写在 §③ 动效原语区、即媒体块**之前**，同特异度 (0,1,0) 时源序后者胜。新增
`--dur-flow` / `--flow-seg` / `--stagger` / `--stag-cap` / `--halo-bg` 五个令牌与一条
`@property --delay`。

**别这么干（本轮实测否决）**：① **SMIL（`<animate>` / `animateMotion`）驱动流光**——它
不吃 `animation:none`，`prefers-reduced-motion` 兜底与导出截图页那一刀都管不住它，
`getAnimations()` 也冻不住（探针拿不到可设 `currentTime` 的对象），于是"量过才写进范本"
这条纪律根本没法执行；② **`offset-path` + 一个小圆点沿线走**——移动的子节点不进
`getBBox()`，检查器与 §5 的几何口径看不见它（量到的 bbox 仍是那条路的），而且它有个
**实体**：切掉 animation 之后圆点落在路径起点，导出帧上多出一个谁也没请的小点。`.flow`
的两个端点都"看不见"正是为了避开这一坑。**0.20.0 对本条做了限定性翻案**：翻案的不是
"能不能用 offset-path"，而是**由谁驱动**——把行程交给 `transition:offset-distance` 并把
终态写在呈现属性 `data-go="1"` 上，切掉 transition 之后落的就不是路径起点而是**终点**
（实测 dist 落 100%、锚点停在路线终点那一格），"实体"那一半随之消失，成了 `.ride`。
仍然成立的是前半句：包围盒不跟着走，所以 `.ride` 只能当**视觉指引**，不当热区、不参与
§5 的连线几何判定（见本节末 0.20.0 边界 ④）；③ **marching-ants（`stroke-dashoffset` 无限
循环的蚂蚁线）**——违反导出边界"循环动画的 `0%` 必须等于静止态"，逐帧冷启动时每帧截到
的相位都不一样，成片里流光位置乱跳；而且无限循环说的是"这里可以走"，不是"刚刚走通过"，
与逐句节拍没有对应关系；④ **用 `transition` 驱动 dashoffset**——renderer 是 (scene,
step) 的纯函数、只写目标状态，同一帧里"建档写起点 + 就地改终态"**不会补间**：实测
computed 值一步落 `-1px`，中间不经过任何行程（浏览器那一帧还没解析过旧值，没有
"上一状态"可比）。要让它补间，得在两次写之间塞一次强制回流或一帧等待——那是在
renderer 里手搓两拍时钟，违反纪律 1；而导出是每帧一次冷启动，那一帧永远只有一拍，
截图里连"补间过"的痕迹都不会有。掠光和 `.draw` 一样必须是"建档即演"的 `animation`。

**退场与逐字（0.19.0）**：前几轮的词汇全在说"怎么长出来、怎么被走一遍"，这一轮补的是
**另一端**——读过 / 讲完的东西怎么让位，以及"正念到哪儿"这件事本身怎么被看见。三条都在
Chrome 152（CDP 冻结补间 + 页内 canvas 合成取样）里量过，量不合格的四条收进本节末：

- **跟读点亮（`--lit`）**：字幕带上念过的字是满墨、没念到的压在灰阶地板上，一条 18%
  宽的软过渡带跟着句内进度推过去——karaoke 的通行做法，但它与 0.16.0 那条句内细线是
  **同一句话的两半**：细线说"走到这里了"（几何），点亮说"这几个字刚被念过"（墨色）。
  口径与 `--feather` 同一条、方向相反：`@property --lit{syntax:'<percentage>';
  initial-value:118%}` 注册成百分比、`inherits:false`，渐变停靠点由它算
  （`#000 0 calc(var(--lit) - var(--lit-ramp))` + `rgba(0,0,0,var(--lit-floor)) var(--lit) 100%`），
  写在 `#cap-text` 的 `mask-image` 上。四条实测边界：**① initial 取 118% 而不是 100%**
  ——`--lit` 是"停靠点"不是"完成度"，写 100% 时 `calc(100% − 18%)` 之后的不透明段只到
  82%，每句**末尾那 18% 永久留在地板上**，静止态变成"句尾永远没念到"，纪律③直接不合格；
  取 100% + 带宽 = 118% 让整行落在不透明段上。② **用 mask 而不是 clip-path**：两者都
  不改几何（`getClientRects()` 与 `getBBox()` 实测逐值不变，`captionShown()` 与取景都
  安全——这条本轮量错过一次，先前按 0.15.0 的 clip-path 教训想当然写了"clip 会让 rects
  没了"，实测两者对 rect 的影响相同），真正的差别只在 **clip-path 会把命中一起裁掉**，
  而 mask 不裁（所以 `.feather` 那层要自己写 `pointer-events:none`，字幕带不需要）。
  ③ **它是读数不是动效**：逐拍写在 `style` 上、不挂 transition、**不进** reduced-motion
  清单——关掉系统动效的用户反而更需要跟上嘴。与 `#cap-prog` 同一条口径，调用点也必须
  排在换句分支之后（`capShow` 才写 `capSent`，写在前面会拿上一句的时长算亮度）。
  ④ 地板 `--lit-floor` 取 **.85**，判据是 §8「半透明按合成后的颜色算对比度」：
  非结论字色 `#c9d1e0` 合成后对 panel / edge = **7.97:1 / 8.53:1**（过次要文字 7:1），
  结论字色 `#f5a623` = **6.08:1 / 6.53:1**（字幕带承载口播原文，按正文 4.5:1 判，且念到
  即回 7.94:1 满档）。"念过 vs 未念"另加一条墨量均值比 ≥1.12 的自检（实测 .85 ≈ 1.132）。
  回归用例里跑的是**页内 canvas 光栅化 + 取 p90 墨像素**那一版（同一套合成色，实测
  7.97 / 8.46 与 6.08 / 6.45，与解析值差在抗锯齿那一档），阈值只写到线（≥4.5、≥7.0、
  均值比 ≥1.10），不锁小数。0.23.1 复按把探针改成**同一串字的两行对照**——行 A
  `--lit:118%` 整行走实心段（念过），行 B `--lit:RAMP%` 整行走地板段（未念），同一批列
  取样：量的才是"地板把同一批像素压掉多少"，比值不再取决于哪几个字落在左半边。改之前
  本机 1.132 而 CI 1.108（两串不同的字互相比 = 让字体决定读数），改之后 1.128 / 1.121 /
  1.140 / 1.128。带子也一律由 mask 的百分比算、`<text>` 钉 `textLength="520"`：CI 跑图里
  没装中文字体时固定列区间会落在字尾之外，取不到墨只留一个 `TypeError`。
- **收拢退场（`.tuckR` / `.tuckL`）**：`.reveal` 的反函数——沿行进方向把那一行**收走**。
  方向口径与 `.reveal` 一脉相承，说的都是**裁切线往哪儿走**：`.tuckR` 线自左向右（左端先
  没，与 `wipeR` 同向，读作"往后推演式地收"），`.tuckL` 线自右向左（右端先没，读作"顺着
  来路撤"）。仓库此前的退场只有一条词汇：写 `opacity:0` 再等 `sweep()` 撤走——"忽然没了"
  只说了"没了"，没说"讲完了"。五条边界，最关键的是**为什么这里走 transition 而不是
  animation**（0.18.0 刚否决过"transition 驱动 dashoffset"，这里前提恰好相反）：
  ① 收拢的对象**必然在前一步已经被写过**（它就是被念过的那一行），复用节点就地改
  `clip-path` 天然有完整行程——暂停补间实测 −15% → 90.95 → 113.23 → 115% 严格单调，
  回拖是同一趟行程倒着走（115 → 9.05 → −13.23 → −15）。于是四条好处同时成立：冷启动
  第一步直接落终态；导出那一刀切掉 transition 后落在那一秒的真实档位（实测
  `inset(-15% -15% -15% 115%)`、`getAnimations()` 为空），**不需要见旗分支**；没有
  `fill:forwards` 钉死终态；class 摘与不摘都落同一张定格（对照 0.14.0 `swF/swB` 那个
  "下一次入镜重放旧动画"的坑——那里是 animation）。**代价**：新建档的节点没有上一状态，
  所以消费者必须"多停一拍"（范本 `e-ties` 写 `step >= 1 && step <= 2`，s3 起才不再引用）。
  ② 两端都必须写**带四个长度的 `inset()`**（`none` 与 `inset()` 不可插值，0.15.0 那条
  discrete 教训）。③ 静止档取 **−15%**（外扩）、收拢档 **115%**（= 100% + 那 15% 余量）：
  `inset(0 0 0 0)` 会沿 fill-box 边缘把描边与 `marker-end` 箭头啃掉（同一根弧线墨量
  1444 → 1410），而收拢写 85% 实测留 46px 能点着的残角。④ **这一层不能当热区**：
  `getBBox()` 与 `getBoundingClientRect()` 全程逐值不变（裁切不动几何，取景与 QA 看不见
  这一层），但命中跟着裁——沿路采样展开档 4/4 可命中、收拢档 0/4。**需要 Learner 点的
  图元不要收拢**，让它留在台上或撤走（与 0.17.0 羽化那条同一家族，只是方向相反：羽化
  遮而不裁，收拢裁而不改几何）。⑤ **`.nt` 与 `.tuck*` 不能同节点**——本轮实测的静默坑：
  `put()` 无条件把 class 拼成 `nt tuckR`，而 `.nt` 与 `.tuck*` 各写一条 transition
  **简写**，撞在同一节点上时赢的那条把输的那条的清单**整串清掉**（简写是全属性重新赋值，
  不是合并清单）。实测计算值 `transition-property` 只剩 `clip-path`，同节点上 transform
  每帧读到终值 320、opacity 每帧都是 .2，一步落档；把 class 写法顺序换成 `tuckR nt`
  再测**逐值相同**——谁赢只看 CSS 源序，没法靠写法顺序绕开。所以 `.tuck*` 只挂**纯包装
  `<g>`**，那个 g 除了 `gone` 不再写任何 `.nt` 会补间的属性（两个消费者都不跟着换 opacity）。
- **CJK 行首标点（`text-spacing-trim:trim-start`）**：全角标点在行首还占着**半个字宽**的
  盒子，一行以「、（、，开头的文案起笔比后面那些字往右缩半格，两条栏就成了锯齿。**量法
  本轮踩了一次坑**：拿块的 `getBoundingClientRect().width` 量得到"零变化"的假结论（块盒
  不受影响），必须用 `Range` 逐行量**墨迹**宽。实测 13px 档行首「：整行墨迹 −6.5px、
  16px 档 −8.0px，两档都恰好 0.5em；行首是汉字逐值不动（只动该动的那半格）；16px 那一档
  还会把断点往前挪一个字（行0 +8 / 行1 −16，相加仍是 −8 = 省下的那半格本来就是空白）。
  因此挂在**会换行的 HTML 正文**上（`.n-txt` / `.gate .q` / `.interaction-feedback` /
  `.chapter .tagline`），整块包 `@supports`。**字幕 `#cap-text` 刻意不挂**：它在 SVG
  `<text>` 上确实生效（实测 bbox 宽 −8.511px、`text-anchor:middle` 下 x 偏移 +4.255），
  但字幕单行不换行、收益看不见，却要动三个派生视图（`#cap-hl` / `#cap-prog` / `--lit`
  遮罩）共用的 bbox 读数；等宽 `code` 与对照行 `.kv` 同理不进。非动效，不进兜底清单。

`prefers-reduced-motion` 兜底同步：`.tuckR,.tuckL{transition:none}` 进清单，且这一条
**不需要抬特异度**（与 0.18.0 门禁、0.17.0 掠光两条不同）——基础规则写在 §③ 动效原语区、
即媒体块**之前**，同特异度 (0,1,0) 时源序后者胜；实测关掉动效后计算值 `transition-property`
就是 `none`，换档那一拍**立即**读到 115%（`getAnimations()` 恒空），回拖又落回 −15%。
`--lit` 与 `#cap-prog` **不进**这一栏：它们是时钟的逐拍读数，关了动效反而必须跟上嘴
（实测 0.2 / 0.8 两点仍读到 23.6% / 94.4%，mask 仍是那条 linear-gradient）。新增
`--dur-tuck` / `--lit-floor` / `--lit-ramp` 三个令牌与一条 `@property --lit`。

**别这么干（本轮实测否决）**：① **拿截图像素的平均亮度算对比度**——第一版就是这么量的，
算出"8.04:1"并据此选了 `.72`，而 §8 要的是**合成色对底色**；换成页内 canvas 光栅化 +
取 p90 墨像素按 WCAG 公式算，同档位实测只有 4.76:1（结论字色对 panel），结论整个翻掉。
② **`--lit-floor:.72`**——墨量差确实更大（均值比 1.250 vs .85 那档的 1.128，0.23.1 同字
两行口径），但结论字色合成后只剩 4.76:1，贴着 4.5:1 线零余量；`.92` 反向失败：均值比掉到 1.063，肉眼分不出
念没念过，等于没做（写满 1 同理，均值比 1.002）。③ **同节点叠 `.nt` + `.tuck*`**——
见上面边界 ⑤，这是静默失效不是报错，别指望调整 class 顺序绕开。④ **用块盒宽度验
`text-spacing-trim`**——块盒逐值不变，量不到任何变化（假阴性）；要量就量 `Range` 的墨迹
矩形。⑤ `text-autospace` / `font-variant-numeric:tabular-nums`——各取值在本机实测零差值
（连字体都没有 tabular 字形可换），不写进范本；⑥ `anchor()` 定位跟随元素——页面只允许
`currentTime` 一个时钟，给指针那一类跟随开第二个时钟与逐帧冷启动的导出模型冲突；
⑦ `forced-colors` 适配——headless 模拟不了，量不到的东西不进范本。

用弱化时记住它是**真的把颜色变暗**，不是错觉：`saturate()`/`brightness()` 与
`opacity` 一样按合成后的颜色吃对比度，被弱化的那一块仍要过 §8 的对比度三查。
mask 的灰阶地板同理：`--lit-floor` 是 alpha 不是颜色，改这一档必须把合成后的墨色
拿出来对底色重算（0.19.0 那三条数就是这么定的）。
判据也简单——**只有"这一步不看它、但它是参照"才弱化**；该消失的东西就撤走
（`begin()` 的自然退休），别留一块糊在背景里抢注意力。

**当面与抵达（0.20.0）**：0.19.0 补的是退场，这一轮补的是**换面与到场**。此前的词汇改的是
颜色（`.nt` 属性补间）、形状（`.reveal` / `.tuck`）、亮度（`--lit`），可课堂上最常发生的
两件事一直没有词：一个记号**当着观众被另一个记号取代**（判决从 `vs` 变成 `<`），和一个
东西**从甲处走到乙处并留在那儿**（这个人的分数落进那一列）。三条原语都在 Chrome 152 里
按逐毫秒冻结采样量过；量不过、或结构与这套模型不合的共五条收进本节末。

- **当面翻面（`.flip`）**：包装 `<g class="flip" data-over="0|1">` 里两面 `<text class="face">`
  与 `<text class="face faceB">`，父层 `transform:perspective(600px) rotateY(0deg → 180deg)`，
  时长 `--dur-flip`（600ms）。五条边界：
  **① SVG 里 `backface-visibility` 是死的**——HTML 卡片翻面那套"两面各 `backface-visibility:
  hidden`"在这里不成立：实测翻到 180° 后 `getScreenCTM().a` 已经是 −1（矩阵确实翻了面），
  而像素层上那面镜像的字**照描不误**。交接只能自己管（见 ③）。
  **② 3D 要写在 transform 的函数列表里**：`perspective(600px) rotateY(θ)` 计算值才落进
  `matrix3d`（实测 θ=0 那一格 m11=1、z 分量 −0.0016667 就是 perspective 留下的），单写
  `rotateY` 是平面镜像、没有远近。相机层里照旧合成（实测 `#cam` scale(1.8) 下 CTM.a 从
  +1.8 连续走到 −1.8，中途不跳档）——这一层可以住在镜头下面。背面自带 `rotateY(180deg)`，
  父层翻到 180° 时两面合成整 360°，读起来是正的字而不是镜像。
  **③ 交接必须落在侧立那一刻，所以曲线必须两头对称**：两面各写
  `transition:visibility 0s linear calc(var(--dur-flip) / 2)`——时长 0、只借 delay，把换班
  钉在行程的一半。而"半程 = 90°"只有对称曲线成立：实测 `--ease-in-out`(.65,0,.35,1) 在
  模板那枚 vs 标签上三个补间一起冻结采样，t=0/150/300/450/599ms 得 θ = 0 / 12.7 / 90.0 /
  167.3 / 180°，两面在场 v,h → v,h → **h,v** → h,v → h,v，交接正落在侧立那一采，全程没有
  一帧两面同显。换成仓库默认的 `--ease-out`(.22,1,.36,1) 再量：θ 在 60.5ms 已过 78.9°、
  约 65ms 就侧立，而交接仍按半程等到 300ms——**背面要在观众眼前倒着走 235ms**，那是穿帮
  不是翻页。所以 `.flip` 是全仓库**唯一不走 `--ease-out` 的原语**，也是唯一要求"角度对时间
  居中"的那一个。
  **④ 只挂纯包装 `<g>`**：`put()` 拼成 `nt flip`，实测该节点 `transition-property` 只剩
  `transform` 一项（`.flip` 源序在 `.nt` 之后，简写整串顶掉它——与 `.tuck*` 边界 ⑤ 同一课），
  所以包装层除 `data-over` 一律不写别的状态；两面拼成 `nt face` / `nt face faceB`，特异度
  (0,2,0) 压过 `.nt` 的 (0,1,0)，实测 `transition-property:visibility` + `delay:.3s` 落得上。
  **⑤ 终态在呈现属性上**：导出那一刀切掉 transition 后，实测背面墨量与"同一行不翻面的字"
  逐像素相同（69 = 69）、正面落 `visibility:hidden`；`elementFromPoint` 命中的是**在场那一面**
  （正面在场 `b-0-vs`、翻完 `b-0-vs-b`），没有"看不见却点得着"的幽灵面——`visibility:hidden`
  天然退出命中树，这一条是白赚的。与 `.reveal` / `.tuck` / `.ride` 同口径：CSS transform 不改
  `getBBox()`，实测正面那一格翻页前后 bbox 同值 [461.3, 147.35, 37.41, 34.72]，一格不动。
  消费者：范本场景 B 比较式那枚 `vs` 在该行出结果的那一句翻成 `<`，两行各自按自己的句子
  错开一拍（实测第二行 s4 才翻）。
- **沿线抵达（`.ride`）**：`offset-path:var(--route)` + `offset-rotate:auto`，补间的只有
  `offset-distance`（0% → `data-go="1"` 那一档 100%，`--dur-ride` 800ms，**linear**）。路线是
  **数据不是动效**：`path('M … L …')` 写在呈现属性 `style` 上，`offset-path:var(--route)` 在
  计算值阶段做令牌替换（实测计算值 `path("M 354 150 L 646 222")`）；**不注册 `@property`**——
  `offset-distance` 自己就是可动画属性，`--route` 不需要被逐帧插值。四条边界：
  **① 状态写在属性上**：`data-go="1"` 才是 100%，0% 是元素自身值。于是三条退路落的都是
  "抵达之后的那一格"（实测切掉 transition 后 dist 落 100%、锚点停在路线终点那一格），冷启动
  同口径，纪律 1 不受影响——这一条就是它与 0.18.0 那条被否决写法的**全部**差别。
  **② `offset-rotate:auto` 让标记自己对准方向**：实测那条 292×72 的斜线上 CTM =
  [0.8243, 0.2033]（含场景 E 相机缩放 0.849），反解 13.86° 与 `atan2(72,292)` 逐值相符，
  箭头/楔形不用 JS 再算一遍角度。
  **③ 行程连续且等距**：实测 0 → 25 → 50 → 75 → 99.875%（t=0/200/400/600/799ms），落定后
  锚点与那条 `.draw` 连线的右端点重合（±2px）。缓动**必须是 linear**：位移是匀速走一段路，
  套 easeOut 会读作"起步猛冲、到站撞墙上"。
  **④ 包围盒不跟着走**：实测用户坐标下 bbox 起步/中途/落定三采同值 [-6,-6,16,12]，屏幕盒
  一路在走（r=6 那枚标记中心 x 336.5 → 462.7 → 588.5）——**QA 与相机看的是包围盒，观众看的
  是屏幕盒**（与 clip-path / mask 那两条同一课）。所以 `.ride` 只能当**视觉指引**：不当热区、
  不参与 §5 的连线几何判定、不拿它验"连上了"。范本里它挂在 `e-body` 而不是 `e-ties`——后者
  s2 起收拢退场，会把走在半途的标记一起裁掉；实测 s2/s3 线收走了人还在，`class` 仍是
  `nt ride`（档位换了 class 不动）。
- **圆形绽开（`.bloom`）**：`@keyframes bloomIn` 从 `circle(0% at 50% 50%)` 推到 `circle(75% …)`，
  `.bloom` 自身静止态就写全开、`animation … backwards` 不写 forwards。用在"这个位置本来该有
  个东西、它空着"（范本拿它开比较式里的空缺格 ∅）：从中心长出一个圆读作"这块是腾出来的"，
  而直边扫描读作"往后推演"——那句话在这里是错的。三条边界：**① 半径百分比按
  `sqrt(w²+h²)/√2` 归一**，而盖住四角要 ≥ 半对角线 `sqrt(w²+h²)/2`，两者一比**覆盖整盒的下限
  恒等于 √2/2 ≈ 70.7%，与长宽比无关**——所以终态取 75% 而不是 100%：实测那张 42×52 的空缺格
  上 50% 咬掉上下边（墨量 142 对 286）、75% 与完全不裁逐像素相同（286 = 286）、100% 纯属白给。
  **② 关键帧两端同型**（0.15.0 那条 `inset()` ↔ `none` 的 discrete 教训），实测 0 → 34.97 →
  62.41 → 73.78 → 75%（t=0/60/150/300/499ms）一路连续无硬跳；不写 forwards，跑完落回自身值，
  取消动画后计算值仍是 `circle(75% at 50% 50%)`——导出那一刀同口径。
  **③ 挂纯包装 `<g>`，且它是本轮三件套里唯一不抢 `.nt` 简写的**（`put()` 拼成 `nt bloom`，
  实测 `transition-property` 完整留着 `.nt` 那九项，因为 `.bloom` 只声明 animation），内层图元
  照旧享受属性补间。clip-path 会裁命中：实测绽开头 60ms 那一格点不着、150ms 圆推到 62% 才
  命中 `b-x00-r`——它本来不是热区所以无害，但**要 Learner 点的图元不要开 `.bloom`**。

`prefers-reduced-motion` 兜底同步：`.flip,.flip .face,.flip .faceB{transition:none}`、
`.ride{transition:none}`、`.bloom{animation:none}` 三行进清单，**都不需要抬特异度**（基础规则
写在 §3.4 动效原语区、即媒体块之前，同特异度源序后者胜——与 0.19.0 `.tuck` 同一条判据，与
0.15.0 折叠、0.17.0 掠光那两条要抬的相反）。实测模拟 reduce 与导出式一刀两种口径下：θ 立即
落 180°、dist 立即落 100%、clip 立即 `circle(75% at 50% 50%)`，`getAnimations()` 恒空——三条落的
都是"完成之后那一格"，与不关动效跑到尾的定格同口径。`--route` 与 `circle()` 的取值本身**不进**
兜底清单：路线是数据、终态是定格，不是动效。新增 `--dur-flip` / `--dur-ride` / `--dur-bloom`
三个令牌。

**别这么干（本轮否决，含两条旧案重按）**：① **HTML 卡片翻面那套两面 `backface-visibility:hidden`**——
SVG 宿主上这条属性不生效（三种宿主各测一遍：`<g>`、带 `transform-box:fill-box` 的 `<g>`、
`<text>`，翻到背面镜像字全在），见上面边界 ①；② **`corner-shape:squircle`**——打在
`<rect rx>` 上零差值，rx=9 那一档逐像素相同（HTML div 上有曲率过渡，SVG 几何不吃），
没有收益不写；③ **`text-wrap:pretty`**——CJK 正文与 `normal` 实测零差值（0.17.0 那条
`balance` 量得到行盒，`pretty` 靠空格分词，中文没有空格）；④ **`@property --num` +
`counter()` 的里程表数字**——0.17.0 已按回去一次，本轮研究报告又把它列成"前沿做法"，再量
结论不变：不支持 `@property` 时那一段渲染成**空字符串**（纪律 3 直接不合格），而且这里所有
读数都是 `audio.currentTime` 的逐拍值，用计数器就是偷偷开第二个时钟；⑤ **View Transitions**
——`startViewTransition` 要等一次异步快照，renderer 是 (scene, step) 的纯函数、没有可等的
第二时钟，而逐帧冷启动导出里每一帧都是首帧（结构性排除，与 0.17.0 ③ 同一条）。

**定盘与成形（0.21.0）**：0.20.0 补的是"换面与到场"，这一轮补的是**判定落下来**与**句子成型**。
课堂上还有两个动作一直没有词：一个结论落定、仪器当场读出方向（比较函数返回 −1 / 0 / +1），
和学习者按下选项那一瞬间的"收到了"。三条原语同样在 Chrome 152 里以 CDP 把补间 `pause()` 后
逐档钉住采样量过。

- **倾侧定盘（`.tilt`）**：包装 `<g class="tilt" data-pan="-1|0|1">`，只补间**独立 `rotate`
  属性**，`--dur-tilt`（550ms）配 `--ease-spring`（注册的弹簧 `linear()`），角度 `--tilt-deg`
  = 6.5°、**只有三档**（− / 0 / +）。五条边界：**① 连续角度在这里是错的**——契约只看符号，
  不看不平衡的程度；**② 不写进 transform**（实测该节点计算值 `transform` 全程 `none`、
  `transition-property` 只剩 `rotate` 一项）；**③ 支点靠 `transform-box:fill-box` +
  `transform-origin:50% 50%`，且包装层的包围盒中心必须正好是支点**——退回 `view-box` 支点跑到
  (500,230)、倾 6.5° 整根梁平飘 6.7px，再省掉 origin 就绕 viewBox 左上角转、屏上位移 69px；
  往这一层多塞一个"挂在下面的支点三角"，包围盒从 [406,280,188,12] 胀成 [406,280,188,24]、
  中心从 y=286 掉到 y=292，倾侧时梁又平移 0.7px（所以支点画在包装层**外面**，静止不动）；
  **④ 与 `.nt` 同节点**时两条 `transition` 简写互相顶掉（已知且正是想要的：这层只该有角度在动，
  位移归外层、描边色归内层）；**⑤ `rotate` 不改 `getBBox()`**（实测三档同盒 [406,280,188,12]），
  命中却跟着变换走（playing 态下 `elementFromPoint` 打在倾侧后的左托盘上仍命中 `c-pan-l`，
  该层 `pointer-events:auto`）——视觉与热区一致、与几何判定不一致，这是 0.15.0"看不见的东西
  不能当热区"的反面版本：**要判定的东西别挂 `.tilt`，要动的东西别拿它当坐标**。弹簧的行程
  实测（+6.5° → −6.5°）：134ms 还剩 +0.17°、138ms 上下过零、385ms（70%）越到 −8.45°（超行程
  1.95°，约为 13° 全程的 15%）、551ms 收在 −6.5°；屏幕上左托盘 439.7 → 460.7，过冲那一格 463.8
  ——再多沉 3.1px，读作"盘沉下去了一下"，不是"抖"。6.5° 这一档是按几何选的：支点距托盘 88
  单位，`88·sin6.5° ≈ 10` 单位、两枚托盘屏幕 y 相差 21px，"哪边沉"一眼读得出来；再大一档
  （10° → 15.3 单位）左托盘就压到 y=306 那根刻度轨上。消费者：范本场景 C 那三句「比较函数的
  契约」（`--ease-spring` 此前只交给气泡与反馈落定，这是第一次把它交给一个**读数**）。
- **触点涟漪（`.opt.rip`）**：前沿做法是 Material 系的 touch ripple——按下那一点立刻给一圈
  确认，不用等两百毫秒后的反馈文字。`::after` 一枚圆从**触点**涨满整颗按钮再淡掉，`--dur-rip`
  （500ms）配 `--ease-out`，墨色 `--rip-ink` 取主色浅档（纯白雾会把按钮上的字压过去）。五条边界
  里最值得抄走三条：**① 静止态与终态都看不见**（base `scale:0;opacity:0`、不写 forwards，
  `finish()` 之后动画已经从 `getAnimations()` 下场）——涟漪是**事件不是状态**，与掠光 / 流光
  同族判断；**③ 圆心与直径都由 JS 现量**（触点到四角的最大距离 ×2；实测同一颗 84.2×30.9 的选项
  按在 (21.1,21.6) → 133.6px、按在 (12.6,7.7) → 150.4px，最远角从右下换到左上），而且必须**在
  handler 里读 rect**：按住这段时间 `:active{scale:.94}` 把 rect 缩过（实测 84.2 → 79.9），提前
  量好再传进来就连触点一起算错；**⑤ 只挂在 pointerdown**——键盘那条路没有触点，硬编一个圆心
  只会是假的（实测程序化 `click()` 判定照走、反馈照出、涟漪不挂）。行程实测：0ms `.85/0` →
  40ms `.598/.331` → 310ms（62% 那档）`.340/.987` → 470ms `.0002/1` → 500ms 落回 base `0/0`。
  采法留了一条教训：headless 里按下之后动画的 start 要等 ~166ms 才落（前八趟追帧读到的都是
  anim 0），**追帧采不到行程，只有钉档采得到**。
- **字距归位（`.gather`）**：kinetic typography 的收束一拍——一句副题从**散着的字距**
  （`--track-open` = `.3em`）收成正常排布，读作"这句成型了"。范本挂在章节副题 `#ch-tagline`
  上、只在**换节**那一拍重放（摘类 → 读一次盒子 → 挂类，与 0.20.0 `.flip` 的 retrigger 同判据；
  同节换句不重放）。四条边界：**① 走 animation 不走 transition**——"散→收"不是两个状态之间的
  行程，换文本那一拍没有可读的上一档字距，它是一次入场；**② 关键帧两头显式同型**（`from:.3em`
  / `to:0`，都是 `<length>`）：这里一度按 0.15.0 的 discrete 教训只写 `from`，实测 Chrome 把
  `normal` 当 0 来插（基础值留 `normal` 与写 `0` 两组逐帧同值，3.9 → 3.23 → 2.62 → … →
  2.95e-7px 一路连续），**但这条宽容不写进设计**——赌的是别家引擎不认的行为，而把 `to` 写出来
  之后，作者的排版规则也不必替动效让路（`.chapter .tagline` 里那条 `letter-spacing:0` 就是这么
  撤掉的）；**③ 它改的是排宽**，会带动换行，档位按"最坏那句"选：桌面 13px 下 `.3em` = 3.9px，
  范本八句 tagline 在这一档 Range 行度**全为 1**，最长那句散开档 293.5 → 382.2px、容器 886px；
  **④ 窄屏关掉是按余量关的**，不是"实测会断"：500px 档字号升到 14px、容器掉到 449px，最长那句
  散开档实测 315 → 411.6px，仍是一行但只剩 37px 余量——文案比范本长一点就断行，而断行落在哪
  一秒跟着帧变，那是抖不是收拢。

`prefers-reduced-motion` 兜底同步：`.tilt{transition:none}`、`.gather{animation:none}`、
`#gate-block .opt.rip::after{animation:none}` 三行进清单。前两条与 0.20.0 同口径**不需要抬特异度**；
第三条**必须带 `#gate-block`**——基础规则排在本块之后，朴素同形的 `.opt.rip::after` 会被它顶掉
（0.15.0 折叠、0.17.0 掠光那一课）。清单里也不许出现 `rotate:` 或 `--tilt-deg`：关的是补间不是
档位，把符号读数一起关掉就等于把内容锁进一个可能不跑的门（纪律 3）。实测模拟 reduce 与导出式
一刀两种口径下：倾侧立即落 ±6.5° / 0° 三档、`getAnimations()` 恒空；`.gather` 的 `animationName`
落 `none`、计算值回到 `normal`、副题排宽与不动画时逐值相同（117px，字一个字不少）；涟漪 `::after`
的 `opacity` 与 `scale` 都是 0。窄屏（≤560px 档）另关 `.gather` 一条，`.tilt` 照旧——倾角是符号
读数，与屏宽无关。新增 `--dur-tilt` / `--tilt-deg` / `--dur-rip` / `--rip-ink` / `--dur-gather` /
`--track-open` 六个令牌。

**别这么干（0.21.0 复按四条）**：① **`conic-gradient` 扫环 + `counter()` 的里程表数字**——第三次
按回去：不支持 `@property` 的引擎把那一段渲染成**空字符串**（纪律 3 直接不合格），而且这里所有
读数都是 `audio.currentTime` 的逐拍值，用计数器就是偷偷开第二个时钟；② **View Transitions**——
跨元素快照在 WebKit 上不吃 `clip-path` / WAAPI，而逐帧冷启动导出里每一帧都是首帧（结构性排除）；
③ **SMIL `<animate>` / `animateMotion`**——与 CSS 两套时钟不能同页（纪律 1 的唯一时钟边界）；
④ **给键盘那条路补一条"中心涨一圈"的涟漪**——那不是无障碍收益，是把没有的信息编出来；键盘的
确认由反馈文字与 `aria-live` 承担，`ripple()` 里的中心兜底只防"事件对象根本没有坐标"。

**落点与过场（0.22.0）**：0.21.0 补的是"判定落下来"与"句子成型"，这一轮补的是**注意力
的位置**与**被搬动过的时间**。前两轮的词汇一个说"这里对了"、一个说"这句成了"，但课堂上
还有两件事一直没有词：一幕里五六个图元同时在场、旁白逐句只点其中一个（该看哪儿，而不是
谁对谁错），和学习者点了一下进度条 / 章节刻度之后"播放头跳了"这件事本身。三条原语同样
只在范本自己那份 `[10,9,1].sort()` 示范课里找消费者，全部数字来自 Chrome 152（CDP 逐帧
采样 + 截图逐像素剖面）；两条设计被自己的测量推翻，收进本节末。

- **落点灯（`#spot`）**：一盏跟着旁白走的聚光——`#cam` 最后一个孩子，一层
  `mask-image:radial-gradient(circle var(--spot-r) at calc(var(--spot-x) + var(--spot-bleed))
  calc(var(--spot-y) + var(--spot-bleed)), transparent 0 var(--spot-r),
  #000 calc(var(--spot-r) + var(--spot-soft)))` 的暗幕，
  三个洞参数注册成 `@property{syntax:'<length>';inherits:false}` 才能被 transition 逐帧
  插值（0.13.0 `--dimmer`、0.17.0 `--feather`、0.19.0 `--lit` 同一条口径）。七条边界：

**别这么干（0.22.0 实测否决）**：① **`backdrop-filter` 用在 SVG 元素上**——"灯罩"最省事的

**本轮两处"看着跑通了、读数其实是错的"**（都不在验收清单上，是量出来的）：
**其一，注释不成对**。`:root` 里那条令牌长注释续写时漏开了头的 `/*`——只有收尾的 `*/`，
于是那十几行中文变成**裸声明**，紧跟其后的 `--dur-spot:.5s;` 被当成它的值一起吞掉，
`transition:--spot-x var(--dur-spot) var(--ease-out)` 整条 invalid at computed-value time，
`transitionProperty` 悄悄回落到 `all 0s ease`：灯还在、洞也开，就是**不走位**。CSSOM 里
规则数一条不少（改前改后都是 264），只少在 `:root` 的解析结果里，而"灯不动"第一眼看去
像浏览器没在补间。**所以从现在起：改完 `<style>` 先扫注释配对（回归用例里那台状态机，
报"第 N 行 `*/` 没有对应的 `/*`"与未闭合的注释），再断言令牌在解析后的 `:root` 里**——
源文件里有那行字不算数。**其二，灯罩盖不住取景框**（边界 ⑦）：暗幕按 viewBox 铺，镜头

- **挤压落位（`.settle`）**：一个东西落到该在的那一格时先被压扁、再回弹收住，读作"它有质量"。

  calc(2 - var(--squash-y))`，也就是绕 1 镜像——压扁 `1.14×.84` 与拉长 `.86×1.16` 是同一个
  旋钮的两面，作者只改一档、行程形状不变。**② 体积近似守恒**（原则表要的是"压扁时体积不变"，
  这里只能取二维面积）：同一枚徽标（`a-rule`）冻结九个档位量屏幕矩形面积——静止
  77.41×30.97 = **2396.9**、压扁那一格（t=160ms）88.213×26.03 = **2296.1（−4.2%）**、
  `0%` 拉长那一格 66.576×35.92 = **2391.4（−0.2%）**、70% 回弹那一格 75.092×32.204 =
  **2418.3（+0.9%）**。镜像写法让拉长那格天然比压扁那格更接近守恒，观感上要的正是"砸下去
  那一下亏一点、弹起来那一下赚一点"；比强行开方取 `1/x`（压扁格正好 100.0%）少一分橡皮感。

  **④ 走独立 `scale`、不碰 `transform`**：徽标的位移由 `transform` 呈现属性承载（`.nt` 补间它），

  只声明 `animation`，所以**不抢 `.nt` 的 transition 简写**（实测挂上之后十七项清单逐字符不变），
  但同节点不能再有第二条 `animation`——淡入 `.in` 留给内层 rect/字（0.20.0 `.bloom` 同一判据）。
  曲线只能是 **linear**：形状已经写进四个档位里了。同一节点冻在 t=105ms（行程的四分之一）
  对比读数的确凿：linear 读到 `1.04421×.949474`（还在半路）、160ms 才到 `1.13949×.840595`

  "砸下去—弹起来"演成"一开头就砸完"。`backwards` 不写 `forwards`：静止态 = 元素自己的
  `scale:none`（实测自然演完之后 `getAnimations()` 为空、scale 读回 `none`）。
  消费者是 `badge()` 中间那层包装 `key+'-sq'`，所以**第一次落位才演**：同一 key 复用节点时
  class 不变 → 不重放，后来换位置/换文案是补间与重排（舞台 A 的 s2 判词、s3 转字符串，
  舞台 G 的"巧合"）。

- **预备后蓄（`.wind`）**：起跳之前先往下沉一点——原则表那句"物体在向前运动之前会发生细微的
  向后移动"。范本要的正是它：主角那排数字被收上架子（`shelf` 姿势：世界 y 232→84、自己还从
  `k=1` 缩到 `k=.46`）时直接走，观众读作"被系统搬走了"；先沉 `--wind-back:9` 单位再起来才读作
  "它自己跳上去的"。五条边界。**① 行程挂在独立 `translate` 上、层在主角之外**
  （`w-<v>-ant` → `w-<v>`）：合成顺序 translate → rotate → scale → transform，`translate` 走的
  是**父层（世界）坐标系**——在 shelf 那一格量三种写法的屏幕位移：独立属性写 `translate:0 9px`
  动 **13.997 设备px**、同一串走 `transform` 列表且排在 `scale(.46)` **之后**只剩 **6.439**
  （正好被自己的 k 缩掉）、排在**之前**又是 13.997。既然父层坐标系这一点是白送的，这一层买到的
  就不是"躲开缩放"，而是**不占主角的 `animation` 位子**（主角那层的简写已被 `.in` 占着，
  同节点再来一条就把入场淡入顶掉）。**② 幅度与方向都是令牌**：`--wind-back` 给量、
  `--wind-dx/--wind-dy` 给轴向（默认只有竖直那一档，横向预备把 `--wind-dx` 写在节点上即可，
  符号就是方向）；renderer 只写"这一步蓄不蓄"。**③ 曲线 --ease-in-out**（`cubic-bezier(.65,0,.35,1)`）：
  一去一回是对称行程，用 --ease-out 会把"沉下去"演成急刹车、"回来"演成滑行。**④ 主动作得为它
  让出那一拍**——这条是量出来的，不是美学判断：位移走 `--dur-move .5s` 的 --ease-out，前 95ms
  已经走完大半行程。同一步走三遍、每遍逐 rAF 采主角屏幕 y（起点 348.17）：只蓄不让（第一版
  方案）**最高点仍是 348.17、dip = 0.00 设备px**——蓄力层自己确实算出 8.995 的位移，可屏幕上
  完全不回头，观众看不见；让 95.2ms 不蓄（对照组）沉到 **416.75（dip 68.58）**（镜头这一拍正在
  推近，被让出来的那 95.2ms 里旧位置在画面上一路下沉）；让 95.2ms 且蓄（**范本现状**）**429.17、
  dip 81.00**——蓄力在屏幕上多推下来的那 12.4px 才是"它要跳"。所以
  `--wind-hold:calc(var(--dur-wind) * .34)` = **.0952s**，取的是**关键帧蓄满那一格**（屏幕上的
  最低点落在它之后的 110~126ms，那一拍还叠着镜头推近，两个读数不是一回事）：预备是主动作的
  **前缀**，不是同时叠上去的第二笔。**⑤ 那一拍走 `transition-delay` 长档**，写在**被补间的那一
  层**上（`.wind > g`）：简写会把 `.nt` 那份十七项清单整条顶掉（0.19.0 老账），长档只改延迟——
  实测挂上让拍之后 `transitionProperty` / `transitionDuration` / `transitionTimingFunction` 与
  不蓄力的那一步**逐字符相同**（十七项、transform .5s / opacity .4s / …），只有 `transitionDelay`
  从十七个 `0s` 变成一格 `0.0952s`。代价说清楚：这一层的**所有**补间一起晚 95.2ms 起步，主角
  那层只有 transform / opacity 有意义，屏幕上看不出来。用 `.wind > g` 而不是给主角再加一个
  class，是为了"档位与延迟同一个来源"：蓄力层在场 = 它的主角让拍，不存在两处状态各写一遍的
  对不齐风险（这一层从建档那一步就在，因为**重新入树的节点没有 before-change style**——那一次
  148 单位的位移会当场落成终态，"跳上去"变"瞬移"，本轮实测过）。两端与静止态都是
  `translate:0 0`：**事件不是状态**。

- **提牌投影（`.lift` + `--elev`）**：把一块牌**提到台面上方**靠的不是位移而是**影子**——影子
  从没有长出来、跟着越拖越长，观众才读得出"它离开台面了"。这一条说的是"谁是被拿起来比的那一对"，
  与颜色（对错）、灯（注意力）、弱化（参照）都是不同的轴（位移轴已被 0.21.0 `.tilt` 的倾侧占用为
  −/0/+ 的符号读数，抬升是空着的那一条）。五条边界。**① 投影走 `filter:drop-shadow()`**：SVG 的
  `<g>` / `<rect>` 没有盒——同一份 `0 14px 20px` 打在 `c-a-r` 与 `c-a-lf` 上，计算值读得到
  （`rgb(255, 0, 0) 0px 14px 20px 0px`），屏幕对拍 28836 个采样点**变了 0 个**；同一份写在一个
  HTML 盒上，2408 个采样点里 **2005 个变了**。drop-shadow 走**内容的 alpha 形状**，卡片与字的
  影子分开、不糊成一个方框。**② `--elev` 注册成 `<length>`、initial 取 `0px` = 还在台面上**：
  不播 / 不能播 / 导出切掉 transition 三种情形都落在"没有投影、没有抬升"那一格（与 `--feather`
  取 134%、`--lit` 取 118% 同一条口径，只是这一族的终值恰好是零档）。**③ 抬升量与影子都由
  同一个 `--elev` 派生**（`translate:0 calc(var(--elev) * -1)` 与 drop-shadow 的两个 calc），
  所以不会出现"东西抬起来了、影子还在原地"那条假 3D。系数 1.5 / 1.2 说的是**影子比抬升走得远**
  ——真实光源在台面上方时，物体抬起，影子同时变长变淡。逐帧读数：清单里只留 `--elev` 那一档，
  t=122ms 时 `--elev`=3.09456px / 影子偏移=4.64184px / 模糊=3.71347px，33 帧里偏移与 1.5× 的
  最大偏差 **0.00001px**、模糊与 1.2× 为 **0**——派生关系逐帧成立，所以**影子不需要自己再补间
  一次**（把 `filter` 也列进清单是第二套补间，量出来一样对，但多一套就多一处会不同步的地方）。
  影子的墨量真的落在台面上：把这一层钉成 `translate:0 0`（只投影不抬）之后与"完全没抬"那格对拍，
  卡片下沿那条 106×19 的台面带里**变暗 1430 点、变亮 0 点**，同状态重拍两次的噪声地板是 **0 点**。
  **④ 档位写在呈现属性 `data-lift="1"` 上**：它承担"这一对被拿起来比"的状态读数，所以
  reduced-motion 关的是**补间不是档位**（实测该档下 `transition-property:none` 而 `--elev:5px`、
  `translate:0px -5px`、影子 `0px 7.5px 6px` 全读得到）。范本六步的档位表就是那三条契约的形状：
  s0 都不抬 / s1 抬 a / s2 两枚同高（"`a − b = 0`"在这台仪器上的形状就是同高）/ s3 抬 b /
  s4-s5 回台面。**⑤ 只挂纯包装 `<g>`**：`.lift` 自己声明 `transition` 简写，与 `.nt` 同节点会
  互相顶掉；位置归外层 `c-a`/`c-b`、描边归内层 rect。`pointer-events` 不禁：drop-shadow 与 mask
  一样**不裁命中测试**——抬起那一格牌心 `elementFromPoint` 仍落回字节点 `c-a-t`，下沿外 8px 落回
  台面 `rect`。

**随动层（0.24.0 三条一组）**：前三轮的量都落在"事件来了演一拍"上，这一轮换轴——三条
原语共同点是**没有"演完"那一说**：镜头跟着这一步真的走了多少、光跟着指针落在哪儿、色温
跟着这一段在课程的哪一档。三条共用的口径是：驱动量要么注册（能被逐帧补间），要么挂在
呈现属性上（能被测试与导出读到），没有一条靠 JS 排时长。

- **位移定拍（`camRun()` → `--cam-pan` / `--cam-zoom` → `--cam-dur`）**：镜头时长不再是一档
  常数，而是**这一趟真的走了多少**推出来的——平移行程（viewBox 单位）与倍率变化两个读数
  乘各自权重、进 `clamp()`，两端兜住。五条边界。**① 时长是派生值**：
  `--cam-dur:clamp(var(--dur-cam-min), calc(var(--cam-pan)*var(--dur-cam-pan) +
  var(--cam-zoom)*var(--dur-cam-zoom)), var(--dur-cam-max))`，JS 只写那两个读数——时间与
  几何各只有一处，权重、地板、封顶只在 `:root` 一处（断言里也不许出现第二个 `.0014`，
  测试按页面自己的令牌现算）。**② 两端各有出处**：地板 `.5s` == `--dur-spot`（灯永远不落
  在镜头后面）、封顶 `.78s` < `--dur-ride .8s`（画面里最长的一趟），实测 `--cam-dur` 的
  computed 值就是**替换之后**的那串 `clamp(.5s, calc(0.0 * .0014s + 0.000 * .35s), .78s)`
  ——未注册属性不做插值、只做常量替换，这既是它"不被补间"的理由也是它能进 `calc()` 的理由。
  **③ `--cam-pan` / `--cam-zoom` 故意不注册**：注册了就去补间一个"行程"，得到时长自己也在
  爬的第二套动画（第二轮 `--spot-*` 那一课同一处）。**④ 读数写在 `transform` 之前**：反过来
  就在两次写之间夹一次强制布局，补间会拿到**上一趟**的时长（探针里那种写法实测跑 500ms
  而计算值已经是 560ms——看着跑通了、读数其实是错的）。**⑤ #cam 与 #depth 共读同一个派生
  值**：逐趟两条 computed 时长逐字符相同（视差不另算一套）。实测走法（每趟等落定再跳下一趟）：
  冷启动没有"上一状态" → `0.0 / 0.000` → 落地板；opening s0 → seg-2 s1 是 `378.6 / 0.690`
  → **771.54ms**，`getAnimations()` 里正在跑那条的建档时长逐位等于它；seg-2 s1 → s2
  `79.2 / 0.065` 折出 `.133s` 被地板接住 → 500ms（旧写法这两趟恒 600ms，**短的那趟从此快
  100ms**，是口径变化不是回归）；s4 → s5 `450.2 / 0.200` → **700.28ms**、closing s0 →
  seg-1 s1 `243.5 / 0.477` → **507.85ms**——地板与封顶之间真的在插值，一趟走下来出现四个
  不同时长。擦洗与导出截图模式一律写 `0/0`（那两处的"行程"不是用户能感知的连续运镜），
  同一句重复跳时 `camRun` 根本不跑（画面没重画，`getAnimations()` 里没有 transform 那条）。

- **触点辉光（`.hot` + 注册属性 `--hot-x` / `--hot-y` + 呈现属性 `data-hot`）**：指针落在
  哪一块、落在这一块哪儿，光就在哪儿亮起来，并且**跟着指针走**。与 0.22.0 的 `#spot` 是两套
  轴、可以同场：那条是"观众该看画面哪儿"（导演的手），这条是"你的手在这儿"（手的回话，
  只长在这一块自己盒里）。六条边界的关键三条：**① 光心走注册属性不走 `left/top`**——改
  `left/top` 是每来一个 `pointermove` 重排一次（门禁卡里全是流内条目），改注册属性只重绘；
  实测六次连续小位移 `LayoutCount` **+0**、`RecalcStyleCount` +28、`PaintCount` +0。
  **② 位置用 px（盒内坐标）、初值兜在 `50%`**：`<length-percentage>` 两种都收，所以
  `50% → 21.1px` 那一趟的中间值是 `calc(37.5% + 5.275px)` 这种**混合长度**（注册才补得出，
  没注册就整档跳），而 px → px 那一趟走 `linear` 所以半程正好在两点正中（实测
  21.1 → 44.35 → 67.6px）；`transition` 清单里 `opacity` 配 `--ease-out`、两个位置配
  `linear`——指针停了光就停，ease-out 会在每次小停后拖一段尾巴。**③ 状态写在 `data-hot`
  上、不由 `:hover` 驱动**：`hover:hover` / `pointer:fine` / `any-hover:hover` 在 headless
  里实测**三个全 false**（触屏同样 false），而 `:hover` 原语在这套 QA 里永远读成"没跑通"；
  `data-hot` 与两个坐标一起构成"指针在场与否 + 在场哪儿"的读数，测试摸得到、导出也摸得到。
  实测逐格：静止态 `::before` 在场但 `opacity:0`、光心 `50%`、`data-hot` 根本不存在（没有
  指针就不编一个中心）；落上来淡入 `0 → .961383 → 1`（160ms，借 `--dur-hover` 那一档的读数）；
  落定后光心与盒内触点坐标相同（±1px）、`elementFromPoint` 仍落回那颗按钮（`pointer-events:
  none`）；手走了淡出 `1 → .0386175 → 0` 而**读数留在最后一格**（35.5px / 13px，不重置——
  这一层已经看不见，重置只会多演一趟没人在看的补间）；放行之后光按灭在**两类宿主**上各验
  一次（选项药丸走 `:not(:disabled)`，筐条目不 disabled、只有 `[data-locked]` 那条按得住，
  实测 `data-hot` 还在线上而 `opacity` 已经落 0）；键盘那条路（focus + `click()`）**不点亮**，
  判定照走——没有坐标就绝不硬编一个假光心。

- **色温定调（`data-mood` + 注册成 `<color>` 的 `--tint`）**：整段气氛跟着"这一段在课程的
  哪一档"走，不给内容加颜色（对错有 `--ok`/`--bad`、重心有灯）。一处补间、两处消费：JS 只在
  `documentElement` 换档，`#depth .wash` 的 `fill` 与 `body::before` 那圈页面光晕各自继承
  同一个值。四条边界的关键两条：**① 注册的 `<color>` 把补间中的逐帧值继续传进 SVG**（`<defs>`
  / `<pattern>` 里的图元同样吃到），实测同一帧里 `#depth .wash` 的 `fill` 与根上的 `--tint`
  **逐字符相同**——所以消费者一条 `transition` 都不写，一个数只补间一次；**② 补间空间是
  sRGB 逐通道线性 × 页面 `--ease-out`**：把 `#0e1f4b → #08261f` 钉在 300 / 600 / 900ms 上
  读回 `rgb(9, 36, 41) / rgb(8, 38, 33) / rgb(8, 38, 31)`，与"按 `cubic-bezier(.22,1,.36,1)`
  求进度再逐通道插值"的预测**逐格相同**，Oklab 路径在同三格差 40+ 个通道单位（本轮实测排除）。
  三档 `--tint` 的相对亮度差 **2.9%**（.015813 / .015381 / .015368），按 §8 在 python 里
  合成后逐格算——柔光 `.28` 压到舞台三支底色上、六支墨色共 54 格，三档之间对比度**最大偏移
  1.90%**，最险那格（判词红 `#ef4d4d` 对最深底色 `#161a23`）4.841 → 4.749 / 4.772 / 4.754
  都还在 4.5 线上；中点那一格的相对亮度可以比两端低 10%，但合成后没有一格的对比度跑出两端
  所夹区间超过 0.06%——"只换色相不换亮度"靠这两条叠在一起才成立。`--dur-mood` 1.2s 是全仓库
  最长的一档（比最长的运镜还长，气氛不该比一次推拉抢眼），也正因为它长，中途换档**不跳**：
  注册属性在补间中改目标值，浏览器从当前值重新起算（擦洗来回拖过章节线时色温来回游而不是闪）。
  档表没登记的段落**继承上一档**，不回落 calm——"这一段没有气氛"不可读，归零就是白演一次
  1.2s 的变色。换档挂在**换节**分支上（挂在换句上就成了每句游一次颜色），实测同场换步
  `getAnimations()` 里没有 `--tint` 那一条、颜色不动。

**别这么干（0.24.0 实测否决）**：① **把远景点阵也当 `--tint` 的第三个消费者**——点阵
  `rgb(43,50,63)` 对自己那块底色本来就只有 1.489:1（纯纹理、不承载信息），`fill` 换成
  `--tint` 之后三档分别只剩 **1.239 / 1.247 / 1.247**，纹理比现在再糊掉 17%，等于把"远处
  有东西"这条深度线索洗平——柔光矩形盖在它**上面**是这一族的正确做法（同宽同裁、`opacity`
  只有一处 `.28`）。② **注册一个 `<percentage>` 的混合比例去补间**——两个消费者要的浓度本来
  就不同（柔光 `.28`、页面光晕满值），补间比例就得各写一份，两处持有者迟早分手；补间**已经
  合成好的颜色**、浓度留在消费者自己那一处，才是"一处写、两处读"。③ **用 `:hover` +
  `@media (hover:hover)` 写触点辉光**——实测那三个媒体查询在 headless 与触屏上都 false，
  而 `:hover` 本身在合成鼠标事件下**却**置位：判据与读数不在同一个轴上，这条组合在这套 QA
  里要么恒真要么恒假。④ **把行程读数注册成可补间属性**——`--cam-pan` 一旦被补间，时长就成了
  自己也在爬的第二套动画，`clamp()` 那一条就不是"这一趟的时长"了。

**本轮三条"看着跑通了、读数其实是错的"**：**其一，注册成 `inherits:false` 的宿主属性进不了
伪元素**——伪元素在继承树里是宿主的子节点，`--hot-x` 于是恒读 `50%`，计算出来的背景是
`radial-gradient(64px, …)`（连 `at` 都被省掉），光"跟着走"整条没跑，而页面看上去是**亮了**
的。数据写在 host、画在 child，中间那一段非得继承不可；"只让这一块看见"靠的是 `.hot::before`
那个**选择器**，不是靠继承开关（两者搞混过一次）。**其二，中途被打断的过渡，时长是浏览器
改写的**——上一趟没落定就跳下一趟时实测读到 **298.75ms**（比地板 500 还短），那是 Chrome 对
"半途换向"按剩余距离做的补偿，不是页面算出来的数；所以"跑动中的补间时长 == 计算值"这一类断言
必须**逐趟等落定**，否则测的是浏览器的补偿逻辑而不是 `clamp()`。**其三，`a.play()` 不是"留在
终态"**——把补间钉到终点之后再 `play()` 会倒回去重演一遍（淡入那条又跑一次，读数 0 被当成
"没动"），要留在终格得用 `a.finish()`；同一句重复跳时画面没重画、`camRun` 根本不跑，
"没有补间"与"补间时长为 0"是两种不同的读数，别混。

**换位弧凸（`.swap`，0.25.0 一组一件）**：list-reorder 的"换了位置"读法——排序课三张卡
重排成序那一步（seg-1 s2，[10,9,1] → [1,10,9]），'1' 要从 x=700 直穿到 x=300，直线穿行
会从另两张卡中间"隧道式"穿过，读不出"换了位置"（现代列表重排动画专门避开这条直线交叉：
overlap 那一拍必须有个"越过"可看）。这一族把直线位移（照旧走 `.nt` 的 transform）与一条
**垂直抛物线**（`offset-path`，两端都回原点）叠在两层上：抛物线只在换位那一步演，
"越过 / 让位"一目了然。五条边界：
  ① **包装层 `w-<v>-swp` 挂在蓄力层之外**（`w-<v>-swp` → `w-<v>-ant` → `w-<v>`）：
     offset-path / offset-distance 是独立呈现属性，不与内层 transform（槽位）或
     animation（.in）抢位——同节点两条 transition 简写互相顶掉（.lift 老账），分开成层
     各演各的。包装层只有 `.swap` 自己的 transition 简写（computed transition-property
     只剩 `offset-distance` 一项，实测）；
  ② **档位挂在呈现属性上**：`data-go` 翻 1 才演，弧凸路径写进 `--swap-route`（路线是数据，
     与 `.ride` 同一条口径）——`M 0 0 Q 0 -2·rise 0 0`，控制点 = 峰值 × 2（二次贝塞尔
     50% 处到峰，两端都在原点 = 换位完成 = 无偏移）；`offset-rotate` 必须写 `0deg`：
     不写默认 `auto`，卡会顺着竖直路径的切线被转成 90°；
  ③ **峰值由行程现算**（poseWorld 读三枚令牌，口径同 --par-far）：新老槽位距离 ×
     `--swap-k`、封顶 `--swap-rise`、短于 `--swap-min` 的平移不演（位移短 = 平移，不算
     换位）。[10,9,1] → [1,10,9] 这一步：'1' 行程 400 → 峰值 140（控制 -280），'10'/'9'
     行程 200 ≤ 250 → 直行——弧凸只给"真的越过整行"的那张；
  ④ **换位判据写在 worldFor、由 (scene, step) 就地推导**（纪律 1，导出每帧冷启动照演）：
     "本幕内第一个可见姿势（op>0）之后出现不同序"扫到就算数（sticky）——"排好了 → 收上
     架子"那一步不重放；开头灯灭着的 off（op=0）不立基准，看不见位置的换位（off →
     messed）不演弧凸。判据与行程**分两处**：fired 决定 data-go、prevPose 决定峰值，所以
     向后擦洗回 s2 时换位照常、只是行程按"上一步姿势"现算；
  ⑤ **reduced-motion 与导出关的是 transition、不关档位**：data-go 与 --swap-route 的终值
     都在呈现属性上，一刀切掉直接落"换位完成"那一格，一格信息不少（与 .ride / .tilt /
     #spot 同一判断）；`.swap{transition:none}` 在媒体块里、基础规则在 §③ 之前，同特异度
     源序后者胜，不需要抬。兜底清单里不许出现 --swap-k / --swap-rise / --swap-min /
     data-go（纪律③：关的是补间不是状态读数）。

**别这么干（0.25.0 实测否决）**：① **给让位卡也按比例配弧凸**——行程短于 --swap-min 的那
两张实测 200 单位，若也配 70 的弧凸，会把"一个越过、两个让位"读成"整排一起弹"，越过者与
让位者的关系糊掉；阈值把"平移"与"换位"分开，是这条读法成立的前提。② **data-go 非 sticky
的写法**（每一步都重写 0/1）——实测在"排好了 → 收上架子"那一步 1→0 会把弧凸**倒着再演一
遍**（抛物线从 100% 走到 0% = 向下多沉一记），sticky 扫到就算数才不重放；同一幕若出现第二
次可见换序（范本没有），data-go 已驻 1、弧凸不重演，直线位移照常，不撒谎。③ **把换位判据
建立在"记住上一步姿势"上**——导出每帧一次冷启动、seek 直落 s2 时 poseNow 还是 off，判据
漏演；fired 必须从 WORLD 表就地回推（与 0.12.0 世界层沿用同一个理由）。④ **峰值两处共写**
（JS 写 --swap-route、CSS 再写一遍 --swap-rise）——令牌只在 :root 一处，JS 用
getComputedStyle 读（口径同 --par-far），数值在代码里只出现一次。

**余势、推导与在手（0.26.0 三条一组）**：0.24.0 让画面跟着连续量走，0.25.0 让换位读出
"越过"，这一轮补的是前沿动效落到网页时最常漏掉的三件事——**主体先动（从属者各晚一
格）**、**术语正在被推导出来**、**边界要有阻力**。三条各一件，全在真实 Chrome（CDP）里
量过才写进范本：

- **拖尾跟随（`.trail`，12 项动画原则里的 overlapping action / follow-through）**：
  兔子落地之后耳朵还在动；网页侧的落地版是"主体先走，从属者各晚一格"。范本消费者是
  世界层那三张卡在换位那一步（seg-1 s2，`[10,9,1]` → `[1,10,9]`）：'1' 走 400 单位
  （= 510.4 设备px）是主动作、rank 0 不挂档，'10'/'9' 各让 200 单位**行程打平**，按 HERO
  书写序分 rank 1 / 2——于是让位里最右那张等得最久，画面上一道从左往右的波。四条口径：
  ① **只写长档 `transition-delay`，绝不重述 `transition` 简写**（主角节点已经挂着 `.nt`
  那十七项清单，再写一份简写就整条顶掉——0.19.0 / 0.23.0 老账）：实测挂上之后
  `transitionProperty` / `Duration` / `TimingFunction` 三个读数与不挂时**逐字符相同**，
  只有 delay 变，而且是**一个值**（computed 从 17 个 `0s` 收成一个 `0.14s`）——要的就是
  整张卡（位移 + 淡入 + 辉光）一起晚一格，而不是只有 transform 晚、别的原地追；
  ② 先后只从 `--trail-step`（.07s）一处派生，rank 写在元素自己身上（`--trail-r`）——
  排位的**事实**属于节点、档距的**尺度**属于令牌；`--trail-r` **故意不注册**（读数不是
  要补间的行程，未注册时 `calc(.07s * 2)` 照样求出 `0.14s`，实测）；
  ③ **同一步只许一个让拍来源**：上架子那一步 0.23.0 已经借过一拍，`.wind > g` 带元素
  选择器、特异度 (0,1,1) 压过 `.trail` 的 (0,1,0)，实测那一步三张卡读到**同一个** delay，
  拖尾自动退让，不需要 JS 判姿势；
  ④ 档位是 (scene, step) 的读数、由 `poseWorld` 按行程现推（没有新写的姿势表），
  行程为 0 的卡不给档——它没动，晚一拍落定就是撒谎。把三张卡的 transform 补间一起
  `pause()` 后按 `currentTime` 钉格采样才是这条的可信读法（跑真实时钟会先被 runner
  快慢骗一次）：t=70 主动作已走 ≥40 设备px 而两张跟随**一格没动**（与 t=0 同值），
  '10' 在 140、'9' 在 210 才动，t=640 三张都落到 `cancel()` 之后的终值（`.5 + .14 =
  .64s`，短于 `--dur-ride` 的 .8s，档距不改终态）。

- **逐字解码（`decodeArm` / `decodeWrite`，kinetic typography 的 decode 读法）**：
  画面里的术语不写成"已经定好的字"，而是让它在被念到的那一句里**从噪声里一个字一个字
  定住**——旁白说到"先转成字符串"时观众看着那五个字被逐个认出来，读作"这个词正在被推导
  出来"。与 0.19.0 的跟读点亮同族（都是 currentTime 的逐拍纯函数、回拖跟得回、暂停停得
  住），但刻意不同：点亮只压暗、永远可读；解码在未定住的那些格**本身就是不可读的字**，
  对晕动/读屏用户是减分——所以 reduce 与导出截图模式一律直接落完整的词（前沿实现同一
  口径：resolved text 才是内容本体，scramble 只是它的入场）。四条口径：① **不许用随机
  数**（GSAP ScrambleText 一类内部随机取字符，官方文档自己写了逐帧渲染要 `--concurrency=1`
  才复现得一致；本仓库导出 mp4 是每帧一次冷启动 seek，随机一次就等于同一秒的两帧是不同的
  字），字面由 (目标字符, 下标, 句内进度) 现算，实测 `.71 → .72 → .71` 三次同一串；
  ② **字宽不许漂**：建档时把终态宽度钉进 `textLength` + `lengthAdjust=spacingAndGlyphs`，
  量的必须是 `getComputedTextLength()`（**推进量**）而不是 `getBBox().width`（**墨盒**）——
  实测四字词自然推进量 55.968 → 钉 56.0，十格采样推进量全是 56.0、药丸底宽全是 77.413
  一格不差，而墨盒在 `spacingAndGlyphs` 逐字重排边距下会自己抖（k=.5 那格的噪声字「较」
  墨宽溢出，读到 56.467），钉墨盒等于把整串压窄、而药丸底是按文案长度写的不会跟着窄；
  ③ 噪声池按**字符类**分（CJK 换 CJK、数字换数字、字母换字母），噪声长得像它要变成的
  东西才读作"还没定住"，而不是"换了一门语言"；④ **前 `--decode-lead`（.72）走完**，
  落定节奏 `round(k / lead × 字数)`，末字其实提前落：四字词实测 k=.60 还是"默认规后"、
  .63 起整词，五字词 .65——贴着句尾才定住等于没演。登记表按步重建（`begin()` 清空），
  "这一步有没有在解码"与画面一样是 (scene, step) 的纯函数。

- **越界橡皮筋（`.bar[data-band]` + `--band`，边界的手感）**：拖动条到端点之外，原生
  播放器要么死要么跳，rubber-band 那条路是**给画面阻力、不给数据越界**。指针越界时
  `seek` 把**未夹**的 raw 交给 `bandWrite`、只把夹过的写给 `currentTime`：实测向右越过
  12 / 24 / 48 / 96 / 200px 五格，`currentTime` **全部**钉在时间轴末尾 115.201s（数从
  `lesson-timeline` 现读），向左越过 40px 落 0s——时间轴一个字都不许多说；而气泡按
  `cap · x / (x + soft)`（`--band-cap` 24px / `--band-soft` 48px 两只旋钮，JS 读 computed
  求值、不抄字面量）折出 4.80 / 8.00 / 12.00 / 16.00 / 19.35px，单调、亚线性（顺应
  0.40 → 0.097，手指每多拖 1px 换到的位移越来越少）、逼近但不越过封顶；端头那一圈
  `.bar::after` 渐变随 `data-band="l|r"` 淡入且 `pointer-events:none`，松手删档位、
  `--band` 写回 0px 由 CSS 的 `--dur-band`(.42s) + `--ease-spring` 弹回（本机实测 459ms
  落定、中途反向过冲一次 −1.68px——测试**轮询 computed 读数**直到落定，不等这个毫秒数）。
  `--band` 注册成 `<length>`、`inherits:false`、初值 `0px`：不注册就没有回弹（对照页实测
  未注册时 13 次采样全是终值），`inherits:false` 是"谁用谁持有"，不往后代与伪元素穿。

**别这么干（0.26.0 实测否决）**：① **把拖过头的位置直接写进 `currentTime`**——听着
"跟手"，其实是让时间轴说谎：导出、字幕、`capSent` 全按它算，一步越界就等于念出一句
不存在的话。给手感的不许是给证据的（与 0.16.0 "渲染器不读墙钟"同一条族）。② **用
`getBBox().width` 钉解码的字宽**——量到的是墨盒，它随噪声字自己抖（见上面那条实测），
而且对 Latin 串会明显小于排版宽度，钉上去就是把字压扁到药丸边上。③ **拿
`tipEl.style` 验回弹**——`style` 读的是刚写进去的**目标值**，computed 的 `--band` /
`translate` 才是插值中的那一格；本轮的探针因此把两个读数一起取（`want` vs `comp`），
否则"回弹"这条断言永远测不到自己想测的东西。④ **在 `.trail` 里重述 `transition`
简写**——十七项清单会被整条顶掉，症状是补间全部消失而 delay 看起来"没生效"。
⑤ **给 reduce 兜底写成"补一个更短的时长"**——`.trail` 那行必须是 `transition-delay:0s`
（全局 `transition-duration:.01ms` 的钳制**管不到 delay**，0.18.0 在 `animation-delay`
上踩过同一个坑的 transition 孪生兄弟），橡皮筋那两行必须是 `transition:none`；写短一档
等于给晕动用户演一次更快的动效。

**批注与迎手（0.27.0 三条一组）**：0.26.0 把"什么时候出现"补齐之后，画面里还剩一种
信息只靠颜色承载——**哪一句是结论、哪一句已经被否掉**。琥珀色说"重要"却不是一个动作；
红色说"错"可错写法还完整地立着。前沿批注式排版（highlighter annotation / red-pen
strike-through）和门禁按钮的磁吸迎手（magnetic button）给的启发是同一条：**让标记成为
动词**。三条都在真实 Chrome（CDP）里量过：

- **荧光笔标记（`.mark` + `markBehind()`，结论被"划"出来）**：范本消费者是 seg-4 s4 的
  结论行「只看符号：负 / 0 / 正，数值本身不参与」。色带**从目标文本的 `getBBox()` 现量**：
  实测文本 364.88×22.79 → 带 372.87×12.09（宽 +8、高 ×.55、起点 y+45%、左缘 x−4），
  换字号 / 换句长都不用改坐标。四条口径：① **色带必须 `insertBefore` 到文字节点之前**——
  SVG 没有 z-index，绘制顺序就是文档顺序；盖在字上等于把字色与带色按 alpha 再混一次，
  整行糊成一块平色；② **只有琥珀字配亮带**：按 §8 合成口径，琥珀 #f5a623 衬 .14 琥珀带
  仍是 6.09:1（舞台顶）/ 6.64:1（`--panel`），同一支红 #ef4d4d 只剩 3.43 / 3.74，跌破
  4.5:1——红字那一路必须换划线 + 压暗；③ 斜度走**独立 `rotate`**（`--mark-tilt:-.6deg`），
  `transform` 只留给 `markIn` 的 `scaleX(0)`：写进 keyframes 的 from 端会在 to 端丢掉
  rotate，独立属性不参与补间、导出切掉 animation 后它还在；④ 终态写在元素自己身上
  （base `transform:none`），减少动效 / 导出截图两种兜底都落在**整条带**。s5 不再调用，
  `sweep()` 按 key 收掉——标记是一次性的"现在看这句"，不是永久高亮。

- **反证划线（`.strike` + `strikeThrough()`，反证被"划"掉）**：消费者是 seg-5 的错写法
  `(a, b) => a < b`：s0 完整摆出来，s1 判错那一拍红笔从左往右划掉，文字同时压到 #8d95a8
  （对红 tint 盒 5.37:1，仍是正文读数），红只留给线（4.48:1，图形 3:1 档）。三条口径：
  ① **斜率算进端点**——水平 `<line>` 的 fill-box 高为 0，`transform-box:fill-box` 上的
  rotate 没有稳定的旋转盒；按 `Math.tan(--strike-tilt)` 把 y1/y2 算成左高右低（实测文本
  bbox 162.44×21.55 → 线 172.39 宽、y 142.66→147.28，中心正好在 bbox 的 52% 处）；
  ② 与 `.mark` 相反，划线 append 在文字**之后**（压过笔画才读得出作废）；③ 归一单位与
  `.draw` 同族（`pathLength=1` + `dasharray 1 1`），但**不挂 `.draw`**：划线要的是"每一步
  都在"（s1 划掉之后到 s5 仍划着），所以自建 `strikeIn`、不继承入场的错峰参数。线宽
  `max(2, bbox高×.09)`——18px 字号得 2px，是笔尖不是删除线字符。

- **磁吸迎手（`magMove` / `magClear`，按钮在按下之前就迎手）**：指针进到门禁按钮**盒边**
  外 `--mag-r`（34px）的场里，按钮朝指针挪最多 `--mag-pull`（6px）；位移按 `sin(πd/r)`
  衰减：贴边 0、半程峰值、场缘回 0。实测 88.65×35.46 的提交键：盒边外 17px 得 6px、
  贴边 2px 得 1.1px、40px 归零。五条口径：① 只写**独立 `translate`**（`:active` 的
  `scale` 是另一个属性，两者相乘），时长 / `--ease-spring` 全在 CSS；② 事件委托在
  `#gate`（卡片每次开题重建，逐个绑会丢线），每帧只扫可见的 `.go`；③ 场半径从**盒边**
  算，量场时扣掉上一帧位移（否则按钮迎 6px、场也挪 6px，指针没动它却来回找位）；④ 只认
  鼠标 / 笔，触屏没有 hover 语义；`mqReduce` / `__coursewareShotMode` 下**一个字节都不写**
  ——不是补一个更短的时长，而是根本不启动；⑤ 键盘路径一个字节都不碰：`focusin` /
  `pointerdown` / `pointerleave` 即清位移，`translate` 不改布局盒（实测 rect 宽高不变），
  点击落点仍按原盒判定。

**别这么干（0.27.0 实测否决）**：① **给已入树的 SVG 节点每步 `appendChild`（或对已就位
节点重复 `insertBefore`）**——DOM 插入会先把节点摘下再插回，浏览器**重放 CSS 动画**：
划线在 s3 / s5 每一步都重新划一遍、荧光笔在同一句上划两次，而所有静态断言仍然全绿
（本轮就是这么踩到的）。helper 必须只在"位置不对"时才搬节点；首创建时 `put()` 已经把它
追加在同一父层，别再补一次 `appendChild`。② **把 `--mark-tilt` / `--strike-tilt` 注册成
`@property`**——它们是静态几何读数，注册后反而会被逐帧插值（口径同 `--cam-pan` /
`--trail-r`）。③ **拿 `transform:rotate()` 做荧光笔斜度**——`transform` 已被 `scaleX`
入场占用，把 rotate 塞进 keyframes 的 from 端会在 to 端丢掉它；斜度必须走独立 `rotate`。
④ **给红字配荧光带**——合成后 3.43 / 3.74:1，跌破正文 4.5 线；红字只能划线 + 压暗。
⑤ **把磁吸位移写进 `transform`**——按钮本来就有 `.nt` 的 transform 补间与 `:active` 的
`scale`，再写一份会互相顶掉；而且几何一挪，`getBoundingClientRect` 驱动的场就会自己
找位。⑥ **每帧重算磁吸场**——只在 `pointermove` 里算，不挂 rAF / 计时器：指针不动时按钮
也不该动。


通用陷阱：计算值读得到不代表画得出来（`backdrop-filter` 0.22.0 同课，但 box-shadow 更阴，因为它
连"没生效"都不肯告诉你）。② **`perspective()` + `translateZ()` 抬 SVG**——`getScreenCTM()` 的
`a`/`d` 分量纹丝不动、屏幕 0 个像素变；要 3D 得走 `.flip` 那条函数列表写全的路（0.20.0），
而"抬起一条牌"本来就不需要 3D。③ **把 `filter` 列进 `.lift` 的补间清单**——不是错，是多余：
影子由 `--elev` 派生、逐帧实测偏差 0.00001px，列进去就是第二套补间，两套补间迟早会不同步。
④ **把蓄力写进 `transform` 列表**——同一个 `translate(0,9)` 放在 `scale(.46)` 之后只剩 6.439
设备px（被自己的 k 缩掉），而 `.nt` 补间的正是 `transform`，写进去等于把位移与形状搅在一起。

**本轮三条"看着跑通了、读数其实是错的"通道**（都不是设计错误，是量法错误）：
**其一，CSS 动画的曲线不在 `effect.getComputedTiming().easing` 上**——它返回的是**关键帧自己的**
easing，CSS 动画那里恒为 `linear`，于是 --ease-in-out 的 `.wind` 读起来像"没缓动"。曲线要从
`getComputedStyle().animationTimingFunction` 读（回归用例把两个读数**都**断言一遍，就是为了
锁住这个读法）；CSS 过渡相反，`getComputedTiming().easing` 才是对的（0.22.0 同一条）。
**其二，`getComputedStyle().translate` 在零位移时塌成一格**——静止读 `"0px"`、有 y 分量才读
`"0px -5px"`，`split()[1]` 直接 IndexError，而把 `"0px"` 当"动了 0"读又会把"没动"混进样本里；
本轮的探针因此统一走一个容错解析器。**其三，reduced-motion 的让拍归零那行是承重的**——把
`.wind > g{transition-delay:var(--wind-hold)}` 原样重述到媒体块**之后**，`transition-property`
仍然是 `none`（`.nt` 那行在管），只有 `transition-delay` 读回 `0.0952s`：清单空了的时候延迟
确实不动任何东西，看起来"删掉也无妨"，但兜底不该在页面上留一个"等着补间"的读数（导出与调试
读的都是页面上的读数）。

**动效可及性兜底（WCAG 2.3.3）**：模板自带
`@media (prefers-reduced-motion: reduce)`——入场/补间/呼吸全部关闭、
循环动画停掉、终态保留。内容不依赖动效：关闭后每一帧仍是同一张正确定格，
与导出截图页（`transition/animation:none`）同口径。

导出边界（`export_video.py` 注入 `transition/animation:none`、每帧冷启动）：

- 终态必须落在**属性**上，`animation-fill-mode` 用 `backwards` 或不写；
- 循环动画的 `0%` 必须等于静止态，否则截到的那一帧停在半亮；
- **每一步单独看都要讲得清**——动效是直播播放的加护，不是信息的载体。

### 3.5 阈值

```js
if (step >= 3) showToken();
if (step === 4) flashOnce();
```

阈值直接写成常量，不用由句数推导出的魔法表达式。


## 4. 字幕区

模板提供：

```html
<text id="cap-text" data-courseware-caption="1"></text>
<text id="cap-speaker"></text>   <!-- 可选：对话课的说话人标签 -->
<rect id="cap-prog" .../>        <!-- 可选：句内进度细线（0.16.0，派生视图） -->
```

每次 `sentAt(t)` 返回当前句时，把该句对象交给 `capShow()`。页面不维护第二份字幕表。

说话人标签（`#cap-speaker`）是同一句数据的**派生视图**：`capShow()` 把
`s.speaker`（对话讲稿经 `build_timeline.py` 透传的说话人 label，见 `script.md` §1）
写进标签，句子没有 `speaker` 时留空。它**不碰 `#cap-text`**——QA 比对的是字幕
节点本身，标签不改变"字幕唯一来源"的契约；标签文案也只是称呼（人名 / 角色），
不得复制旁白正文。

两条 QA 会机械校验的约定：

- **空档保留上一句**：换场空档（`sentAt(t)` 返回的 scene 为 `null`）与**场景内两句
  之间的空档**（scene 命中但 `index < 0`）字幕带都**不清空**，停在上一句上（一进
  空档就 `RENDER(-1)` + 收字幕，每换一节闪一下空白）。只有开场前（还没有上一句）
  与课程结束才收起。`check_gates.py` 会在换场空档与场景内句间空档两处各放探针探测
  这一点。
- **字幕必须真的可见**：文字对但被 CSS 压在 `opacity:0` / `visibility:hidden` /
  `hidden` 之下同样算失败——QA 沿字幕节点的祖先链查计算样式，不只是读 `textContent`。
  同一条契约也管**结束态回拖**：`ended` 收起整条带子后，把进度条拖回**最后那句之内**
  时句号没有变化、换句分支不进，带子必须靠"这一拍有活跃句子"补回来（范本 0.16.0 起
  在 `tick()` 里按 `capSent !== hit.sentence` 补一次 `capShow`）——画面与读数都回来了
  而字幕还空着，就是状态不再是 `currentTime` 的纯函数。

字幕带的**派生视图**（`#cap-hl` 结论色带、`#cap-prog` 句内进度细线、`#cap-speaker`
说话人标签）都不算第二份文案：它们几何从 `#cap-text` 现量、内容由当句数据算出，
QA 的比对节点始终是 `#cap-text`。

跟读点亮（`--lit`，0.19.0）同样是派生视图，而且是这三者里唯一**只碰呈现**的一层：
它写在 `#cap-text` 的 `mask-image` 停靠点上，`textContent`、`getBBox()`、
`getClientRects()` 全部逐值不变。这里有一条**量出来的纠正**：clip-path 与 mask 对
rect / bbox 的影响其实相同（都不会让 `getClientRects().length` 变 0，实测两档都是 1），
差别只在**命中测试**——`clip-path` 会裁掉命中、mask 不裁。所以 `captionShown()`
那套"祖先链样式 + client rects"的判据对这一层完全安全；反过来，需要 Learner 点的
图元不能收在 clip-path 后面（见 §3.4 收拢退场边界 ④）。

## 5. 连线要真的连上（几何）

连线（实线 / 虚线 / 带箭头的都算）**两端必须落在它连接的两个图形的边界上**：不悬空留缝，
也不插进图形内部。症状是"中间那条线看着没接上，两头都空着"。

- 端点坐标**从图形算出来，不靠手感给**：矩形用 `x` / `x + width`，椭圆用 `cx ± rx`；
  算完让两端各留 **2 单位呼吸缝**。
- **带 `marker-end` 时终点再缩一个箭头长度**，否则箭头会压进目标图形、或与它的边线叠在一起。
  缩多少由你自己的 marker 决定：`refX` ÷ `markerUnits` 的换算结果，量级通常在 **8–10 单位**。
- **改了图形的坐标 / 尺寸后，回来把它所有的连线一起改**——连线是图形的派生数据。
- 导轨（时间轴主线、分支轨道）本来就自由延伸，不受这条约束；受约束的是**连接件**
  （把 A 指向 B 的那根线）。

## 6. 内容底线

字幕带有固定区域。主要图形留在分隔线以上，不与字幕重叠。

真实尺寸由你的 `viewBox` 与内容并集决定，不把模板某个数字当成通用魔法数字。

**每一步的画面重心都要落在画布横向中线上**（viewBox 宽的一半）。桌面全屏 / 宽视口
会把画布撑到最宽，偏心在这个尺寸下最扎眼；紧凑态（窄屏、横屏手机）反而看不出来
（`camSet()` 在窄屏按内容包围盒自动取景），所以只在桌面截图很容易漏。两种常见病因：

- 成排图元的行中心 ≠ 画布中心（范本曾把三张卡放在 220/420/620，整行左偏 80）；
- 分步生长的流程图（右侧分支后段才出现）：不长的步态留右侧大空带。范本舞台 D 的解法
  是按步态给整条管线 `translate` 配平，长出的那一步再归位。

用相机配平是更省事的一条路：窗的中心会被钉到可用区中心，所以**把窗写正，重心就正**
（§3.3）。改完构图仍要逐场景量一次 `getBBox()` 中心（或全屏截图目测），别只看桌面
默认尺寸——导出是每帧一次冷启动，**每一步都得单独站得住**。

## 7. emoji 装饰：默认装饰层

**默认给画面图元和侧栏配 emoji 锚点**，不等用户开口要。装饰仍服从纪律 4：图形优先，emoji 只是记号的点睛，不取代结构。

- 每个概念记号**至多一个** emoji，贴着图元文字写：`📤 push`、`🧩 action`、`🖥️ runner`、`⏳ 等待`、`🚀 发布`、`🔔 事件`；
- 选**语义贴合**的，不选热闹的：比喻要能帮记忆（耳朵 = 监听、拼图块 = 复用、轮胎 = 造轮子）；
- 静态呈现：emoji 不驱动状态、不参与步进，renderer 里不许为它造计时；
- 三条禁区：**旁白 `text` / 字幕不放**（TTS 会念出来，且破坏字幕唯一来源）；**门禁题面与反馈不放**（证据通道保持纯文字）；**QA 钩子节点不放**（`#cap-text` 等比对基准必须原样）。

## 8. 画面来源：先定呈现，再定来源

内联矢量绘制仍是默认形态。本节只回答一件事：**这一段观众该看到什么、素材从哪里来。**

| 内容特征 | 首选呈现 |
|---|---|
| 顺序 / 流程 / 关系 / 对比 / 状态（绝大多数讲解步） | 内联 SVG（纪律 4 的形式表） |
| 数值比较 / 占比 / 趋势 | 数据图表，以内联 SVG 绘制 |
| 真实人物、产品、地点、事件现场 | 真实照片（用环境任一可用的联网检索能力，本 skill 不内置） |
| 外观 / 场景 / 氛围意象 | 图片生成能力（生图，本 skill 不内置） |

两条边界判据：**抽象且不承载严谨数据 → 意象图；抽象但逻辑严谨 → 内联示意 / 图表**。有明确真实实体的内容不要用生成图替代事实照片。

表中的「联网检索」「生图」都是**能力泛称**，不特指某个工具：模型自带能力、平台提供的工具、或已安装的生图 / 检索类 skill，用当前环境里任一可调用的执行；一个都没有时直接退回内联 SVG 绘制——它是 always-on 的兜底形态。

选生图时：prompt 先描述"讲什么"（主体 / 场景 + 核心动作或结构）再描述"怎么画"（风格、背景明暗），构图优先接近画布横向比例、主体居中；同一课的多张图锁同一套背景明暗与风格词，保证风格统一；**图内不放文字**——可读信息由图元标注和字幕承担（纪律 3 / §8 末）。

素材只承担**增量信息**：旁白和图元标注已经把话说清时，不要为填满画布配图，也不要为"高级感"堆 3D、仪表盘、拼贴这类不帮助理解的装饰。

### 选不到时的降级链

照片检索失败 → 意象生图 → 简化内联示意，逐级**降低视觉复杂度**，绝不为了补画面编造信息；
每一级都不合格时就停在最简单、一定讲得清的那一级。

### 素材纪律

- 外部素材（照片 / 生图 / 现成 SVG）落进课件目录并记录来源；真实照片要打开原图核对，不看缩略图选图；长边低于约 1200px 的图进入成片容易发虚，宁降复杂度不硬凑；
- **来源只进文件，不进画面**。出处、生成方式、工具名这类元信息写进项目目录里的记录文件（如 `assets/provenance.json`）就够了——学习者要的是这张图讲什么，不是这张图从哪来。给图配注脚只配**内容性**的（图在看哪一步、结论是什么），"AI 生成 · 来源见侧栏"这种署名式标注画布和侧栏都不放；
- 不以 AI 生图冒充现场照片；同一张泛化图不反复盖到多个不相关场景；
- 数据红线（对内联图表与素材同样适用）：不为"好看"改数字，估算值必须标明、不得画成事实，不用截断坐标轴、面积失真对比等误导比例，不省略单位，不编造数据点。

### 图内文字：定色在前，自查在后

对比度判据（WCAG）：正文与标签 ≥ 4.5:1，图内大标题 ≥ 3:1，低于线重画。图内小字还要经响应式缩放与 `export_video.py` 压缩编码，**次要文字按 ≥ 7:1 取色**。

三条最常踩的：

- **深色文字只能待在明确的浅色底板上**。改任何底板颜色，同时复核压在它上面的全部文字；`fill` 能就近写死就别靠 `<g>` 继承——底板一挪一删，继承的字立刻瞎掉；
- **主题背景色族不得当文字色**。判据是"这个色值属不属于背景族"，不是"看着有没有对比"；深浅主题串色（把 dark 主题的近白抄进浅色稿、或把浅色稿的深字放进深底）都是 1.x:1 的瞎字；
- **半透明按合成后的颜色算对比度**。`opacity` / `fill-opacity` 会真实吃掉对比度，要弱化文字就换一个更暗（或更亮）的实色，不要用透明度表达层级。

外部 SVG 素材若以 `<img>` 载入是独立文档，页面的字体变量渗不进去，其内部 `<style>` 要自带中文无衬线字体栈（如 `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif`）；且它内部的文字对 `check_gates.py` 完全不透明——这正是不作特殊要求时画面留在内联渲染的理由：DOM 里的文字对比度看得见、量得到。

## 9. 自检

- [ ] 一个句子对应一个主要视觉步；
- [ ] renderer 不计时；
- [ ] renderer 是 (scene, step) 的**纯函数**：没有"记住上一步演到哪儿"的可变状态（导出每帧冷启动）；
- [ ] 常驻图元在这一步都被写过；要淡出的先写 `opacity:0` 再收尾，没有"靠没写来消失"的中间态；
- [ ] 跨幕的主角放在世界层、姿势逐句对账，各幕没有重画它；
- [ ] `CAM` 每一窗都框住了这一步该看的东西，内容没有沉到字幕带以下（那里会被裁掉）；
- [ ] 用了视差远景层（`#depth`）的：它是 `#cam` 的**同级兄弟**、位移取 `camTo()`
      回传的 `tx/ty`（没有第二份钳位公式）、系数只在 `--par-far` 一处；
- [ ] 用了方向感换场（`.swF`/`.swB`）的：判据是**换节**不是换句、擦洗与截图模式
      不演、退场图层在 `only()` 里把 class 摘干净（否则下一次入镜重放旧动画）；
- [ ] 用了结论句划重点（`#cap-hl`）的：几何从 `#cap-text` 的 `getBBox()` 现量
      （不写第二套字号常数）、非结论句归零、色带写在 `#cap-text` 之前；
- [ ] 用了擦除揭示（`.reveal`/`.revealL`）的：关键帧**两端都写成 `inset()`**（只写
      `from` 时终态取自身 `clip-path:none`，inset↔none 不可插值，实测按 discrete 两格
      硬跳）、挂在包装 `<g>` 上而不是文字节点本身、只裁不位移（`getBBox()` 全程恒定）；
- [ ] 用了 SVG 几何补间（`.nt`）的：只碰 CSS 清单里的属性（rect 的 x/y/width/height/rx、
      circle 的 cx/cy/r、ellipse 的 rx/ry、path 的 d；`<text>` 的 x/y 与 `<line>` 的
      x1/x2 **不在清单里**，写了白写）；现量结果写进呈现属性，占位值只给新建档的节点；
- [ ] 用了折叠面板（0↔auto）的：`interpolate-size:allow-keywords` 在 `:root`、
      `display` 与 `height` 同进 `transition-property` 清单（漏了 display 收起半边硬跳）、
      `transition-behavior:allow-discrete` 单独一行、`@starting-style` 给出起点、
      reduced-motion 兜底带上 `li.note` 抬特异度（源序在后面，同特异度会被基础规则盖掉）；
- [ ] 用了句内进度细线（`#cap-prog`）的：它归字幕带管、不属于 renderer——只写呈现
      属性、不挂 transition（它是读数不是动效，**也不进 reduced-motion 清单**）、
      `tick()` 里的调用点排在换句分支**之后**、句间空档不清零；
- [ ] 用了滚动驱动入场（`animation-timeline: view()`）的：整块包在
      `@supports (animation-timeline: view())` 里、隐藏态只写在 keyframe 的 `from`
      （不支持的浏览器整块跳过，内容一格不少）、`animation-duration:auto` 显式写、
      `animation-range` 落在 **entry 段内**（取 cover 段实测静止态停在 0.845 这种
