# 舞台与逐句渲染

> 写 renderer 与动效时读。`references/template.html` 是语法范本（class、令牌、关键帧都
> 在里面），本文件说明渲染模型、原语语义与边界。所有约定都服务同一条主线：
> **页面状态是 `audio.currentTime` 的纯函数**。

## 1. Renderer 的职责

### 1.1 调用形状

renderer 接收一个句序号：

```js
renderScene(step)
```

输出这一句应该看到的 SVG / DOM 状态。主循环负责：

```text
audio.currentTime
  ↓
sentAt(t)
  ↓
如果 scene / index 变了 → begin() → RENDER[scene](index) → worldFor() → camSet()
```

### 1.2 必须是纯函数

**renderer 必须是 (scene, step) 的纯函数**：同一句在任何路径上都画出同一张图。

这不是洁癖——`export_video.py` 导 MP4 时**每帧开一个新浏览器**、直接 seek 到那一秒，
只跑这一步的 renderer。任何"记住上一步演到哪儿"的写法（模块级可变状态、按历史推导
出来的姿势）都会把第一句的画面漏进后面每一帧。

## 2. 四条纪律

### 2.1 不在 renderer 里计时

renderer 不拥有时间语义。禁止用 `setInterval` / `setTimeout` 排程后续视觉状态——句
序号是唯一驱动源，`check_gates.py` 会把它报成错误。

要"动"就声明**目标状态**，让 CSS 去补间（§3.4）。renderer 里既不排程也不轮询，
一次性 `requestAnimationFrame` 也不需要。`check_gates.py` 对 renderer 体内的
`requestAnimationFrame` 仍报警告：那是在用 JS 手搓补间，回到声明式写法即可。

### 2.2 句号决定步数

一幕有 6 句旁白，就按 6 个主要视觉步设计。不要凭感觉再造第 7 个中间状态。

### 2.3 字幕不属于 renderer

renderer 画图，时间轴写字幕。

图元上的文字只能是**短标注**：公式、代码、记号（`🔤 [10,9,1].sort() → [1,10,9]`、
`只看符号`）。检查器会把三类素材与旁白原句做**形状**比对：

- renderer 体内名为 `txt()` / `badge()` 的写字函数调用（自造 helper 起这两个名同样
  被覆盖）；
- `textContent` / `innerHTML` / `createTextNode` 直接赋值的字符串字面量；
- 页面除字幕钩子外的静态 SVG `<text>`。

判据是形不相似，不是意不相似：把标注写成短语 / 代码而不是完整句子，天然安全；把
旁白那句话原样抄进图里必踩。机制细节见 `runtime.md` §8.2。

### 2.4 图形表达优先于装饰

| 结构 | 常见形式 |
|---|---|
| 顺序 | 流程图 |
| 关系 | 关系图 / 连线 |
| 系统组成 | 分区 / 架构图 |
| 对比 | 双栏 / 对照矩阵 |
| 状态 | 状态块 / 状态图 |

装饰可以有，但不要因此再造一个时间系统。结构之外还要先选**表现方式**（真实体可以
上照片、抽象概念可以生图，见 §8），内联 SVG 仍是默认形态。

## 3. 舞台模型：常驻图元 + 世界层 + 相机

一幕一屏、每步重建节点的写法有两个天花板：节点是新的，所以东西**没有"从哪儿来"**
（只能凭空出现）；场景是孤岛，所以**上一幕的主角走不进这一幕**。模板把舞台换成三层：

```text
<g clip-path="#frameClip">   ← 取景框：字幕带以上才是画面（硬边界）
├ <g id="depth">             ← 远景视差层（纯装饰，比 #cam 慢一拍）
└ <g id="cam">               ← 唯一的相机，camSet() 每步声明一个取景窗
  ├ <g id="world">           ← 跨幕常驻的主角：POSE 给姿势，WORLD 给哪一步用哪个
  └ <g id="stX"> / <g id="x-body"> ← 这一幕的局部图层
```

### 3.1 建档、写状态与撤走

| 调用 | 作用 |
|---|---|
| `begin()` | 主循环每步一次，开一个世代号 |
| `put(parent, tag, key, attrs)` | **写目标状态**：这个 key 没见过就建档（入场），见过就地改属性 |
| `txt(parent, key, attrs, s)` | `put` 的写字形状 |
| `badge(parent, key, x, y, s, col)` | 短标注：药丸底 + 居中字 |
| `sweep(parent)` | 本步没被写过的 key 撤下台（递归整棵子树） |

规则只有一条：**这一步看到的每个图元，都要在这一步被写过一次**。写了就留下，属性
变了就补间，没写就被撤走。所以"淡出"是把 `opacity:0` 再写一步、下一步不再引用——
不是自己消失。

节点复用是这一切的前提：同一个 key 在下一步拿到的是**同一个 DOM 节点**，CSS
transition 才有"上一状态"可补间。key 同时写进 `id` 与 `data-key`，所以嵌套建档只要
父节点那一步写了 key 就够。

### 3.2 世界层：跨幕常驻

段与段之间最贵的不是新画面，是"刚才那三个数去哪了"。把主角写进世界层，它就被观众
一路认出来：收上台当参照物、被搞乱、最后回到台上回答问题。

```js
var POSE  = { bench:{y,xs,k,op,quoted,tone,order}, shelf:{…}, messed:{…} };
var WORLD = { 'seg-1': ['bay','bay','sorted','shelf'], 'seg-5': ['off','off','off','off','messed','messed'] };
```

- 姿势是**整步的快照**：位置、缩放、灯亮不亮、染色、顺序一次给全，段内不换姿势就
  不会在两句之间漂一下重心；
- `WORLD[scene]` 里没写到的那一步**沿用本幕最近一个写过的姿势**（画面上就是站着
  不动）；整幕没写 = 主角不在台上（`off`）。沿用是**在这一步就地回推**的，不是记住
  "上一幕演到哪儿"——那是 §1.2 纯函数约束的头号反例；
- 局部图层不要在世界层里重画主角。范本舞台 B 只画两行逐位比较，被排的那三个数始终
  由 `#world` 承担。
- 换位之后留一组**弧痕**（`.traces`）：`traceAt()` 从 `WORLD`/`POSE` 现推"最近一次
  看得见的换序"，把旧槽位 → 新槽位画成虚弧（arc diagram 的事后读法）。它补的是
  `.swap` / `.wake` 的盲区——那两条只活在行程里，念完停在句末就只剩结果。判据与
  几何见 §3.4.3（5）。

### 3.3 相机：取景窗就是构图声明

```js
var CAM = { 'seg-2': [ FULL, [230,61,580,120], [300,72,460,110], … ] };
```

窗是**世界坐标** `[x, y, w, h]`；没写的那一步 = `FULL`（identity，与"不做任何变换"
等价，不会莫名缩放）。`camTo()` 把窗的中心钉到画布可用区中心，倍率钳在 `0.85–1.8`：
低于下限会把内容裁掉，高于上限字会糊到画布外。

三件事一并解决：

- **运镜**：旁白说到哪一位，窗就框到哪一位。`#cam` 的补间时长由这一趟真的走了多少
  现求（`0.5s–0.78s`，见 §3.4.3 位置与状态）；
- **重心**：声明了窗就等于声明了构图中心——§6 那条"逐场景量 `getBBox()` 配平"从
  人工活变成读表活，一眼就能看出哪一步把内容丢在了画外；
- **窄屏兜底**：窄屏下没声明窗的步按 `contentBox()`（可见内容并集包围盒）居中，桌面
  不动镜头。

取景框是**硬的**：`#cam` 外面套了一层 `clip-path`。镜头推近后可见区仍然是整个
`viewBox`（比窗大），不裁的话被留在身后的内容会一路画到字幕带上、字压字。所以任何
落在字幕分隔线以下的内容都会被裁掉：排版时把它当画布下沿。

### 3.4 动效原语

class 就是节拍词汇。原语只描述**目标状态**与**一次事件的确认**，时长与曲线全部来自
`:root` 令牌。

#### 3.4.1 词汇总览

| 族 | 回答的问题 | 代表原语 |
|---|---|---|
| 入场与节拍 | 新东西怎么上台 | `.in`、`--delay` / `.st1–3`、`.stag`、`.pop`、`.pulse`、`.draw` |
| 位置与状态 | 已在台上的东西怎么变 | `.nt`、几何补间、`#cam`、`#depth`、`.swF/.swB`、`--cam-dur`、对焦 |
| 揭示与退场 | 怎么长出来 / 怎么让位 | `.reveal`、`.featherR/L`、`.tuckR/L`、`.bloom` |
| 关系、注意力与标注 | 该看哪儿、两者是什么关系 | `[data-dim]`、`#spot`、`#cap-hl`、`.mark`、`.strike`、`.scope`、`.brace`、`callout()`、`connect()`、`loupe()`、`.flow`、`.halo`、`.crisp` |
| 行进与换位 | 谁走到哪儿、谁先动、刚才怎么换的 | `.ride`、`.wake`、`.swap`、`.trail`、`.traces` |
| 过程与进度 | 这条路走到第几段、还剩多少 | `drawTo()`（已走实线 / 未走虚线 / 走头，可停在半路） |
| 判定与重量 | 结论落下来、天平读出方向 | `.settle`、`.wind`、`.lift`、`.tilt` |
| 文字 | 念到哪儿、词怎么成形 | `--lit`、逐字解码、`.gather` |
| 声画同步 | 旁白此刻在念谁 | `cue()` + `.cue`（四角括号）、`cueWrite()` / `cueGeom()` |
| 对照与差异 | 两个版本差在哪、改了什么 | `compare()` + `[data-cmp]`（对照窗、互补裁切、接缝与标签） |
| 组成与拆解 | 一个整体由哪几件组成、怎么打开 / 合拢 | `explode()` + `.explode`（按装配位与离锚点距离沿轴分开，错峰开合） |
| 形变与连续 | 同一件东西换了轮廓，还是不是它 | `morph()` + `.morph`（两端各采 48 点、搜顶点对应、逐拍走折线，终态落回作者那条 `d`） |
| 重复与逼近 | 同一件事绕到第几回、每一回落在哪儿 | `loopTo()` + `.lp` / `.lp-cur`（游标 + 落点痕 + `k/n` 读数；每圈"走一段 / 停一下"，落点梯越走越短就是收敛） |
| 并行与相位 | 这几件东西各自走到哪儿、谁跟谁同时 | `lanes()` + `.ln`（多轨时序带 + "现在"针 + `phase` 起步相位；实心段与针都是句子进度的纯函数，同时 / 先后由相位说） |
| 取数与区间 | 取的是哪几件、从哪儿切到哪儿 | `range()` + `.rg`（窗口带 + 两道切口 + 序号读数；宽度是读数、窗口会滑） |
| 数字与读数 | 计数怎么滚到新值、量怎么长出长度 | `data-count` + `countRollWrite` + `.roll`、`data-meter` + `meterWrite` + `.meter` |
| 度量与边界 | 够不够、界在哪、过了多少 | `limit()` + `.lim`（界线 + 两端头 + 界外区带 + 界值 / 超差读数；判定由每拍现量那颗量得出） |
| 交互反馈 | 手按下去收到了什么 | `.opt.rip`、`.hot`、磁吸迎手、`.mag`、`.go.shine` |
| 播放器 | 时间被搬到哪儿 | 擦洗态升级、`#ffwd`、`.bar[data-band]`、`.tip` |
| 氛围与排版 | 这一段什么温度、文字怎么排 | `data-mood`、`.pregate`、`text-wrap:balance`、`text-spacing-trim`、`--key-soft` 族、侧栏折叠 |

#### 3.4.2 节拍与令牌

**节奏是令牌，不是散落魔法数**：缓动与时长集中在模板 `:root`，按域分组：

| 域 | 令牌（例） |
|---|---|
| 缓动 | `--ease-out`、`--ease-in-out`、`--ease-spring` |
| 入场 / 退场 | `--dur-in`、`--dur-move`、`--dur-pop`、`--dur-draw`、`--dur-swp`、`--dur-tuck` |
| 相机 | `--cam-dur`、`--cam-pan`、`--cam-zoom`、`--dur-cam-min/max/pan/zoom`、`--par-far`、`--dur-blur` |
| 注意力 | `--dim-focus`、`--dur-dim`、`--dur-spot`、`--spot-k`、`--spot-soft`、`--spot-bleed` |
| 字母与读数 | `--dur-hl`、`--dur-cap`、`--lit-floor`、`--lit-ramp`、`--flow-seg`、`--dur-flow`、`--dur-roll` |
| 声画同步 | `--dur-cue`、`--cue-lead`、`--cue-pause`、`--cue-settle`、`--cue-pad`、`--cue-arm`、`--cue-ink` |
| 对照 | `--dur-cmp-min`、`--dur-cmp-full`、`--cmp-ink`、`--cmp-before/after`、`--cmp-seam`、`--cmp-wash` |
| 拆解 | `--dur-ex`、`--ex-stagger`、`--ex-cap` |
| 形变 | `--dur-morph`、`--morph-pts`、`--morph-min` |
| 圈数 | `--dur-loop`、`--loop-run`、`--loop-per-min/max`、`--loop-mark`、`--loop-ink`、`--loop-r`、`--loop-dot` |
| 时序带 | `--lane-h`、`--lane-gap`、`--lane-pad`、`--lane-min`、`--lane-fs`、`--lane-track`、`--lane-ink` |
| 区间窗 | `--dur-range`、`--range-pad`、`--range-cap`、`--range-fs`、`--range-wash`、`--range-edge`、`--range-ink` |
| 界线 | `--dur-lim`、`--lim-cap`、`--lim-fs`、`--lim-ink`、`--lim-alert`、`--lim-zone`、`--lim-hot` |
| 原语专属 | 每个原语 2–4 个（如 `--dur-settle` / `--squash-x` / `--squash-y`） |

改全局节奏只动一处。曲线是 easeOutExpo 家族（`.22,1,.36,1`）：入场与补间共用它，
退场用 inOut。**唯一例外是 `.flip`**：翻面要求"角度对时间居中"，只有对称的
`--ease-in-out` 成立（用 `--ease-out` 实测背面要倒着走 235ms）。

**派生令牌**：`--cam-dur` 不是写死的档，而是由 `--cam-pan` / `--cam-zoom`（JS 每趟
写的行程读数）与两端、权重四个常数在 `clamp()` 里现求出来的时长——令牌仍然只有一处，
数值的来源多了一个连续量。

**错峰入场**：`.in` 支持 `--delay`（`animation-delay:var(--delay,0s)`），现成档位
`.st1/.st2/.st3`（60/120/180ms），也可直接写在元素上（`style="--delay:.55s"`）。
**错峰只用于同一步的一组图元，最晚元素延迟 ≤ 180ms**——单独截一帧仍然讲得清。

`--delay` 注册成 `inherits:false`：写在**外层包装节点**上不再传给子节点的 `.in`。要
一组整体错开就挂 `.stag`，要某个图元单独错开就直接写在它自己身上。

**`.stag` 自动错峰**：`sibling-index()` / `sibling-count()` 现算延迟，档间距取
`--stagger`，总量封顶在 `--stag-cap`（实测 2/3/6 项分别落在 0；0/.06/.12；
0/…/.18s，最后一项永不超过 .18s）。作者加图元不用回头改 CSS。三条边界：

- **减号两侧必须有空格**：紧凑写法让整条 `calc()` 在计算值阶段作废，而动画照样跑、
  延迟全落 0s，控制台不报错；
- **必须锁在分组那一层**：`.stag>*` 只命中直接子节点；`--delay` 不注册的话每个后代
  各自重算 `sibling-index()`，深层小图元也各自错开，满屏乱闪；
- 分母用 `max(…, 1)` 兜住单项组。整块包在 `@supports (animation-delay:calc(1ms *
  sibling-index()))` 里，不支持的浏览器整组同进，内容一格不少。

#### 3.4.3 分族手册

**（1）入场与节拍**

- `.in`：建档自带，淡入 + 轻微上浮；终态就是常驻态。
- `.pop`：弹一下，用于"已经在那儿的东西"被点名。
- `.pulse`：呼吸，用于等点击 / 提示该看哪儿。
- `.draw`：描线，配 `pathLength:1`；`stroke-dashoffset` 从 1 到 0。
- `.stag` 与 `--delay`：见 §3.4.2。

**（2）位置与状态**

- `.nt`：属性补间（位置 / 尺寸 / 颜色）。同一 key 的节点复用才有"上一状态"。
- **几何补间**：`rect` 的 `x/y/width/height/rx`、`circle` 的 `cx/cy/r`、`ellipse`
  的 `rx/ry`、`path` 的 `d` 可补间（`d` 要求两条路径命令序列同构）。`<text>` 的
  `x/y` 与 `<line>` 的 `x1/y1/x2/y2` **不在列**——文字的位移只能靠 `transform` 或
  独立 `translate`，连线要动就用 `.draw` 或挂父层。
  现量写法：新建档先落一个够用的占位框，`getBBox()` 量出字宽再写终值；**占位框只给
  新建档写**（`if (!REG[boxKey])`），复用节点再写一遍会被当成真实状态变化，画面先
  补向占位值再掉头，是肉眼可见的抖动。
- `[data-dim="1"]`：焦点弱化。`@property --dimmer` 注册成数字驱动
  `filter:saturate()/brightness()`；**只碰 filter，不碰 opacity**（opacity 会盖掉
  renderer 写在呈现属性上的逐句档位）。弱化档同时写 `opacity:.45` 作兜底：退到背景
  的东西仍要能被看见当参照。
- `#cam`：推拉摇移，窗由 `CAM` 声明。**位移定拍**：JS 只写 `--cam-pan` /
  `--cam-zoom` 两个读数，`--cam-dur` 由 `clamp()` 现求（地板 `.5s` == `--dur-spot`，
  灯永远不落在镜头后面；封顶 `.78s` < `--dur-ride .8s`）。两个读数**故意不注册**
  （注册了就去补间"行程"，时长自己也在爬）；**读数写在 `transform` 之前**（反过来
  会夹一次强制布局，补间拿到上一趟的时长）；擦洗与截图模式一律写 `0/0`。
- `#depth`：远景视差。与 `#cam` **同级兄弟**、共用世界坐标，镜头每落一次按
  `--par-far` **同向**漂一小段、**不放大**。位移取 `camTo()` 回传的 `tx/ty`，不要在
  别处重算钳位公式；系数从令牌读（改名时 `parseFloat` 得 NaN，落回默认档）。位移挂
  父层 `transform`，不改子节点 `getBBox()`。
- **对焦**（`depthFocus()` / `--defocus`，0.35.0）：镜头推近的确认拍。取景窗只回答
  "框住哪儿"，失焦把"该看哪儿"从构图升级成景深：`#depth` 远景层按取景窗倍率失焦
  （超过 `--defocus-in` 开始、到 1.8× 封顶 `--defocus-max`），推回即复原。三条边界：
  - 状态由 `camSet()` 每步现算写进 `--defocus`（与 `depthShift` 同一调用点），作者
    零负担；参数只从令牌读（`--defocus-in` / `--defocus-max`），改名删名
    `parseFloat` 得 NaN 落回默认档；
  - 只对**声明过的取景窗**演：窄屏 `contentBox` 兜底取景是自适应不是叙事推近，不虚；
    FULL 与中等景别（k ≤ `--defocus-in`）恒锐；
  - filter 与 transform 共用派生时长 `--cam-dur`——对焦和运镜是一回事，不引入第二套
    时钟；擦洗与运镜同一节奏地追，reduced-motion / 导出截图切掉补间后落当步真实
    档位；只挂 `#depth`（远景装饰层），命中 / QA 几何不受影响。
- `.el.swF` / `.swB`：方向感换场——换节时新画面从行进方向一侧进场。判据是**换节**
  不是换句（`lastSceneIdx` 比对）；冷启动第一步、擦洗、截图模式不演。位移写独立
  `translate`。退场那一幕要在 `only()` 里把 class 摘干净，否则下次入镜重放旧动画
  （导出每帧冷启动，那一帧就停在半推半进上）。
- `.blurpass`：运镜运动模糊。0%/100% 都是 `blur(0)`，只在中段糊一下；只在真的挪了
  一次镜头时触发（位移 > 180 世界单位，或倍率相对变化 > 22%）；不达标的这一步必须
  主动 `remove`，否则下一步小移动会再跑一遍。

**（3）揭示与退场**

- `.reveal` / `.revealL`：擦除揭示，`clip-path:inset()` 从一侧扫出；方向带语义
  （左→右"往后推演"，右→左"回溯"）。边界：
  - 只裁不位移，`getBBox()` 全程恒定，但**命中跟着裁**；
  - 挂在**包装 `<g>`** 上，不与 `.nt` 的 transform 同节点；
  - **两端都写成 `inset()`**（`inset()` 与 `none` 不可插值，只写 `from` 会按
    discrete 两格硬跳）；
  - 用 `backwards`，不写 `forwards`。
- `.featherR` / `.featherL`：羽化揭示，mask 渐变带掠出，软边。用于结论/记法这类
  不打扰观众的内容。边界：
  - `@property --feather` 初值取终值 134%（不透明段占到 100%），于是不支持
    `@property`、不支持 mask、导出切掉 animation 三种"没跑"的情形都落在**完整可见**；
  - **mask 不裁命中**，所以这一层必须 `pointer-events:none`；需要 Learner 点的图元
    一律用 `.reveal`；
  - 挂包装 `<g>`、不进 `.nt` 清单；两端写百分比 + `backwards`。
- `.tuckR` / `.tuckL`：收拢退场，沿行进方向把那一行收走，`.reveal` 的反函数。边界：
  - 走 **transition**：对象必然在前一步已被写过，复用节点就地改 `clip-path` 天然有
    完整行程；冷启动第一步直接落终态，导出切掉 transition 落"那一秒的真实档位"；
  - 两端都写**四长度 `inset()`**；静止档 −15%（外扩）、收拢档 115%（`inset(0)` 会
    啃掉描边与箭头，85% 会留能点着的残角）；
  - **消费者要"多停一拍"**（`step >= 1 && step <= 2`）：新建档没有上一状态；
  - 只挂**纯包装 `<g>`**，除 `gone` 外不写任何 `.nt` 会补间的属性——同节点两条
    transition 简写会互相顶掉，计算值只剩 `clip-path`；
  - **需要 Learner 点的图元不许收拢**。
- `.bloom`：圆形绽开，`clip-path:circle()` 关键帧从 0% 到 75%。`circle()` 的百分比
  按 `sqrt(w²+h²)/√2` 归一，覆盖整盒的下限恒为 √2/2 ≈ 70.7%，所以终态取 75%（50%
  咬边、100% 白给）。关键帧两端同型、静止态写在元素自己身上、不写 `forwards`。clip
  会裁命中：**要点的图元不要开 `.bloom`**。

**（4）关系、注意力与标注**

- `#cap-hl`：结论句划重点。几何从 `#cap-text` 现量（`capShow()` → `capHl()`），
  色带写在 `#cap-text` **之前**、字压在上面；`x`/`width` 同时写进呈现属性作兜底；
  **非结论句一律写 0 宽**（否则上一句的色带赖在下一句下面）。它是**状态**，减动效只
  关 transition、终态照留。
- `#spot`：落点灯。`#cam` 最后一个孩子，一层 `mask-image:radial-gradient()` 暗幕，
  `--spot-x/y/r` 注册成 `<length>` 才能逐帧插值。
  - 洞心从 `camBox()` 现量：目标 `getBBox()` 沿 `transform.baseVal` 逐层乘到 `#cam`
    坐标系；**不用 `getScreenCTM()`**（补间半途取到上一帧矩阵，灯照歪）；
  - 半径取外接圆 `hypot(w,h)/2 + 26`；幕深按 §8 合成反推（封顶 `.15`，洞外正文仍需
    过 4.5:1；量的是**相对亮度跌幅**不是 WCAG 比值）；
  - 暗幕四边各向外多铺 `--spot-bleed`（≥ 取景框宽 / .85 / 2）：幕要盖住整个取景框，
    不是 `viewBox`。`rect` 坐标、令牌、`mask` 里的 `calc(+bleed)` 三处同改；
  - 整层全局、不随 `sweep()` 撤走，所以 `begin()` 每步 `spotOff()`；renderer 不声明
    就是没有聚光；
  - `pointer-events:none`；字幕带在相机之外，不进灯；
  - **主角在世界层的那一句别打灯**；全景步也不打。
- `.mark`（`markBehind()`）：荧光笔标记，色带按目标文本 `getBBox()` 现量（宽 +8、
  高 ×.55、起点 y+45%、左缘 x−4）。必须 `insertBefore` 到文字**之前**（SVG 没有
  z-index）；只有琥珀字配亮带（红字合成后跌破 4.5:1）；斜度走独立 `rotate`，终态写
  在元素自己身上；一次性标记，下一步 `sweep()` 收掉。
- `.strike`（`strikeThrough()`）：反证划线，append 在文字**之后**；斜率按
  `--strike-tilt` 算进端点（水平线的 fill-box 高为 0，rotate 没有稳定旋转盒）；文字
  同时压到 `#8d95a8`；`pathLength=1` + 自建 `strikeIn`，不挂 `.draw`；线宽
  `max(2, bbox高×.09)`。
- `.scope`（`scopeFrame()`）：对位镜，两端 tick + 中间读数 `i=k`，线 + tick 合成一条
  path 配 `.draw`。同一行换位只补组上 `transform`，换行/换对重建重画。只做注解：
  `pointer-events:none`、墨色 `--scope-ink`、读数写短记号。
- `.brace`（`braceUnder()`）：集合括注。并集从被括节点 `getBBox()` 沿 `transform`
  属性现推（不读 `getScreenCTM()`）；两臂各一条 path、同收一枚括尖（写成一条会读成
  划线）；标签晚 `--dur-draw` 的 .6 落；落点在内容下方、字幕带之上；`pointer-events:
  none`；只括"同组"，不括整列。
- **引线标注**（`callout()` + `drawCallouts()`，0.38.0）：给一件已在场的图元挂一句
  短注记——圆点落在它的边缘、一段先直后斜的引线、一块垫实底的药丸签。
  - **登记与布局分两拍**：renderer 只登记（`CALL`，与 `DECODE` / `COUNT` 同一张
    "每步清空、renderer 重挂"的表），`drawCallouts()` 在 `worldFor()` **之后**、
    `camSet()` **之前**现量——renderer 跑在主角落位之前，世界层还停在上一步；
  - 几何从被注节点的 `boxIn()` 现推：点外伸 2、引线先直 10、签离点 16（横向）/ 12
    （纵向）、签内边距 18；朝向 `side:'r'|'l'|'t'|'b'`，默认右；横向两档签上抬一个
    签高，引线因此读得出"从这儿连过去"；
  - **三种时序**：点 `.in` → 线 `.draw`（delay = `--dur-in` × .22）→ 签
    `calloutLand`（delay = `--dur-draw` × .72），签从**所指处退回**自己的位置
    （`--c-dx/--c-dy` 反向缩回），终态是元素自己的 0；
  - **安全区 = 这一步的取景窗**（`CAM[sid][step] || FULL`）内收 6：推近的镜头里注记
    不被裁到画外；塞不下、或钳回后压住被注对象时**整条不画**（宁可不注，不注错位）；
  - **复用同一 key 不重放**：被注对象跨步移动时签组 `transform` 由 `.nt` 补间跟走；
    `gone:true` 把线沿原路收回到圆点、签与点同时淡掉（与 `.tuck*` 同一族：读过的东西
    让位要快）；
  - `pointer-events:none`；文案进 `put()` 的 text 通道，`check_gates.py` 的双字幕
    比对看得见它；`dec:true` 与 `badge` 同义。同一步**不要与 `#spot` 并用**：
    两套注意力装置各说各的"看这儿"，读者只会两个都不看。
- **关系连线**（`connect()` + `layoutConnects()` / `connTock()`，0.43.0）：比较 /
  匹配 / 归并等**两个已在场图元之间的双边关系**成立当拍，一条细线从 a 的 bbox 边缘
  长到 b 的边缘。与 callout / brace 同一张"纯注解层"纪律：
  - **登记与布局分两拍**：renderer 只登记（`CONN`，与 `CALL` 同一张"每步清空、
    renderer 重挂"的表），`layoutConnects()` 在 `worldFor()` **之后**、`camSet()`
    **之前**现量（与 `drawCallouts()` / `drawCompares()` 同批）——renderer 跑在
    主角落位之前，世界层还停在上一步；
  - **端点贴面不穿心**：两端取两中心连线与各自 bbox 边缘的交点、再沿该方向外伸 2
    （与 callout 圆点同纪律）；`boxIn()` 的第三参 `flush` 传 `true`——量前同位置重插
    一次强制失效几何缓存（复用节点改了几何属性后 `getBBox()` 可能返回旧盒）。这个
    重插会让节点自己的 CSS 动画（`.in` / `.draw`）从头重放，所以**只有 connect 的
    两个调用点传 `true`**，其余原语走默认 `false`（0.44.0 把 0.43.0 的无条件重插
    收窄：它等于每句给所有被量的目标重放一次入场）；
  - **边界三不连**：线长 < 24px 不连（贴脸不画线）、量不到两端不连（节点不在台上 /
    空盒直接跳过）、标签塞不下不画（中点居中，生长 35% 后才浮现，`pointer-events:
    none`）；
  - **时序**：生长（句首 `stepT0` 起、`--dur-conn:.5s`、easeOutExpo——与 count roll /
    meter 同拍，`dashoffset` 1 → 0 是 JS 逐拍读数）→ 复用同 key 不重放（关系未断线
    保持完整）→ `gone:true` 沿原路收回再移除（显式"关系解除"）；**不登记即消失**
    （旧线直接摘掉，与 CALL sweep 同口径）；`.conn .line` 只挂 `d` 的 transition
    （端点跨步移动时线的补间），`dashoffset` / 标签透明度逐拍、无 transition
    （防双缓动，与 `.meter` 同课）；
  - **导出 / reduced-motion 落终值**：生长落 `stroke-dashoffset 0`（线完整，定格里
    读"这两件有关系"）、收回落移除（关系不成立）；复用同 key 不重放；
  - 线只做"关系"这一件事，不替代 callout（标注）/ brace（括组）；`pointer-events:
    none`。
- **细节镜**（`loupe()` + `layoutLoupes()` / `loupeTock()`，0.44.0）：把一件**已在场**
  图元的某一小块"拿到眼前"放大——看清一个字符、一个下标、一处差异。与镜头推近
  （0.35.0 对焦）分工：推近是"我走近了、远景跟着虚"（取景窗整体变化），细节镜是
  "取景窗不动、旁边的东西不跟着变，只有镜里那块被放大"。与 callout（说谁）/
  brace（括组）/ connect（什么关系）同一张"纯注解层"纪律：
  - **登记与布局分两拍**：renderer 只 `loupe(key, node, opt)` 登记（`LOUPE`，与
    `CALL` / `CONN` 同表），`layoutLoupes()` 在 `layoutConnects()` 之后、`camSet()`
    之前现量（与 `drawCallouts()` 同批）；
  - **镜心在目标外侧、四侧择一**：`opt.at` 是观察点在 bbox 内的相对位置（默认
    `[.5,.5]` 中心）；`opt.side` 默认 `'r'`（目标右缘外 `gap 26 + r`），放不下依次试
    `l` / `t` / `b`；**四侧全放不下、或取景窗比镜还小（`2r+4` 超窗宽 / 窗高）→
    整个不画**（宁可不放大，不放大一个错位的块）；
  - **镜里是定格副本**：`cloneNode` 克隆目标子树、递归摘 id（重复 id 破坏 `REG` /
    `el()`），根上摘掉 `opacity` / `data-dim`（这块本来可能退居参照，但镜里是"看清"，
    还原标准亮度）；`.copy *` 关掉克隆体自己的 `animation` / `transition`——镜里不重放
    入场、也不跟 `.nt` 的中间帧；每换句重克隆一次（对象换了位置 / 文案，镜里跟着换）；
  - **三层各干一件事**：`lid` 只平移（镜心跟走，走 `--dur-move` transition）、`zoom`
    只缩放（JS 逐拍写 `scale`，**不挂 transition**，与 `.meter` / `.conn` 同课防双
    缓动）、`mag` 只 `translate(-u)`。**变换顺序是 scale 在外、translate 在内**：
    `P′ = k·(P − u)`，写反内容会飞出镜圈（实测踩过）；
  - **时序**：圈与内容从 `.72` 弹到 1（`--dur-in`）+ 内容从 `k·.92` 定到 k
    （`--dur-loupe:.45s`、句首 `stepT0` 起、easeOutExpo，`loupeTock()` 逐拍写）；复用
    同 key 跨步不重放（`__t0` 不动，p 早已到 1 保持 k）；`gone:true` 进 `.gone` 淡出，
    下一步不再登记时 `layoutLoupes()` 连同 `clipPath` 一起摘掉；
  - **茎从目标边缘起、到镜圈止**：起点是"观察点 → 镜心"射线与目标 bbox 的交点
    （从内部起笔会压在字上），终点收在圈内 2（圈边盖住线头）；
  - **导出 / reduced-motion 落终值**：scale 落 k、透明度 1、`gone` 直接不可见
    （定格里读"这一块放大后是什么"）；`pointer-events:none`。
- `.flow`：沿线流光，`pathLength:1` + `dasharray` + `dashoffset`，必须**叠在一条
  看得见的 `.draw` 底线之上**、分两个节点（同节点会互相顶掉）。静止态与终态都
  "看不见"——掠光是**事件**不是状态。`pointer-events:none`（虚线空隙不命中）。
- `.crisp`：`vector-effect:non-scaling-stroke` 恒定屏幕线宽。**不继承**，逐图元挂；
  只给注记 / 参照线用（卡片边框、结论色带跟着镜头变粗是对的）。
- `.halo`：`paint-order:stroke` + 一圈舞台局部底色的描边，让标注字压在线上仍可读。
  光环色取舞台那圈的渐变底色（不是 `--bg`），宽度用 `em` 跟着字号走。包 `@supports`。

**（5）行进与换位**

- `.ride`：沿线抵达。`offset-path:var(--route)` + `offset-rotate:auto`，只补间
  `offset-distance` 到 `data-go="1"` 的 100%，`linear`。路线是**数据**，写在呈现
  属性。终态写在 `data-go` 上（绝不能由 animation 驱动，否则切掉动效落回路径起点）。
  `getBBox()` 不跟着走：只能当**视觉指引**，不当热区、不参与 §5 连线判定；挂在不会
  提前收拢的层上。
- `.wake`：`.ride` 的余像修饰层。同一条 `--route`、同一个 `data-go`，只加
  `transition-delay:calc(var(--trail-step) * var(--wake-i))` 与 `pointer-events:
  none`。余像是**兄弟节点、建在头之前**，只描圆环、透明度递减；到站完全收在头下；
  行程太短别挂；reduce 只归零 delay，别关 `data-go`。
- `.swap`：换位弧凸。直线位移照旧走 `.nt` 的 transform，另在包装层叠一条垂直抛物线
  `offset-path`，两端回原点。包装层在蓄力层之外、只挂 `.swap` 自己的 transition
  （computed 只剩 `offset-distance`）；`offset-rotate:0deg` 必须显式写（默认 auto
  会把卡转 90°）；峰值 = 行程 × `--swap-k`、封顶 `--swap-rise`、短于 `--swap-min`
  的平移直行；换位判据由 `(scene, step)` 就地推导且 **sticky**（"排好了 → 收上架子"
  不重放；灯灭着的 `off` 不立基准）。
- `.trail`：拖尾跟随。只写长档 `transition-delay`（不重述简写，否则 `.nt` 十七项
  清单被整条顶掉）；先后从 `--trail-step` 派生、rank 写在元素自己身上
  （`--trail-r`，故意不注册）；行程为 0 的卡不给档；同一步只许一个让拍来源
  （`.wind > g` 特异度更高，拖尾自动退让）。
- `.traces`：换位弧痕。`traceAt(scene, step)` 纯扫描 `WORLD`/`POSE`，取本幕**最近
  一次看得见的换序**（两端 op>0 且同一排），且当前步仍停在换序结果上才返回；旧槽位
  → 新槽位画二次贝塞尔虚弧，弧高 = `min(--trace-max, 行程 × --trace-k)` 再按舞台顶
  封顶，行程 < `--trace-min` 或弧高 < 8 不画；起点补空心小圆当方向（无箭头）；层是
  `#world` 末尾的 `<g class="traces">`（晚于卡片 = 压在卡上），每步 `sweep`；只淡入
  （`.in`），不描画；线宽不挂 `vector-effect`（世界坐标物）。

**（6）判定与重量**

- `.settle`：挤压落位，独立 `scale` 关键帧。压扁与拉长由同一对令牌**镜像**（`0%`
  写 `calc(2 - var(--squash-x))`）；支点取 `fill-box` 底边中点（九档冻结读数的屏幕
  下沿必须同一个数）；只走独立 `scale`；只挂纯包装 `<g>` 且同节点不再挂第二条
  `animation`；曲线 `linear`；`backwards` 不写 `forwards`。**第一次落位才演**——复用
  同一 key 换位置是补间，不是又一次落地。
- `.wind`：预备后蓄。蓄力层在主角**之外**、**从建档那一步就在**（重新入树没有
  before-change style，那一次位移会当场落成终态）；走独立 `translate`；曲线
  `--ease-in-out`；两端与静止态都回零。主动作必须让出 `--wind-hold`
  （`--dur-wind × .34`），让拍走 `transition-delay` 长档写在**被补间的那一层**上
  （`.wind > g`）；reduced-motion 里让拍要**一起归零**。
- `.lift` + `--elev`：提牌投影。`@property{syntax:'<length>'; initial-value:0px}`
  （零档 = 还在台面上）；补间清单**只有 `--elev` 一项**，`translate` 与
  `drop-shadow` 都由它派生（影子比抬升走得远，系数 1.5 / 1.2）；档位写呈现属性
  `data-lift`（reduce 关补间不关档位）；只挂纯包装 `<g>`。**不许改用 `box-shadow`**
  （SVG 上计算值读得到而屏幕 0 个像素变）；投影不裁命中，别加 `pointer-events:none`。
- `.tilt`：倾侧定盘。只有离散三档（−/0/+，`--tilt-deg` 6.5°），终态写在
  `data-pan`；只补间独立 `rotate`、不写进 `transform`；`transform-box:fill-box` +
  `transform-origin:50% 50%`，且包装层包围盒中心必须正好是支点（往这层多塞一个
  下方图元就把支点顶跑）；`rotate` 不改 `getBBox()`，命中却跟着变换走——**要判定的
  东西别挂 `.tilt`，要动的东西别拿它当坐标**。

**（7）文字**

- `--lit`：跟读点亮。`@property` 注册成百分比、`inherits:false`，写在 `#cap-text`
  的 `mask-image` 停靠点上。
  - initial 取 **118%（100% + 带宽）**而不是 100%——`--lit` 是"停靠点"不是"完成度"，
    取 100% 时每句末尾 18% 永久留在地板上；
  - 用 mask 不用 clip-path：两者都不改几何，但 clip-path 会裁掉命中；
  - 它是**读数不是动效**：逐拍写 `style`、不挂 transition、**不进** reduced-motion
    清单；`capLitWrite()` 排在 `capProgWrite()` 之后（都在换句分支之后）；
  - 地板 `--lit-floor` 取 .85，按 §8 合成算对比度（非结论字 7.97:1 / 8.53:1，结论
    字 6.08:1 / 6.53:1）；改这一档必须重算。
- **逐字解码**（`decodeArm` / `decodeWrite`）：术语按句内进度从噪声里逐字定住。
  - **不许用随机数**：字面由 (目标字符, 下标, 句内进度) 现算，导出同一秒的两帧才
    一致；
  - **字宽不许漂**：建档时把终态宽度钉进 `textLength` + `lengthAdjust=
    spacingAndGlyphs`，量的必须是 `getComputedTextLength()`（推进量）而不是
    `getBBox().width`（墨盒）；
  - 噪声池按字符类分（CJK 换 CJK、数字换数字）；噪声若恰好算到真字自己，顺延一格；
  - 落定节奏 `round((1 − (1 − k)²) × 字数)`（缓出），前 `--decode-lead`（.72）走完；
  - reduce 与导出直接落完整的词（未定住的格本身就不可读）。
- `.gather`：字距归位。走 animation（"散→收"不是两个状态之间的行程）；关键帧两端
  同为 `<length>`（`.3em → 0`），不依赖 `normal` 的宽容；改的是排宽，档位按"最坏
  那句"选；只在**换节**那一拍重放；窄屏按**余量**关掉。

**（8）交互反馈**

- `.opt.rip`：触点涟漪。`::after` 一枚圆从触点涨满再淡掉，走 `pointerdown`。
  圆心与直径**在 handler 里现量**（`:active{scale}` 会把 rect 缩过）；base 与终态都
  不可见（事件不是状态）；`pointer-events:none` + 宿主 `overflow:hidden`；键盘路径
  不编圆心。
- `.hot` + `--hot-x/y` + `data-hot`：触点辉光，光跟着指针走。
  - 光心走注册属性不走 `left/top`（改后者每个 `pointermove` 都重排）；
  - 坐标注册成 `<length-percentage>` 且 **`inherits:true`**（消费者是宿主的伪元素）；
  - 位置补间 `linear`、`opacity` 配 `--ease-out`；静止态兜在 `50%`，`data-hot` 不
    存在；
  - **不用 `:hover` 驱动**（headless 与触屏的 hover 媒体查询均不成立）；
  - `pointer-events:none` + `border-radius:inherit`；键盘路径不点亮；放行后
    `[data-locked]` 按灭。
- **磁吸迎手**（`magMove` / `magClear`）：指针进到按钮盒边外 `--mag-r` 的场里，按钮
  朝指针挪最多 `--mag-pull`，位移按 `sin(πd/r)` 衰减。只写独立 `translate`；事件委托
  在 `#gate`（卡片每次开题重建）；场半径从**盒边**算并扣掉当前位移；只认鼠标/笔；
  `mqReduce` / 截图模式**一个字节都不写**；`focusin` / `pointerdown` / `pointerleave`

- `.mag`：同一套磁吸给选项药丸。因为 `.opt` 已挂全属性 transition 简写，位移写在外层
  `span.mag` 上，只演 `translate`；答对后按钮禁用即不再迎接。
- `.gate-next .go.shine`：放行键掠光。伪元素 + `background-position`；静止态停在盒外
  （`120% 0`）；`pointer-events:none` + 宿主 `overflow:hidden`；只演"这一行从无到有"
  那一次，判据取 `hidden` 的**旧值**（`var nextShown = !gateNext.hidden;` 必须排在
  `gateNext.hidden = false;` 之前）。

**（9）播放器**

- **擦洗态升级**：6px 轨道 → 9px、刻度 12px → 16px。只长高、不加 margin；圆角跟着
  高度走，填充 `border-radius:inherit`；过渡清单只给 `height` / `border-radius`，
  不给 `width`（进度走 `--dur-fill`，混进来就是第二个时钟）；刻度用 `top:50%` +
  独立 `translate` 居中。
- `#cap-prog`：句内进度细线。只写呈现属性、不挂 transition、**不进 reduced-motion
  清单**；几何在 `capShow()` 时现量存进 `capGeo`，`tick()` 每帧只写 `width`；调用点
  排在换句分支之后；空档不清零（停在满格），`ended` / 开场前才归零。
- `.bar[data-band]` + `--band`：越界橡皮筋。`seek` 把**未夹的 raw** 交给
  `bandWrite`、只把**夹过的**写给 `currentTime`——给手感不给时间，时间轴一个字都
  不许多说。气泡按 `cap·x/(x+soft)` 亚线性溢出，松手删档位由 `--dur-band` +
  `--ease-spring` 弹回；`--band` 注册成 `<length>`、`inherits:false`。
- `.tip`：窥探气泡。`pointer` 事件驱动；出现时轻弹 7px 落定，`transform` 里每帧都要
  重复写 `translateX(-50%)`（动画期间的 transform 整条接管静态值）；重触发判据留在
  JS 差分里。
- 进度填充：`.bar-fill` 的 `width` 走 `--dur-fill linear`——播放与拖动时连续滑动，
  不每拍跳变。

**（10）氛围与排版**

- `data-mood` + `--tint`：色温定调。注册成 `<color>`、`inherits:true`；补间只写在
  `:root` 一处，两个消费者（`#depth .wash` 的 `fill` 与 `body::before` 光晕）都不写
  transition。补间空间是 sRGB 逐通道线性（Oklab 实测偏离 40+ 通道单位）；三档必须
  **近等亮度**并按 §8 合成后逐格重算对比度；`--dur-mood` 长于任何一次运镜；换档挂在
  **换节**分支；档表没登记的段落继承上一档（不回落 calm）；柔光矩形排在点阵**之后**。
- `.pregate`：引导浮层离散进出。`transition-property` 包含 `opacity` / `translate` /
  `display`，`transition-behavior:allow-discrete` **单独一行**，`@starting-style`
  给进场起点；`[hidden]` 那一边写终态；整块包 `@supports
  (transition-behavior:allow-discrete)`。**`hidden` 属性仍是唯一真值**——QA 的放行
  信号与导出注入的 `display:none!important` 都不动。`#gate` 本体不转。
- **折叠面板**：`interpolate-size:allow-keywords` 让 `height:auto` 参与插值；
  `display` 必须同进清单；`transition-behavior` 单独一行；`@starting-style` 给起点；
  兜底带 `li.note` 抬特异度（基础规则源序在后）。
- **侧栏滚动驱动入场**：`animation-timeline: view()`，整块包 `@supports`、隐藏态只
  写在 keyframe 的 `from`、`animation-duration:auto` 显式写、`animation-range` 落
  **entry 段内**（取 cover 段会让不溢出的侧栏停在半透明格）、位移挂独立 `translate`、
  兜底用 `ul.notes>li.note` 抬特异度。
- **排版留白**：`text-wrap:balance` 让多行标题每行等长；`text-box-trim:trim-both` +
  `text-box-edge:text` 收走行盒上下的 leading（`text-box-edge` 只认 `text`，其他值
  整条作废）。只管 HTML 侧文本，SVG `<text>` 与字幕带不受影响。
- `text-spacing-trim:trim-start`：收掉行首全角标点的半格。只挂会换行的 HTML 正文，
  整块包 `@supports`；字幕带、等宽 `code`、`.kv` 不挂（单行无收益，却要动派生视图
  共用的 bbox 读数）。量法用 `Range` 墨迹宽，块盒 `getBoundingClientRect().width`
  量不到变化。
- `--key-soft/softer/act`：主色浅档底色，认得 `color-mix` 的浏览器由 `--key` 现调。
  兜底写在 `@supports` 里，不靠"同名两条声明"（自定义属性解析期什么都收，坏的是
  替换之后那条 `background`）。

**（11）数字与读数**

- **数字落定**（`data-count` + `countRollWrite` + `.roll`）：计数读数从旧值滚到新值。
  作者零负担——在 renderer 给带数字的图元传 `data-count`（目标值）即可，模板自动
  拾取：
  - **登记口在 `put()`**：attrs 里出现 `data-count` 的元素是计数读数。目标值同时写进
    呈现属性（导出 / reduce / QA 直接读它），并在**目标值变化**的那一步登记进
    `COUNT`（旧值 = 元素上一次的 `data-count` 属性）；
  - **首次建档与数值未变都不滚**：滚的只是"数值变化"这件事，入场照旧走 `.in`，
    同值不重写；
  - **滚动的起点是句首**（`stepT0 = hit.sentence.start`）：计数挂在"这一句的画面
    变化"上，与 `begin()` 每步清空 `COUNT` 配成 (scene, step) 纯函数，导出冷启动
    seek 到那一帧也照样是该滚的一步；
  - **中间值按 audio 时钟现算**：`easeOutExpo`（`1 − 2^(−10p)`，与 `--ease-out`
    同族），整数取整、小数按目标串的位数 `toFixed`；时长只从 `--dur-roll`（.5s，
    与 `--dur-move` 同档）读，`rollDur()` 读不到时落默认档；
  - **数字是"量"不是"进度"**：导出截图与 reduced-motion 直接落 `data-count` 终值
    ——定格里要读得到"比较了 3 次"，而不是"滚到 2.4 次"（与 `--lit` / 细线那些
    真读数逐拍留中间值形成对照）；
  - **挂 `.roll` 用等宽**（`font-variant-numeric:tabular-nums`）：滚动时字宽不跳，
    读数元素的位置与 bbox 稳定。只挂画布里的计数读数，字幕带与等宽 `code` 不挂。
  只做 SVG `<text>`；HTML 侧静态数字不做（不会滚，挂了也是死档位）。
- **量条**（`data-meter` + `meterWrite` + `.meter`，0.42.0）：几何量读数——条长 = 目标
  `width`，值变化的那一步从旧长滚到新长。它与数字落定是同一个"量"的两张皮（数字滚
  字身、量条滚长度），所以边界全部同款：
  - **登记口在 `put()`**：attrs 带 `data-meter` 的 rect 是量条，目标长度写进 `width`
    呈现属性；旧长 = 元素上一次的 `width` 属性，**首次建档与长度未变都不滚**（入场
    照旧走 `.in`，同宽不重写；上一步打断的 scale 由 `put()` 归位）；
  - **同一个拍**：起点是句首（`stepT0`）、时长共用 `--dur-roll`、`easeOutExpo` 现算
    中间长度、逐拍写 `transform` 属性（`scale(sx 1)`，等宽 1e-4 档）——与
    `countRollWrite` 同一只时钟、同一张"每步清空、renderer 重挂"的 `METER` 表；
  - **量不是进度**：导出截图与 reduced-motion 落 `scale(1 1)` 全满（定格里读得到
    "这条有多长"），live 播放逐拍滚中间长度——与数字落定同口径，与 `#cap-prog` /
    进度填充的"进展到哪儿"相反；
  - **`transform` 以条自己的左缘为轴**：`.meter` 挂 `transform-box:fill-box` +
    `transform-origin:left center`，类由 `put()` 自动补（作者只传 `data-meter` +
    `width`）；`transition:none!important` 是刻意的——`.nt` 的 width / transform
    补间会与滚动的 scale 双重叠加；
  - **只做 rect，不做路径 / 组**：`width` 是"上一长度"的唯一来源，别的 tag 拿不到
    旧宽；圆头在缩放中会被压扁——要圆头就把圆角画在外层装饰上，量条本体直角。
  要淡入 / 位移就包一层 `<g>`（`.in` 挂包装层），量条自己身上不挂别的 transition。

**（12）声画同步**

- **词拍**（`cue()` + `.cue` + `cueWrite()` / `cueGeom()`，0.39.0）：旁白念到哪个词，
  画面上那件东西就套上四角括号。它回答的是**时间关系**——"此刻在念谁"——不是
  "这是谁"（`badge`）也不是"这句话在说谁"（`callout`）。前沿对应是卡拉 OK / lyrics
  的逐词高亮，以及 AI 视频工具的 word-level cue；本仓库没有词级时间戳，词窗从句子
  自己的 `text / start / duration` 按**字数 + 标点权重**现算（`cueAt`），误差约
  ±1~2 字，宁早勿晚（`--cue-lead .08s`，夹在句首）。**不新增时钟**：仍然是
  `audio.currentTime`，仍然是 (scene, step) 的纯函数。
  - **登记、建层、上相位是三拍**：renderer 只登记（`CUE`，与 `DECODE` / `COUNT` /
    `CALL` 同一张"每步清空、renderer 重挂"的表）；`drawCues()` 在 `worldFor()` 之后
    只建空括号（`#cues` 在 `#cam` 内、注记之上、`#spot` 之下）；`cueWrite()` 按
    `audio.currentTime` 写 `.on`，并在**词窗打开的那一拍**由 `cueGeom()` 现量几何；
  - **几何为什么不在建层时量**：本步刚建档的卡，占位框宽 96 会经 `.nt` 补向真宽 76。
    范本开场实测——建层那一刻量到 57.6 宽的盒（96 × .6），落定后只有 45.6，括号
    左右各胖 6 单位。所以第一道在词到的那一拍量，之后在 `--cue-settle`（.56s，覆盖
    `--dur-move .5s` / `--dur-grow .42s`）窗口内逐拍重量到入场落定；同一 `d` 不重写，
    窗口过后本句内目标不再动，就只剩一次量；
  - **累积到本步结束**：从词出现到换步都不撤，一句点三次就是三道括号依次留下。
    导出每帧截在**句末**，所以成片里读得到"这一句点过谁"；下一步 `drawCues()` 重建
    整层，标记随步清零。没有退场动画——换步本来就是一次切；
  - **只做注记，不碰目标**：括号层 `pointer-events:none`，目标的几何、透明度、滤镜、
    命中区一个字都不动，因此可以落在要 Learner 点的热区上；`.crisp` 逐图元挂，
    镜头推到 1.8 时仍是 1.5px 注记。墨色取 `--cue-ink` 中性白：主色会说"重要"、
    红绿会说"对错"，而词拍只说"正在被念到"；
  - **一"词"框一件东西**：`word` 是**检索键**，必须与本句旁白原字面一致，不上屏、
    不进双字幕比对；同一字在一句里出现多次用 `opt.nth`（"1" 在 `10` 里一次、末尾
    一次，不写 `nth:2` 会框在 `10` 上）。要框"一组"用 `.brace`，词拍不做集合点名；
  - **与注意力装置的分工**：`#spot` 说"看这两个"、词拍说"现在念到这一个"，两者可以
    同场（范本 seg-5 s2：灯照着 true / false，括号依次点过"真""假"），因为一个管
    空间、一个管时间；同一步不要再用 `callout` 复述同一件事——三套注记各说各的会
    互相解释。词拍也不承担"结论"：结论划重点归 `#cap-hl` / `.mark`。
  - **状态不是动画**：`.on` 是 audio 时钟的读数，opacity 0→1、scale .94→1 走
    transition；导出 / reduced-motion 切掉补间后落"括号完整、无缩放"的定格，与
    `#spot` / `#cap-hl` 同族（关过程不关档位）。

**（13）对照与差异**

- **对照窗**（`compare()` + `[data-cmp="a"/"b"]` + `drawCompares()`，0.40.0）：把
  "同一个位置的两个版本"叠成一扇窗，A 从左往右退、B 从右往左进，接缝扫过时读到的
  是"改了什么 / 差在哪"。前沿对应是 before-after slider 与 diff wipe；这里不引入
  拖拽——`opt.at` 是 (scene, step) 的读数，观众看到的是被旁白推着走的擦除。
  - **登记、建层、上相位三拍**：renderer 只登记（`CMP`，与 `CUE` / `CALL` 同一张
    每步清空的表）；`drawCompares()` 在 `worldFor()` 之后量几何、写 `data-cmp`；
    `--cmp-r` 由 `opt.at`（0–1）写，默认 0。同一 `compare` key 跨步复用，`CMP_R`
    记住上一步的读数，步间差决定这一趟补间时长。
  - **互补裁切**：A 用 `inset(0 0 0 var(--cmp-r))`、B 用
    `inset(0 calc(100% - var(--cmp-r)) 0 0)`。0% 时只看得见 A，100% 时只看得见 B，
    中间不会两份重叠透出；`--cmp-r` 注册成 `<percentage>`（`inherits:true`），
    补间是浏览器对注册属性的插值，不是逐帧写 style。
  - **参考盒定窗**：A/B 的内容不同，各自的 `getBBox()` 也不同；窗取两者并集，才能
    让接缝从第一张卡扫到最后一张卡。做法是在 A、B 内部各放一个窗口大小的隐藏 rect
    （`data-helper="cmp"`、`fill:none`）把两边钉到同一坐标；这两个 helper 会参与
    `getBBox()`，所以每步**先摘再量**，`prune()` 也必须跳过它们（否则 renderer 的
    `sweep()` 会在 `drawCompares()` 之前把它们收走，窗口退回内容盒）。
  - **接缝、四角框与标签共用一份读数**：`#cmp` 在 `#cues` 之上、`#spot` 之下，
    `pointer-events:none`；缝隙组 `translate` 到 `win.x + win.w * r`，四角框画窗沿，
    版本标签用同样的 `[data-cmp]` 裁切与 `--dur-cmp`，所以标签出现 / 消失永远与
    卡片同步，不会各走一条时间线。缝两侧的暖色 wash 是 40 宽的渐变 rect，随组平移。
  - **标签首帧要先登记 0%**：新建的标签组第一次写目标 `--cmp-r` 前，先
    `void lg.getBoundingClientRect()` 强制一次布局；否则浏览器没登记初始 0%，会从
    "无裁切"直接跳到目标值，标签在擦除中段整块提前出现。
  - **时长令牌**：`cmpDur(delta)` 从 `--dur-cmp-min` / `--dur-cmp-full` 现算，
    `max(min, min(full, |delta| * full))`；`scrubbing` / 截图模式 / reduced-motion
    直接返回 0，`--dur-cmp` 写 `0s` 时裁切、缝隙、标签一帧到位。
  - **`at` 是状态不是事件**：0 / 1 是最常用的两档，中间值留给"正在擦"的定格；
    导出帧落在句末，读到的就是这一步声明的最终档位。`opt.dim` 把整框压到 .45，
    交给同一套 `data-dim` 纪律去弱化非话头；`opt.labels` 两个字符串分别贴窗的
    右上 / 左上，`opt.pad` 默认 6。A/B 必须都已入树且非空盒，否则这一条静默跳过。
  - **与 `.reveal` 的分工**：`.reveal` 是单件东西的硬边揭示；对照窗是"同位置两份
    内容"的差异比较，必须同时有 A 与 B，且窗沿、接缝、标签是一套注记。两者可以
    同场，但对照窗不负责入场，也不改变被对照节点的几何与命中区。

**（14）组成与拆解**

- **拆解视图**（`explode()` + `.explode` + `drawExplodes()`，0.41.0）：把一组
  **纯包装件**沿一条轴分开，露出一个已经成立的整体由哪几件组成。前沿对应是装配图 /
  爆炸图（exploded view）、维修手册的分解插画与三维拆解动画。它回答的是**组成关系**，
  不是"这东西怎么出现"——每一件从第一帧就在场，改变的只是件与件之间的距离。所以
  它不能替代 `.reveal` / `.in`；拆完也不是退场，而是可以留在台上继续当语法骨架
  （范本 seg-4 s0 拆比较函数、s1 起合拢成整幕共用的公式条）。
  - **登记、量几何、写位移三拍**：renderer 只登记（`EXPLODE`，与 `CUE` / `CALL` /
    `CMP` 同一张"每步清空、renderer 重挂"的表），并把每件的**装配位**放进
    `opt.base`；`drawExplodes()` 在 `worldFor()` 之后按离锚点的轴向距离归一求偏移、
    按距离算错峰，再写 `transform`。锚点默认取所有件盒心的均值，`opt.anchor` 可钉住
    某一件；`opt.axis` 选 `'x'` / `'y'`，`opt.offsets` 可逐件给自定义位移。
  - **`transform` 归原语独占**：renderer **不要**给这一层写 transform。CSS transition
    是在属性被写下的那一刻、用当时的 `--ex-delay` 起跑的；若 renderer 先写装配位、
    `drawExplodes()` 之后才改延迟，这一趟补间记住的是上一步的延迟——实测合拢时内外
    圈错峰整个反掉。正确接线是：节点只给 class 与子图元，装配坐标走 `opt.base`，
    位移一次写成。这也是它跟 `.nt` / `.lift` 等"作者写目标值"的图元最大的接线差异。
  - **首次建档要两次写**：新建节点若直接写"拆开后的目标"，浏览器会把创建与位移并成
    一帧，拆解看起来是瞬移。`drawExplodes()` 对首次参与且有位移的件先把 `--dur-ex`
    压成 0s、写装配位、`getBoundingClientRect()` 强制一次布局，再恢复时长与错峰、
    写目标。已经参与过的件不做这两拍——它已有上一拍的计算值可补间。
  - **错峰方向看 `amount` 的增减**：拆开时外圈先走、内圈后走；合拢时反过来（内圈
    先回、外圈最后落定）。方向只看这一拍相对上一拍的开合量，不看步号，所以往回擦洗
    时动画方向也跟着回。单件组或所有件重合时没有"分开"可演，直接落装配位。
  - **开合量是状态**：`opt.amount` 0 = 装配位、1 = 完全拆开，中间值合法；`EX_R` 记住
    上一拍的量，用来判方向。`gap` 是最外件的位移量（对称件各走一份，所以它们之间的
    间距实际增加 2 × gap），不是"最终间距"。
  - **几何与标注**：偏移写在 `transform` **属性**上，所以 `boxIn()` / `camBox()` 与
    `getBBox()` 的局部坐标都读得到目标位置；`drawCallouts()` / `drawCompares()` 在
    `drawExplodes()` 之后跑，注记量到的是拆开后的落点，不是装配位。件内的文字、卡框
    仍各自走 `.nt`；拆解层只做平移，旋转 / 缩放放进子节点。
  - **导出 / reduced-motion**：两者都把 `--dur-ex` 与延迟压成 0，目标 `transform`
    照写，所以定格落在"这一拍该拆多开"的状态上，不是半程；与 `.tuck` / `#spot`
    同一判断（关的是补间，不是档位）。
  - **与 `.reveal` / `.flip` 的分工**：`.reveal` 改变可见量，`.flip` 换同一位置上的
    说法，拆解只改变件间距离；同一步不要再用 `.tuck` / `.flip` 争同一层的 transform
    （`.explode` 的 transition 简写会顶掉 `.nt`，两套变换会互相覆盖）。

**（15）形变与连续**

- **形变**（`morph()` + `.morph` + `morphTock()`，0.45.0）：让**同一件东西**换轮廓——
  旧轮廓连续走到新轮廓，而不是撤掉再建一张图。前沿对应是 flubber / MorphSVG 那一族
  轮廓插值：两端各采同样多的点、先配好顶点对应、逐点走线。它回答的是"**它自己变了
  形**"——身份不变、形状变，读出来是连续的一件事，所以 `展示变化` 这一类目的里它占的
  是"轮廓本身在变"那一格：`.flip` 换的是同一位置上的**说法**（两面），`compare()` 是
  两个版本叠进同一扇窗（读差异），`.reveal` / `.tuck` 是上台与让位，`.nt` 的几何补间
  是同一个形状换尺寸 / 位置。范本没有加用例（理由见本节最后一条与 §9）。
  - **`d` 归原语独占，建档时也别写进 `put()` 的属性表**：`put()` 只在值不同时覆写，
    于是换句那一步它先把半路的采样折线顶成新的目标，`morph()` 随后读到的"旧轮廓"
    已经等于新目标 → 不登记 → 跳档。探针 A20 实测过这条坑（`put` 先写的节点登记不上）。
    正确接线：`put()` 只给 class 与样式，形状只从 `morph(key, node, to, opt)` 声明。
  - **登记即落终态**：`morph()` 在登记那一刻就把作者那条 `to` 写进 `d`（状态写在呈现
    属性上，纪律 4），飞行表另存两端采样；`morphTock()` 逐拍把中间帧写成 48 段折线，
    `p` 到 1 再落回作者那条精确轮廓。所以**"不演"从来不等于"不落"**——所有拒绝演出的
    分支（下面三条）都只关掉过程。
  - **顶点配对**：闭合轮廓搜"原序 / 翻转 × 整体旋转 n 档"，取逐点位移平方和最小的
    一档（部分和一旦超过当前最优就跳出）。不配对的后果是"两个三角形对转"——起点差
    半圈的对应关系把形变演成扭绞；实测星→方这一对配对后逐点行程从 105.5px 压到
    63.8px（省 40%）。开放路径（`opt.open:true`）锚在起点上、不搜配对，搜了会把线头
    挪到轮廓中间。**不做 flubber 的加权插值**：它补的是"两端周长差得多、点位速度不
    均"，代价是多一倍采样加一段距离场，而 48 点与一句的尺度里读不出更多——后果说清楚：
    顶点数差得远时（三角 ↔ 十点星）中间帧会有轻微穿边，终态不受影响。
  - **飞行表不随 `begin()` 清空**：`MORPH` 按 key 存"还在路上"的飞行，与 `CMP_R` /
    `EX_R` 同族但理由更强——登记表清掉时别的原语最多是"这一拍不再声明这件事"，
    飞行表若清空，节点会停在半路的折线上，形状读成"裂了一半"。收账只有三处：`p` 到 1、
    见旗（导出 / 减动效 / 擦洗）、节点被 `sweep()` 摘走。
  - **宁不变形**：不是 `<path>` 的节点原样不动（rect / circle 的形状由自己的几何属性
    写着，`.nt` 的属性补间本来就在兜）；量不到（零长度 / NaN）不演；逐点最大位移小于
    `--morph-min` 不演——"同一个正方形换个起点顶点写"正好落在这条上，它认得出形状
    其实没变（探针 A8b1）。
  - **导出 / reduced-motion / 擦洗**：都不登记，在飞的直接落作者那条 `d`。逐帧冷启动
    时首见即建档，所以成片每一格读到的都是**精确轮廓**，不会有半截中间态；这与数字
    落定 / 量条"落终值读的是量"同一条口径。
  - **`.morph` 的 transition 清单里没有 `d`**：整串抄 `.nt` 的十六项、只删 `d`（同
    特异度、写在 `.nt` 之后）。留着就是双重缓动——JS 每帧写一条折线，CSS 的 `d` 补间
    再追自己刚写下的那一帧，中间帧永远慢一拍、收尾也落不回精确轮廓（与 `.meter` 的
    `width`、`.conn .line` 的 `dashoffset` 同一课）。其余各项照旧，所以正在变形的图元
    可以同时走位移、透明度与描边色。
  - **为什么范本没有用例**：范本每一幕的话头都已经有专属仪器（对照窗、拆解、天平、
    提牌、词拍…），再挂一条"轮廓在变"要么与它们争同一个话头（违反"一屏一个话头"），
    要么回答不了"为什么在这"。本轮只在探针页与四格视觉夹具（e=0 / .35 / .7 / 1）里
    验证；真要用，优先挑"**同一件东西前后两个形态**"的句子——物态变化、图例换形状、
    规则换了之后的同一个对象。

**（16）过程与进度**

- **进度**（`drawTo()` + `.seg` / `.seg-g` + `segTock()`，0.46.0）：让**一条路自己的
  已走段**可见——前半截实线、后半截虚线、走头钉在断点上。课堂里推导线、流程线、推导
  链本来就**该停在半路**：停在 60% 不是"没演完"，那就是内容（"我们读到这一步，剩下
  的还没验"）。所以它回答的是 §判据里的 `展示变化` 与 `推进叙事`：变化的是"这条路
  的完成度"这个**状态**，推进的是"现在到第几步"。
  - **与四条形近原语的分工**（作者选型时按这一栏对号）：`.draw` = 线**被写出来**（事件
    0→1，终态是满线，没有"半路"）；`.flow` = 刚有一次**通过**（瞬时掠光，静止态与终态
    都看不见，是事件不是状态）；`.ride` = **有人**沿路走到那头（移动的是物件，路本身
    不变）；`drawTo()` = **路自己的已走段在走**（可停可退、跨句保持、导出落声明档位）。
  - **作者只画一条 `d`**：函数替它建一条同 `d` 的虚线副本（`path.seg-g`、`data-helper`、
    `pointer-events:none`），已走段在**原路**上用 `stroke-dasharray` 写长。副本必须
    **同父、紧随原路之后**——单开一层会随 `#cam` 缩放 / `--depth` 变深时与原路错位，
    挂在别的幕里还会被 `sweep()` 提前收走。
  - **时间走向分两种**（与 `connect()` 同一条理由）：首次长出来（`in`）用 easeOutExpo
    ——"画出来"是个动作；之后推进 / 回退（`linear`）按比例读 —— ease 会让观众对"还剩
    多少"判断错，退回去时尤其明显（先慢后快地退，读成"卡了一下才缩"）。
  - **进度是跨步累积状态**：`SEG` 登记表随 `begin()` 清空，但 `SEG_P`（key → 进度）
    **不清**——不登记 ≠ 收回，路停在原处（与 `MORPH` 飞行表同族理由；与 `.conn`
    "不登记即消失"相反，那条表达的是关系，这条表达的是"走到这儿了"）。要收，用
    `gone:true` 显式从当前进度收回 0。
  - **两个初值坑**（都实测踩过）：
    ① CSS 兜底必须写 `stroke-dasharray:0 9999` 这种**大周期**。写 `0 1` 时周期只有 1
       个用户单位，0/1 交替落在亚像素尺度，抗锯齿把它渲染成"半透明的实线"——整条路
       仍看得见，只是脏了一半，读起来像"线画重了"而不是"还没开始"；
    ② `stroke-dasharray` **不能只写在呈现属性上**：`.seg` 那条 class 规则优先级高于
       presentation attribute，会把进度整个盖掉（实测属性写着 `342.6 492`、渲染却是
       兜底值）。`segWrite()` 因此**两处都写**：属性给 QA / 导出脚本读（"读数落在属性
       上"），inline `style.strokeDasharray` 才是真正压住 class 的那一份。
  - **走头**：`opt.head` 给一个节点，`segWrite()` 用 `getPointAtLength(clamp(0, L, v·L))`
    现算 `cx / cy` 钉在断点上。它是**记号不是物件**：不参与 §5 连线判定、不当热区，
    路被 `sweep()` 摘走时跟着一起收。
  - **不进 `d`、不碰 transform**：这条原语一个字节都不改作者画的 `d`（对比 `morph()`），
    也不接管位移（对比 `.ride`）；它只碰 `stroke-dasharray` 与那条副本。所以它可以和
    位移、透明度、描边色**同时**用，互不顶掉。
  - **导出 / reduced-motion / 擦洗**：直接落作者声明的 `at`（定格里读到"走到这一格"，
    不是一段没演完的中间态）；`stops` / `step` 也按站取档。同 `数量不是进度` 的口径：
    成片每一格读的都是状态值，不是过程值。
  - **量不到就不画**：`getTotalLength()` 为 0 或 NaN 时静默跳过（`<path>` 以外的一律
    不登记：rect / circle 的轮廓由自己的几何属性写着，要表达进度就换成 `<path>` 写）。

**（17）重复与逼近**

- **圈数**（`loopTo()` + `.lp` / `.lp-cur` + `loopTock()`，0.47.0）：让**同一件事反复
  做**这件事可见——不是"演一遍快动作的循环"，而是"绕到第 k 回、每一回落在哪儿"。
  整张词表说的都是**一次**：上台、挪位、擦除、形变、走到第几段，全部终将落定；而迭代、
  逼近、逐位比较、周期运动说的是 `一个计数 + 一串落点`。它回答的是 §判据里的 `过程`
  与 `推进叙事`：变化的是"绕到第几圈"这个**状态**，推进的是"第 k 圈又短了多少"。
  - **与三条形近原语的分工**（选型按这一栏对号）：`.pulse` = "该看这儿 / 等你点"，一个
    **没有内容**的呼吸，不数回；`.ride` = **有人**沿这条路走到那头，连续、有目的、中途
    不停；`drawTo()` = 这条路走到第几段，**连续的比例**、可以停在半路；`loopTo()` =
    这件东西绕到第几回，**离散**的落点，只能停在第 k 圈，且每一圈内部还要再分"走一段 /
    停一下"——那一段静止就是确认拍，观众据此数圈。
  - **收敛由运动本身说出来**：`stops` 是相对 `base` 的位移，作者把它写成越走越短；
    每圈时长又**归句子**（`per = 本句时长 ÷ 本步要绕的圈数`，夹在 `--loop-per-min`
    `.5s` 与 `--loop-per-max` `1.6s` 之间）。于是"每圈花同样久、每圈挪得越来越少"就是
    "它正在逼近"——不需要旁白解释，也不需要额外的缓动档位。作者**只给几何与读数**
    （`base` / `stops` / `at`），不填时间：时间与坐标两边都是现量的，与词拍同一口径。
  - **一圈分两段**：走 `--loop-run`（占比 `.62`，行程再封顶 `--dur-loop` `.5s`）用
    easeOutExpo，剩下的**停**。停那一段是内容不是空档；环口（游标那枚开口环）却按
    **整圈占比匀速**转——一圈就是一圈，缓动会把"绕完"这件事转歪。
  - **`at` 是读数、`stops` 是全量声明**：每一步都重申整条梯子（与 `drawTo` 的 `at` /
    `explode` 的 `amount` 同一口径）。所以回退（5 → 3）、擦洗、冷启动定格算出来的都是
    同一格；落点痕与游标位置一律由 `(base, stops, at)` **现算**，不记流水账——导出那一帧
    没有"上一帧"可继承，凭这三样就能把 4 枚痕摆回原处。
  - **落点痕**：已经落定的每一圈一枚小圆点（`--loop-dot`），**落在当前位置上的那一枚不
    画**（游标环就是它，画两枚会读成"这里有两个东西"）。
  - **读数让开本体**：`k/n` 的 x 偏移取 `max(--loop-r, 对象半宽 + 4) + 5`，半宽由
    `loopWorld()` 顺带回传（宿主可能是 26 宽的筹码，也可能是 400 宽的卡片，写死偏移
    必然在一头压字）。环本身是**锚点级**的固定小圈（`--loop-r` `7`）——要框住整个对象
    用 `cue()` / `.scope`，别指望环去贴合轮廓。
  - **账本四张**（`LOOP` / `LOOP_RUN` / `LOOP_P` / `LOOP_LIVE`）：登记表 `LOOP` 随
    `begin()` 清空，圈数账 `LOOP_P` **不清**——不登记 ≠ 收回，它停在已经落定的那一圈
    （与 `SEG_P` 同族理由）。**但节点被 `sweep()` 摘走时 `LOOP_P` 一起清账**：对象都不
    在场了，"它绕到第几圈"就没有所指，留着只会让重建出来的新节点凭空少绕几圈（这一条
    与 `MORPH` 的飞行表相反，那边留着是因为轮廓还挂在同一个节点上）。
  - **`transform` 归原语独占**（同 `explode` 口径）：宿主必须是**纯包装 `<g>`**，
    renderer 只给 `base` 坐标、不写这层的 transform；探针实测在每拍里补写
    `transform:'translate(0,0)'` 会把原语刚落下的那一格顶回原点，而且**画面看起来只是
    "没怎么动"**，最难归因。
  - **`.lp` 的 `transition:none` 是硬要求**：JS 每帧写 `transform` 属性，CSS 再补一遍就
    是双重缓动——中间帧慢一拍、收尾落不回声明的那一格。`layoutLoops()` 会替忘挂的节点
    自动补 `.lp`（与 `layoutSegs()` 补 `.seg` 同一处兜底），确认拍那一下的弹跳走**独立
    变换属性 `scale`**（`.lp-pop`），不与位移抢同一条简写。
  - **句子装不下这么多圈**：`per` 夹在地板 `.5s` 上不硬挤，剩下的圈**溢出到下一步继续
    落**；若下一步没再登记这件东西，注记在落完那一刻摘掉（落点与账本留下）。写课件时
    这不算 bug：读数 `at` 声明的是"这一拍读到第几圈"，不是"这一拍必须演完"。
  - **静默不演**（四种，都不报错）：缺 `base` / `stops` 为空 / 节点不在这一步的台上 /
    `at` 正好等于已绕圈数。最后一种**注记照常给读数**——"停在第 3 圈"是内容，不是没演。
    排查顺序：这一步登记过没有 → 节点在不在台上 → `at` 与 `LOOP_P` 是不是同一个数。
  - **导出 / reduced-motion / 擦洗**：直接落作者声明的那一圈（定格里读"绕到第 k 圈"，
    不是一段没跑完的中间态），`LOOP_RUN` 不留飞行中的趟；减动效下 `at:3` 从前一圈 5
    **回退**到 3 也照样落对。痕按同一判据现算，所以定格里痕的枚数与播放中读到的一致。

**（18）并行与相位**

- **时序带**（`lanes()` + `.ln` + `lanesTock()`，0.48.0）：把**并行关系**放到同一把尺子
  上读——"这几件东西各自走到哪儿了"。整张词表其余原语说的都是"一次"或"一条"：
  `drawTo()` 是一条路、`loopTo()` 是一件东西、`.ride` 是有人走过去；而"读盘与写盘同时
  进行""先做 A 再做 B，但两句旁白其实是一段"这类**同时 / 先后**，此前只能靠旁白说出来。
  它回答 §判据里的 `关系` 与 `过程`：变化的是"第 i 条道走到几成"这个**读数**，推进的是
  句子本身。
  - **与三条形近原语的分工**（选型按这一栏对号）：`drawTo()` = **一条路**自己的已走段，
    单条、连续、可以停在半路；`loopTo()` = **一件东西**绕到第几回，单件、离散落点；
    `.ride` = **有人**沿这条路走到那头，移动的是物件、路不变；`lanes()` = **几件东西
    各自**走到哪儿，多轨、共用同一条时钟，比的正是相位差。它不演"顺序执行"本身——那是
    各步 renderer 的事——它演"这几件东西在时间上是什么关系"。
  - **相位是唯一的表达**：`phase[i]` 是第 i 条道在**句子进度**上的起步点（0–1），缺省
    全 0 = 同时起步；实心比例 `laneFill(at, ph) = (at − ph) ÷ (1 − ph)` 封顶 1。除以
    `(1 − ph)` 是关键：起步晚的那条**仍然在句末走完**，先后 ≠ 没做完。相位钳在 `[0, .9]`
    ——写 1 就是"永远不开始"，那是笔误不是内容。
  - **这一族没有跨步账本**：实心段宽与针位都是 `(t − stepT0) ÷ dur` 的纯函数。`SEG_P` /
    `LOOP_P` 那两张账本存在，是因为"走到第几段""绕到第几圈"是**历史**；而"这一句里第 i
    条道走到几成"是当前读数的函数，记下来只会多一份对不上的账。于是擦洗、逐帧冷启动、
    导出读的都是同一格——探针直接断言"直播句末与冷启动定格同一格"。作者也因此**不填
    秒数**：只声明哪几件在一起、谁先起步。
  - **带子摆哪儿全部现量**：各 item 的 `boxIn()` 并集 → 带宽 = 水平跨度，下限
    `--lane-min`（几件东西挤在一列时带子不该细成一条缝），比并集宽时**相对并集居中**，
    不让左边那件占便宜；上下沿优先摆在对象**下方** `--lane-pad` 净空，放不下整带就翻到
    上方，两头都放不下（取景窗太矮）整条带不画。
  - **安全区是本步声明的取景窗**（`(CAM[sid] || [])[step] || FULL`），不是 `VIEW`：镜头
    推到 `[230, 61, 580, 120]` 那一格时窗底只有 181，拿 `VIEW`（底 394）判会把带子摆进
    看不见的那半截舞台，或反过来在能看见的地方提前翻面。与 `drawCallouts()` /
    `layoutLoops()` 同一口径。
  - **"现在"针是整条带唯一的时间证据**：一条竖线跨全部道（上下各出头 3）+ 顶端小三角，
    描边挂 `.crisp`——镜头 1.4× 时不糊成一条杠。实心段与针共用强调橙 `--lane-ink`（与
    徽标 / 引线同族），轨道底槽走中性 `--lane-track`：它是上下文不是话头。
  - **标签只说"这条道是谁"**：摆在带左外 8、带 `.halo`（压在连线上也读得清）。宽度只在
    文字变了时量一次（`laneLabW()`），量前把 `display` **属性**临时请回来——这里藏的是
    属性不是 inline style，读 `style.display` 永远量到 0。整组放不下就**都不画**，不留
    一半；带宽与针照旧，标签不是第二条注记。
  - **同值不重写**：`laneSet()` 比较前先 `String(v)`——数值属性取回来是字符串，
    `'3' !== 3` 会让这条老纪律形同虚设。探针 spy 过 `setAttribute`：同一拍重复写 0 次，
    时钟推进时轨道那四个属性仍是 0 次（只有实心段与针在动）。
  - **不登记即摘**（与 `callout` / `connect` 同族，与 `SEG_P` / `LOOP_P` 相反）：这条带
    记的是"这一句在说哪几件一起"，不是对象的历史，所以下一步没再登记就整条摘掉，**没有
    `gone`**。item 里有一件被 `sweep()` 摘走 → 整条带一起摘：半条带比没有带更误导，与
    `loupe` / `callout` 的"量不到就不注"同一口径。
  - **静默不登记**（三种，都不报错）：没给 `items` / `items` 为空 / 任一节点不在这一步
    的台上。排查顺序：这一步登记过没有 → 几件东西是不是都还在台上 → 带子是不是被"放不下
    就不画"收走了（换句时 `layoutLanes()` 会再判一次）。
  - **导出 / reduced-motion / 擦洗**：`laneAt()` 见旗恒取 1 → 几条实心段一起满、针停在
    带右缘。定格里读的是"这一句念完，这几件事都做完了"，不是"针停在半路"的中间态。

**（19）取数与区间**

- **区间窗**（`range()` + `.rg` + `rangeTock()`，0.49.0）：把"取的是**哪几件**"落成
  一条会移动的取景带。整张词表在此之前全在**时间轴**上说事——`drawTo()` 一条路走到
  第几段、`loopTo()` 一件东西绕到第几回、`lanes()` 几件各自做到哪儿；而
  `slice` / `substring` / 二分查找的候选区间 / 滑动窗口 / 分页，讲的是"从第几件到
  第几件这一段"：**宽度本身就是读数，而且它得会走**（同一个宽度扫过整排才叫窗口在
  滑）。此前这句只能靠旁白说"我们看中间这三个"，画面里没有东西在说"中间"是哪三个。
  它回答 §判据里的 `关系` 与 `过程`：变化的是"取哪几件"，推进的是"候选区间收窄 / 窗口
  右移"。
  - **与四条形近原语的分工**（选型按这一栏对号）：`.brace` + `braceUnder()` =
    **这几件算一组**（静态括注、没有序号、不会走）；`#spot` / `[data-dim]` = **只看这一
    处 / 其余是上下文**（一个点或一层压暗，不是一个区间）；`lanes()` = 这几件**各自**
    做到哪儿（时间上的并行）；`drawTo()` = **一条路**自己的已走段（路径比例，不是序号
    区间）；`range()` = **取哪几件**（序号区间：宽度是读数、位置是内容）。
  - **作者只给序列与两个序号**：`of`（按序号顺序声明的那一排）+ `from` / `to`（0 基、
    **闭区间**、缺省 `to = from`）。它与 `slice(a, b)` 差一格——`slice` 是半开区间，
    要照抄写 `to: b - 1`；这条差别写在文档里，不提供第二个开关。越界夹取到
    `[0, n − 1]`，`to < from` 收成 `to = from`（"取一件"就是 `from = to`）。
  - **切口落在缝里，不压在字上**：左右沿取所取那几件的盒并集，四边外扩
    `--range-pad`。所以两条竖线站在"从这儿切开"的位置上——这正是它读作取数边界、而不是
    "这组东西被括起来"的原因。**边界**：`--range-pad` 必须小于相邻两件之间的缝，否则
    切口会压到邻居身上（几件挤成一列时宁可改排布，不要靠缩 pad 硬塞）。
  - **窗口会滑，而且滑的那一段是真的在追**：换句那一刻把带的四个数**定在上一拍写到的
    位置**，之后每一拍往**当拍量到的目标**追（easeOutExpo、`--dur-range`）。对象还在
    入场 / 还在挪位时，带子跟着它落位，而不是钉在入场前一瞬的位置上（`lanes` 每拍重写
    带宽是为同一个理由）。追上（`p ≥ 1`）之后就改成直写目标：对象再动，带子跟着动，不再
    补间——否则每一句都会多滑一次。落定那一格必须精确（easeOutExpo 在 p=1 时是
    `.99902`，会把窗口停在离目标半像素的地方，与 `segTock` / `loopTock` 同一纪律）。
  - **读数签是主角**：默认写 `from–to / n`（0 基，与 `slice` 同口径），`lab` 可整句换成
    作者的话，`num:false` 只留带子与切口。签带 `.halo`、压在上沿外 6，**整签压回本步
    声明的取景窗**——与 `.ln-lab` / `callout` 的"放不下就整组不画"反着来：这里读数是
    主角，宁可往里缩也不能被裁掉；窗口比签还窄就居中，上方被顶住了就落到带子下方。
    宽度只在文字变了时量一次（`rangeWrite()` 内），量前把 `display` **属性**临时请回来
    ——藏起来的元素量出 0（与 `laneLabW()` 同一个坑）。
  - **没有跨步账本**：`RANGE` 每步清空、renderer 重挂；`RANGE_P` 只存**上一拍写到的
    四个数**（l/r/y/h），用途只有一个——换句时让窗口从原处滑过去，而不是瞬移。它记的是
    "窗口上一拍在哪儿"（注记的位置），不是对象的历史，所以节点被 `sweep()` 摘走时**连
    账本一起清**（对象都不在场了，窗口上一拍在哪儿没有所指）。
  - **不登记即摘**（与 `callout` / `connect` / `lanes` 同族）：这条带记的是"这一句取的
    是哪几件"，不是对象的历史，所以没有 `gone`；`of` 里有一件不在台上 → 整条静默不
    登记，节点被摘 → 整条一起摘（半条窗比没有窗更误导）。
  - **它不负责压暗**：段外"不用看了"是作者的事（`[data-dim="1"]` 本来就是"这一屏不是
    话头"的原语）。这条带只画"取的是这段"与"从哪儿切开"——两件事一件不落，才不至于
    与 `data-dim` 抢同一个算符。
  - **跨行只有一个框**：所取那几件折行时，带子是它们的盒并集（一个大框），不做多行
    拆分；要分行说就分成两条带（两个 key）。
  - **导出 / reduced-motion / 擦洗**：直接落作者声明的那一格（`from` / `to` 算出来的
    四个数），定格里读到"取的就是这几件"，不是一段没滑完的中间态。

**（20）度量与边界**

- **界线**（`limit()` + `.lim` + `limitTock()`，0.50.0）：把"**够不够**"落成一条读数。
  整张词表在此之前能说"多大 / 到哪儿 / 谁跟谁 / 哪几件 / 几时"，唯独说不出量与一条界
  的关系——`meter` / `countRoll` 只说量自己有多大、没有比较对象，`compare()` 比的是两个
  版本、`range()` 取的是哪几件。于是"预算 / 上限 / 容量 / 安全水位 / 超时 / 误差容限 /
  临界点"这些判断，此前只能靠旁白说"这样就超了"，画面里没有任何东西在说"超了"。
  它回答 §判据里的 `判定` 与 `关系`：变化的是**界内 / 越界这个状态**，推进的是"到这儿
  就换规则"的那一步。
  - **它不画量**：量由作者自己的图形提供（`meter` 的条、一根柱子、一条水位），这一族
    每拍**现量那颗量的边**（`probe`）与界线比。所以"越线"发生在量真的长过去的那一帧，
    不是作者算好放在第几句——这是它比"旁白 + 一根静态线"多出来的东西。不给 `probe`
    就只是一条标尺（"满格到这儿"），不判。
  - **三件东西，各有分工**：界线（一条 + 两端 T 形端头，伸出容器外，让"界"在上下都
    看得见）、界外那一侧的**淡染区带**（**常驻**的图注——"这一侧都不行"；若让它越界才
    出现，"界"就成了事件而不是刻度）、读数（界值；越界时多一行"**超 N**"，那才是这条
    原语的落点）。
  - **`at` 的方向口径**（写反了不报错、只是界出现在镜像位置）：沿**量增长的方向**计。
    x 轴从左往右（`.8` = 右侧八成处），y 轴**从下往上**（`.8` = 靠上，水位 / 栈高 / 柱
    子都是这么长的）。`dir:'max'` = 量超过界算越界（上限、预算、超时）；`dir:'min'` =
    量低于界算越界（安全水位、最低要求、误差下限）。
  - **读数两行、占位恒定**：界值一行、差值一行，差值只在越界时出现，但**那一行一直
    占着**——否则界值会在越界那一刻往上跳一截，同一句里两次读到它停在不同高度。界值
    本身**不换色**（换的是判定，不是刻度）：中性灰的"80"配红色的"超 12"，比红红一片
    更读得出哪个是尺子、哪个是结论。上方两行放不下就整对落到带子下方。
  - **颜色是唯一补间**（`--dur-lim`），几何每拍现写：界线位置是"尺子的盒 × at"、判定是
    "量的边 vs 界线"的比较，两样都是现量，所以擦洗 / 逐帧冷启动 / 导出读同一格。
  - **没有跨步账本**：`LIM` 每步清空、renderer 重挂；`LIM_S` 存的不是历史，是**上一拍
    的判定**，唯一用途是"只在判定变了时切一次 class"（否则每帧都要重写一遍样式）。
    节点被 `sweep()` 摘走 → 连它一起清：留着旧判定，重建出来的同一个 key 会停在上一次
    的颜色上。**无 `gone`**，不登记即摘（与 `callout` / `connect` / `lanes` / `range` 同族）。
  - **缺件静默不登记**：`of` 不在台上、给了 `probe` 但量不到盒 → 整条不登记（半条界线
    比没有界线更误导）。排查顺序：这一步登记过没有 → 尺子 / 量是不是都还在 `#cam` 里 →
    那根量是不是靠 `clip` 裁出来的（`boxIn()` 量的是**几何盒**，不是可见像素；用 `scale`
    或 `width` 长的量条量得到，用 `clip` 裁的量条量出来一直是满格）。
  - **压暗不归它管**：段外"不用看了"仍是 `[data-dim="1"]` / `#spot` 的活。这条线只画
    "界在哪、到没到"——它不负责让别的东西变暗，否则两个算符会抢同一件事。
  - **导出 / reduced-motion / 擦洗**：判定是现量的比较、不是时间决定，所以见旗不需要
    另写兜底——`meter` 在见旗下直接落满，判定自然落"越界"，定格里读到的就是那一格
    （"这一句念完，超了 / 没超"）。

#### 3.4.4 导出与减动效

截图页注入 `transition:none!important;animation:none!important` 且每帧冷启动；
`prefers-reduced-motion` 关闭动效。两者落的是**同一族终态**，按机制分四类：

| 机制 | 代表原语 | 落点 |
|---|---|---|
| animation + `backwards` | 擦除 / 羽化揭示、`.gather`、`.settle`、引线标注的点 / 线 / 签 | 计算值回到元素自身值（全显 / 收好 / 静止盒） |
| animation 无 `forwards`，静止态即全开 | `.bloom`、`.ffwd`、`.opt.rip`、`.flow`、`.traces` | 切掉后落"看不见"或"全开"，不留半截 |
| transition | `.tuck*`、`.flip`、`.ride`、`.tilt`、`.lift`、`.swap`、`#spot`、`--cam-dur`、对焦、`callout` 的收回与跟随 | 落到 after-change style，即那一秒的真实档位 |
| JS 逐拍状态 + transition | 词拍（`cueWrite()` 写 `.on`、`cueGeom()` 现量几何） | 导出 / reduced-motion 切掉 opacity / scale 补间，括号完整、无缩放；定格帧在句末，标记已累积、几何量到的是入场落定后的终值 |
| JS 逐拍 + 注册属性 transition | 对照窗（`compare()` / `drawCompares()` 写 `--cmp-r`） | 直接写当步 `opt.at`；`--dur-cmp` 为 0 时互补裁切、接缝、四角框与标签同步落终值，两端 0 / 100% 只剩一份 |
| JS 逐拍写 transform | 拆解视图（`explode()` / `drawExplodes()`） | 直接写当步 `amount` 对应的 `transform`；`--dur-ex` 与错峰延迟归零，拆开 / 合拢都落终值 |
| JS 逐拍，但语义是过程 | 数字落定（`countRollWrite`）、量条（`meterWrite`） | 导出 / reduced-motion 落终值（数字落 `data-count` 终值、量条落 `scale(1 1)` 全满，定格里读"量"）；live 播放逐拍滚中间值 |
| JS 逐拍（dashoffset）+ 仅 d 的 transition | 关系连线（`connect()` / `connTock()`） | 生长落 `stroke-dashoffset 0`（线完整，定格里读"这两件有关系"）、`gone` 收回落移除（关系不成立）；`dashoffset` / 标签透明度逐拍、`d` 走 transition（切掉即"已跟到位"） |
| JS 逐拍写 scale + animation 入场 | 细节镜（`loupe()` / `loupeTock()`） | 落 `scale(k)` + 透明度 1、`gone` 直接不可见（定格里读"这一块放大后是什么"）；`lid` 的平移 transition 与圈 / 内容的 `@keyframes loupeIn` 切掉即"已落位"，`zoom` 逐拍无 transition |
| JS 逐拍写 `d`（中间帧是采样折线） | 形变（`morph()` / `morphTock()`） | 落**作者声明的那条 `d`**——登记那一刻已经写进属性，见旗只是不再补中间那些折线；冷启动首见即建档，成片每格都是精确轮廓；`.morph` 的清单里没有 `d`，切不掉也不需要切 |
| JS 逐拍写 `stroke-dasharray`（属性 + inline style 双写） | 进度（`drawTo()` / `segTock()`） | 直接落作者声明的 `at`（`stops` 按站取档），已走段与副本一起定格；副本是静态虚线，无需切；`transition:none` 保证逐拍写值不被补间拖住 |
| JS 逐拍写 `transform` 属性（落点由落点梯现算） | 圈数（`loopTo()` / `loopTock()`） | 直接落作者声明的那一圈 `at`（`base + stops[at]` 现算），游标、`k/n`、落点痕同批摆回原处；`LOOP_RUN` 不留飞行中的趟，`gone` 落回基位并连账本一起收；`.lp` 的 `transition:none` 保证逐拍写值不被补间追，确认拍那枚 `.lp-pop` 的 `@keyframes` 切掉即 `scale:1`（不进兜底清单） |
| JS 逐拍写 `width` / `d`（无 transition、无账本） | 时序带（`lanes()` / `lanesTock()`） | 实心段宽与针位都是 `(t − stepT0) ÷ dur` 的纯函数，见旗直接取 1 → 几条实心段一起满、针停在带右缘；冷启动与直播同一格，所以**不需要**兜底清单，也没有 `gone`（不登记即摘） |
| JS 逐拍写几何，只有"注记位置"账本 | 区间窗（`range()` / `rangeTock()`） | 直接落 `from` / `to` 算出来的那一块（带子、两道切口、读数签同批），`RANGE_P` 记的是屏幕位置不是对象状态；冷启动与直播同一格，不需要兜底清单，也没有 `gone` |
| JS 逐拍现量 + 只有颜色补间 | 界线（`limit()` / `limitTock()`） | 判定是"量的边 vs 界线"的现量比较，不是时间决定，所以见旗不用另写兜底：`meter` 落满 → 判定自然落"越界"；`--dur-lim` 被 `transition:none` 切掉即终态；没有跨步账本，也没有 `gone` |
| 离散 / 静态 | `.pregate`、`.crisp`、`.halo`、`.stag`、`text-spacing-trim` | `hidden` 即时生效；静态口径本就不变 |

口径：

- **终态必须落在属性上**：`animation-fill-mode` 用 `backwards` 或不写；循环动画的
  `0%` 必须等于静止态；
- **只关补间，不关档位**：`data-pan` / `data-lift` / `data-go` / `--spot-*` /
  `--swap-route` 这些读数照旧写出；清单里不许出现它们；
- **过渡由状态驱动时天然安全**（`.tuck` / `.flip` / `.ride`），由 animation 驱动时
  要确认终态不依赖 `forwards`；
- **reduced-motion 兜底要真的盖过基础规则**：基础规则写在媒体块**之前**时同特异度
  后者胜，不用抬；写在**之后**（折叠、侧栏、掠光、涟漪、`.pregate`）必须抬特异度
  （`li.note` / `ul.notes>li.note` / `#gate-next` / `#gate-block` / `#pregate`）；
- 让拍（`transition-delay` / `animation-delay`）要在兜底里**单独归零**——全局
  `.01ms!important` 的时长钳制管不到 delay。

#### 3.4.5 常见静默失效

这些错误不会报错，只会"看着像没生效"：

- **CSS 简写互相顶掉**：同一节点两条 `transition` 简写（`.nt` 与 `.tuck*` /
  `.flip` / `.lift` / `.swap` / `.trail`）后写的那条把前一条清单整串清掉。原语只挂
  纯包装 `<g>`，或只写长档 `transition-delay`。
- **`animation` 简写引用未定义的自定义属性**：整条在计算值阶段作废、动画根本不跑。
  缓动/时长要么给字面量，要么保证令牌在 `:root`。
- **`animation-delay` 里的 `calc()` 缺空格**（`sibling-count()-1`）；**分母为 0**。
  都是整条作废，动画照跑、延迟全 0。
- **`@property` 注册名撞上现有色值令牌**（如 `--dim`）：全页 `color:var(--dim)` 在
  计算值阶段非法，整条作废。注册前全仓 grep 同名令牌。
- **不成对的注释**：漏开 `/*` 的收尾 `*/` 会把紧跟的那条声明吞进去，CSSOM 规则数
  不变，只有 `:root` 的解析结果少一项。改完 `<style>` 先扫注释配对，再断言令牌在
  解析后的 `:root` 里。
- **对已入树的节点重复 `appendChild` / `insertBefore`**：DOM 插入会先摘下再插回，
  浏览器**重放 CSS 动画**（划线每步重划、荧光笔同句划两次），而静态断言全绿。
  helper 只在"位置不对"时才搬节点。
- **`transform` 属性 + 独立 `scale` 同节点**：合成顺序 scale 先于 transform，位移
  会被缩放。居中用独立 `translate`，位移与缩放分层。
- **`getScreenCTM()` 量补间中的目标**：拿到的是上一帧矩阵。要"最终在哪"就读
  `transform.baseVal`。
- **拿 `el.style` 读补间中间值**：读到的是刚写进去的目标值。插值中的那一格只有
  `getComputedStyle` 读得到；`CSSTransition` 也没有 `.delay`，delay 在
  `getComputedTiming()` 上。
- **量 SVG 文字宽度**：`getBBox().width` 是墨盒，会随字面抖动；钉宽度、算容器宽都用
  `getComputedTextLength()`。
- **引线标注静默不画**：`callout()` 的几何是现量的，量不到（节点不存在 / 空盒）、
  签比这一步的取景窗还宽、或钳回安全区后会压住被注对象时，**整条注记直接跳过**，
  不报错也不留半截。排查顺序：被注节点这一步在不在台上 → 取景窗够不够宽 →
  朝向是不是把签挤到了对象身上。
- **关系连线静默不画**：`connect()` 的几何是现量的，量不到（节点不存在 / 空盒）、
  或两端距离 < 24px（贴脸）时**整条线直接跳过**，不报错也不留半截；标签塞不下时
  线照画、标签缺席（生长 35% 后才浮现）。排查顺序：两端节点这一步在不在台上 →
  间距够不够 → 标签测量时字体是否就绪。
- **细节镜静默不画**：`loupe()` 的目标要么量不到（节点不在台上 / 空盒），要么
  **四侧都放不下**——取景窗比镜还小时（`2r+4` 超窗宽或窗高，窄窗里最常见），或
  目标四周都贴着窗边；两种情况都**整只镜跳过**（不画圈、不画茎），也不报错。
  排查顺序：取景窗尺寸（镜半径 52 → 至少要 116 的窗宽 / 窗高）→ 目标四周是否
  有 26 + 52 的空位 → 目标这一步在不在台上。另：镜里是**建镜那一刻的副本**，
  目标若在之后的同一句里还接着补间，镜里停在旧形态——这是设计（镜读"结果"），
  要读中间态就别用 loupe。
- **拆解视图的 transform 被写两次**：renderer 先写装配位、`drawExplodes()` 再写
  目标时，CSS 已经在第一笔写下时用**上一步的 `--ex-delay`** 起跑；随后改延迟不会
  改这一趟补间，表现为"拆开正常、合拢时内外圈错峰反了"。修法是 renderer 只给
  `opt.base` 坐标，不写这层的 transform。另：`opt.base` 缺项 / 非有限数时整组静默
  跳过，`EXPLODE` 的登记每步都会清空——renderer 忘了重挂，下一步就收回装配位。
- **形变被 `put()` 顶掉**：`d` 同时写在 `put()` 的属性表和 `morph()` 里时，`put()`
  在换句那一刻把半路的采样折线覆写成新目标，`morph()` 随后读到的"旧轮廓"已经等于
  新目标 → 不登记飞行 → 画面直接跳成终态，而且**没有任何报错**（探针 A20 就是照这个
  反例写的）。`d` 只从 `morph()` 声明。
- **形变与 CSS 的 `d` 补间抢同一条轮廓**：节点同时挂 `.nt`（清单里有 `d`）而不挂
  `.morph` 时，JS 每帧写的折线会被 CSS 再补间一遍——中间帧慢一拍、收尾落不回作者
  那条精确轮廓，肉眼读起来像"变形完了还在那儿抖"。`.morph` 存在的唯一理由就是把
  `d` 从清单里摘掉。
- **指望 `.nt` 自带的 `d` 补间做形变**：那条要求两条路径**命令序列同构**，`M L L Z`
  对 `M C C Z` 不补间、直接跳档（浏览器不报错，`getComputedStyle` 读到的就是终值）。
  跨"角 ↔ 弧"的形状更替必须走 `morph()`。
- **进度被 CSS 兜底值顶掉**：`stroke-dasharray` 只写在呈现属性上时，`.seg` 那条
  `stroke-dasharray:0 9999` 的 class 规则优先级更高，把 JS 写进去的进度整个盖回零
  ——属性上明明写着 `342.6 492`，画面上却一动不动，**没有任何报错**。`segWrite()`
  因此属性和 inline `style` 两处都写。另：兜底值用 `0 1` 时周期只有 1 个用户单位，
  抗锯齿把它渲染成半透明实线，看起来像"线画重了"而不是"还没开始"。
- **进度静默不画**：`drawTo()` 只认 `<path>`（rect / circle / group 一律跳过），
  `getTotalLength()` 为 0 或 NaN 也不画、不登记。排查顺序：节点 tagName 是不是
  `path` → 它的 `d` 是否有实际长度 → 这一步它是否在台上（`isConnected` 为假时副本
  连同账目一起被收掉，那是设计——路被 `sweep()` 摘走，虚线也不该留在原地）。
- **窗口静默不画**：`range()` 只登记"整排都在台上"的窗——`of` 为空、任一节点不在这一步
  的台上，都整条不登记，`rangeBox()` 量不到盒也不画。排查顺序：这一步登记过没有 →
  那几件是不是都在 `#cam` 里 → 它们有没有 `getBBox()`（纯 `<g>` 空组量出 0）→
  这条带是不是被"量不到"收走了（下一句换句时 `layoutRanges()` 会再判一次）。
- **带子垫到内容底下就"只剩两道线"**：取景带的底色画在卡片**之上**（`#ranges` 排在
  所有幕之后、其余注记之前）——它读作"荧光笔划在整排上"。挪到卡片底下（或卡片有实心
  fill 时），底色会被卡片自己的 fill 整块盖掉，画面上只剩两道切口，**看起来像"带子
  没画出来"**，数值全对。与 0.46 `#veilplay` 压住半条路同一课：目测异常先确认遮挡
  关系，再怀疑样式。
- **`--range-pad` 大过缝就压到邻居身上**：切口的位置 = 所取那几件的外沿 + pad，pad 与
  "相邻两件之间的缝"是同一把尺子。缝 8、pad 5 时切口正好落在缝里；把 pad 调到 12，
  两道竖线就会穿过左右邻居的卡片边框——不报错，读起来像"取的范围比说的大"。几件挤成
  一列时改排布，不要靠缩 pad 硬塞。
- **界线画在镜像位置**：`at` 的方向是"沿量增长的方向"——y 轴**从下往上**。照 x 轴的
  直觉写 `.8`，横向是对的、纵向的界会跑到下方两成的位置。它不报错，只是"界"出现在量
  永远到不了的那一头；`dir` 写反同理（该报"超"的时候报"差"）。
- **界线永远判"满格"**：`probe` 指的那根量条如果是用 `clip` / `mask` 裁出来的（而不是
  `width` / `scale` 长出来的），`boxIn()` 量到的是它的**几何盒**（一直满格），判定永远是
  越界。量的表达必须是几何：条宽、`scale`、位置——裁切只影响看得见的部分，不影响盒。
- **界线静默不画**：`of` 不在这一步的台上、`at` 不是有限数、给了 `probe` 但量不到盒，
  都整条不登记（半条界线比没有界线更误导）。排查顺序：这一步登记过没有 → 尺子与量是不是
  都在 `#cam` 里 → `at` 是不是写成了 `'80%'`（只认 0–1 的比例，`--lim-cap` 那类令牌才
  是 px）→ 是不是被"量不到"收走了（下一句换句时 `layoutLimits()` 会再判一次）。
- **界线读数跟着量往左漂**：用 `transform="scale(s 1)"` 长量条时，**属性变换按局部原点
  (0,0) 缩放**，`transform-origin` 只管 CSS `transform`、管不了这个属性——量条要不是
  `x:0` 放在已经定位的组里（`.meter` 就是这么摆的），缩放会把左边缘也一起拽过去，量的
  右边缘到不了该到的位置，判定与"超 N"跟着漂（实测同一条 `scale(.9)` 读成 .59，误差 21
  而不是 10）。要么 `x:0` + 组定位，要么直接写 `width`。
- **圈数没动，但注记在动**：宿主这一层的 `transform` 被 renderer 也写了一遍（最常见是
  照抄别的原语时顺手补了个 `transform:'translate(0,0)'`）。`loopWrite()` 每拍把落点写进
  `transform` **属性**，同一拍里 renderer 的 `put()` 又把属性覆写成基位 → 对象原地不动、
  游标与痕却照常走，读起来像"注记脱开了东西"。宿主是纯包装 `<g>`：`base` 从 `loopTo()`
  给，这一层不留第二支笔。
- **圈数收尾落不回那一格**：忘挂 `.lp`（或把 `.nt` 挂到了宿主上）。JS 每帧写属性、CSS
  再补一遍同一位移 = 双重缓动，中间帧慢半拍、终差一格；`layoutLoops()` 只兜"没挂
  `.lp`"这一种，`.nt` 是作者自己挂上去的，得自己摘。
- **圈数静默不演**：缺 `base`、`stops` 为空、节点不在这一步的台上、`at` 等于已绕圈数
  ——四种都不报错也不动（最后一种注记照常给读数）。排查顺序：这一步登记过没有 → 节点
  在不在台上 → `at` 与 `LOOP_P[key]` 是不是同一个数。
- **时序带摆到了看不见的那半截舞台**：安全区取了 `VIEW` 而不是本步声明的取景窗。镜头
  推到 `[230, 61, 580, 120]` 那一格时窗底 181，按 `VIEW`（底 394）判"下方放得下"，带子
  就落在镜头外——**播放里看不见、探针里数值全对**。`layoutLanes()` 把 `(CAM[sid])[step]`
  存进 `s.__win`，`laneWrite()` 只认它。
- **时序带的标签全叠在同一行**：标签的 `y` 在 `laneBuild()` 里写了一次常量。道与道之间
  只差 `--lane-h + --lane-gap`（11 个世界单位），常量写法让第二条道的字落在台顶，而带宽
  与针照旧——看起来像"标签丢了半截"。`y` 与 `x` 一样归 `laneWrite()` 每拍写。
- **时序带读不到"道高"**：`height` 写成 `--lane-h / 2`（`rx` 取一半是对的，高度不是）。
  行距仍按整道排，于是每条道下面空一截，镜头拉远时读成"两条虚线"而不是"两条轨"。
- **时序带每帧都在重写**：`laneSet()` 比较前没 `String(v)`——`getAttribute` 取回的是
  字符串，`'3' !== 3` 恒真，同值不重写形同虚设（这一族每帧全量跑，代价直接体现在掉帧）。
- **时序带标签量到 0**：`laneLabW()` 读了 `style.display`，而隐藏时写的是 `display`
  **属性**。属性藏起来的东西要用 `getAttribute('display')` 请回来，否则永远量到 0、
  标签"放得下"的判断永远成立。

### 3.5 阈值

```js
if (step >= 3) showToken();
if (step === 4) flashOnce();
```

阈值直接写成常量，不用由句数推导出的魔法表达式。

```html
<rect id="cap-prog" .../>        <!-- 可选：句内进度细线（派生视图） -->
```

每次 `sentAt(t)` 返回当前句时，把该句对象交给 `capShow()`。页面不维护第二份字幕表。

说话人标签是同一句数据的**派生视图**：`capShow()` 把 `s.speaker`（对话讲稿经
`build_timeline.py` 透传的 label，见 `script.md` §1.5）写进标签，没有 `speaker` 时
留空。它**不碰 `#cap-text`**——QA 比对的是字幕节点本身；标签文案只是称呼，不得复制
旁白正文。

### 4.2 空档与结束态

- **空档保留上一句**：换场空档（`scene` 为 `null`）与场景内两句之间的空档
  （`index < 0`）都不清空字幕带，停在上一句上。只有开场前（还没有上一句）与课程
  结束才收起。`check_gates.py` 在两处各放探针。
- **结束态回拖**：`ended` 收起整条带子后，把进度条拖回**最后那句之内**时句号没变、
  换句分支不进，必须靠"这一拍有活跃句子"补回来——`tick()` 里按
  `capSent !== hit.sentence` 补一次 `capShow`。画面与读数都回来了而字幕空着，就是
  状态不再是 `currentTime` 的纯函数。

### 4.3 派生视图

`#cap-hl`（结论色带）、`#cap-prog`（句内细线）、`#cap-speaker`（说话人）都不算第二
份文案：几何从 `#cap-text` 现量、内容由当句数据算出，QA 的比对节点始终是
`#cap-text`。

| 视图 | 几何 | 更新 |
|---|---|---|
| `#cap-hl` | `getBBox()` 现量 | 补间 `x` / `width`，同时写呈现属性 |
| `#cap-prog` | `capMeasure()` 一次存 `capGeo` | 每帧只写 `width`，不挂 transition |
| `--lit` | `mask-image` 停靠点 | 每帧写 `style`，不改几何 |
| `#cap-speaker` | 文本由数据算 | 与 `#cap-text` 同拍 |

跟读点亮是三者里唯一**只碰呈现**的一层：`textContent`、`getBBox()`、
`getClientRects()` 全部逐值不变。

一条**量出来的纠正**：clip-path 与 mask 对 rect / bbox 的影响其实相同（都不会让
`getClientRects().length` 变 0），差别只在**命中测试**——`clip-path` 会裁掉命中、
mask 不裁。所以 `captionShown()` 那套"祖先链样式 + client rects"的判据对 `--lit`
完全安全；反过来，需要 Learner 点的图元不能收在 clip-path 后面（见 `.tuck*`）。

## 5. 连线要真的连上（几何）

连线（实线 / 虚线 / 带箭头的都算）**两端必须落在它连接的两个图形的边界上**：不悬空
留缝，也不插进图形内部。

- 端点坐标**从图形算出来，不靠手感给**：矩形用 `x` / `x + width`，椭圆用
  `cx ± rx`；算完让两端各留 **2 单位呼吸缝**。
- **带 `marker-end` 时终点再缩一个箭头长度**，否则箭头会压进目标图形、或与它的边线
  叠在一起。缩多少由自己的 marker 决定：`refX` ÷ `markerUnits` 的换算结果，量级通常
  在 **8–10 单位**。
- **改了图形的坐标 / 尺寸后，回来把它所有的连线一起改**——连线是图形的派生数据。
- 导轨（时间轴主线、分支轨道）本来就自由延伸，不受这条约束；受约束的是**连接件**
  （把 A 指向 B 的那根线）。

## 6. 内容底线

字幕带有固定区域。主要图形留在分隔线以上，不与字幕重叠。真实尺寸由 `viewBox` 与
内容并集决定，不把模板某个数字当成通用魔法数字。

**每一步的画面重心都要落在画布横向中线上**（viewBox 宽的一半）。桌面全屏 / 宽视口
会把画布撑到最宽，偏心在这个尺寸下最扎眼；紧凑态（窄屏、横屏手机）反而看不出来
（`camSet()` 在窄屏按内容包围盒自动取景），所以只在桌面截图很容易漏。两种常见病因：

- 成排图元的行中心 ≠ 画布中心；
- 分步生长的流程图：不长的步态留右侧大空带。解法是按步态给整条管线配平移，长出的
  那一步再归位。

用相机配平更省事：窗的中心会被钉到可用区中心，所以**把窗写正，重心就正**（§3.3）。
改完构图仍要逐场景量一次 `getBBox()` 中心（或全屏截图目测）——导出是每帧冷启动，
**每一步都得单独站得住**。

## 7. emoji 装饰：默认装饰层

**默认给画面图元和侧栏配 emoji 锚点**，不等用户开口要。装饰仍服从纪律 2.4：图形优先，
emoji 只是记号的点睛。

- 每个概念记号**至多一个** emoji，贴着图元文字写（`📤 push`、`🧩 action`）；
- 选**语义贴合**的，不选热闹的：比喻要能帮记忆；
- 静态呈现：emoji 不驱动状态、不参与步进，renderer 里不许为它造计时；
- 三条禁区：**旁白 `text` / 字幕不放**（TTS 会念出来，且破坏字幕唯一来源）；**门禁
  题面与反馈不放**；**QA 钩子节点不放**。

## 8. 画面来源与对比度

### 8.1 先定呈现，再定来源

内联矢量绘制仍是默认形态。本节只回答一件事：这一段观众该看到什么、素材从哪里来。

| 内容特征 | 首选呈现 |
|---|---|
| 顺序 / 流程 / 关系 / 对比 / 状态（绝大多数讲解步） | 内联 SVG |
| 数值比较 / 占比 / 趋势 | 数据图表，以内联 SVG 绘制 |
| 真实人物、产品、地点、事件现场 | 真实照片（用环境任一可用的联网检索能力） |
| 外观 / 场景 / 氛围意象 | 图片生成能力 |

两条边界判据：**抽象且不承载严谨数据 → 意象图；抽象但逻辑严谨 → 内联示意 / 图表**。
有明确真实实体的内容不要用生成图替代事实照片。

"联网检索""生图"都是**能力泛称**：用当前环境里任一可调用的执行；一个都没有时直接
退回内联 SVG 绘制——它是 always-on 的兜底形态。

### 8.2 生图与降级链

选生图时：prompt 先描述"讲什么"（主体 / 场景 + 核心动作或结构）再描述"怎么画"
（风格、背景明暗），构图优先接近画布横向比例、主体居中；同一课的多张图锁同一套背景
明暗与风格词；**图内不放文字**——可读信息由图元标注和字幕承担。

素材只承担**增量信息**：旁白和图元标注已经把话说清时，不要为填满画布配图，也不要为
"高级感"堆 3D、仪表盘、拼贴这类不帮助理解的装饰。

降级链：照片检索失败 → 意象生图 → 简化内联示意，逐级**降低视觉复杂度**，绝不为了
补画面编造信息。

### 8.3 素材纪律

- 外部素材落进课件目录并记录来源；真实照片要打开原图核对，不看缩略图选图；长边低于
  约 1200px 的图进入成片容易发虚，宁降复杂度不硬凑。
- **来源只进文件，不进画面**。出处、生成方式、工具名写进项目目录里的记录文件（如
  `assets/provenance.json`）；给图配注脚只配**内容性**的。
- 不以 AI 生图冒充现场照片；同一张泛化图不反复盖到多个不相关场景。
- 数据红线：不为"好看"改数字，估算值必须标明，不用截断坐标轴、面积失真对比等误导
  比例，不省略单位，不编造数据点。

### 8.4 图内文字：对比度三查

判据（WCAG）：正文与标签 ≥ 4.5:1，图内大标题 ≥ 3:1，低于线重画。图内小字还要经
响应式缩放与视频压缩，**次要文字按 ≥ 7:1 取色**。

三条最常踩的：

- **深色文字只能待在明确的浅色底板上**。改任何底板颜色，同时复核压在它上面的全部
  文字；`fill` 能就近写死就别靠 `<g>` 继承。
- **主题背景色族不得当文字色**。判据是"这个色值属不属于背景族"，不是"看着有没有
  对比"。
- **半透明按合成后的颜色算对比度**。要弱化文字就换一个更暗（或更亮）的实色，不要用
  透明度表达层级。

外部 SVG 素材若以 `<img>` 载入是独立文档，页面字体变量渗不进去，其内部 `<style>`
要自带中文无衬线字体栈；且它内部的文字对 `check_gates.py` 完全不透明——这正是不作
特殊要求时画面留在内联渲染的理由。
