# 交互与门禁

## 1. 什么时候才做门禁

只有当学习者必须做出一个可观测判断，并且这个判断改变后续理解，才做门禁。

推荐每课 1–2 道，长课最多 3 道。不要每节都放一道题来制造“互动感”。

范本 `references/template.html` 是为演示契约写的，对它的 `check_gates.py` 报告不是
交付基准：五种题型各一道（恒报"超过 3 道"警告）、不带 `audio/` 与 runtime 副本
（静态检查它——`check_gates.py references/template.html`——会恒报三条 error：缺主音频、
缺 timing、缺 runtime）。正式交付页不要照抄这些形态。

侧栏参考资料与纯手感实验不产证据。

反过来也要守住下界：门禁放行（`data-locked`）的语义是"当堂经提示后答对"——错答不记、
可无限重试。它是继续的许可，不是掌握的声明，页面上不要因为它而写"已掌握/已通关"：
掌握的断言需要跨课时的记忆，那是平台系统的事（SKILL.md §1「Skill 不背平台基础设施」）。
`recall` 的放行更弱一档：只表示"完成过对照"，连"答对"都不主张。

## 2. 题型选择

判断 → 类型的映射表以 SKILL.md §6 为准；不要为了统一而全部做单选。

`recall` 是五种题型里唯一不判定的（机器核不了口头复述）：它的价值不在"拦住答错的"，
而在"逼一次主动回忆"——检索练习本身就是教学动作，对照参考答案即闭环。
适合放在**生成性转折点**（学完一个方法，先自己说一遍再往下走）。
别的题型可以滥用 `recall` 来水门禁，但它没有判错能力，水了就是自欺：
一道课 1–2 道门禁里最多占一道。

### hotspot 的可点区放哪

可点区是**盖在示意图上的绝对定位按钮**（`left`/`top` 用百分比，图缩放时跟着走），
不是画布 SVG 里的 `<g>`：门禁浮层开着时画布被盖住，点画布上的部位等于让学习者
隔着一层雾答题——把那张需要点的图**放进题目卡里**最稳。用真 `<button>`（或任何
带 `data-hotspot-id` 的可聚焦节点）而不是 SVG 图形，键盘和触屏才点得到；圈里不
写字，写了等于给答案，虚线描边本身就是"这里可以点"的提示。

## 3. 门禁锚点

### 场景开始

适合考**前面已经讲过**的内容。锚点就是 `scene.runtime.start`：时间走到该场景
第一句开口之前，门禁浮出（默认形态，`at` 缺省即是）。

挑旧内容时往**远**了挑：一两景之前的结论、甚至更早的，而不是刚说完的那句。单堂课里
能拉开检索距离的只有这个位置——学习者快要忘了再被要求想起一次，这一下本身就是教学；
考"刚说完的下一句"只是把旁白按了暂停。

### `at: 'end'`

适合考本场最后一句刚讲完的内容。锚点必须是：

```js
lastNarration.start + lastNarration.duration
```

而不是“最后一句的 `index`”。否则会在最后一句开头就停，直接掐断旁白。

### 不要在句中打开

门禁应该落在场景开始或某句结束后的空档。

### 导出的时间线上没有门禁

线性视频不存在"答对才继续"，`export_video.py` 在截图页抑制门禁；旗标注入与
页面侧唯一契约（`syncGate()` 见旗直接 return）以 runtime.md §7 为准。

## 4. 页面门禁控制器

```js
var GATES = [
  {scene:'seg-3', type:'choice',   preGate:true, ...},
  {scene:'seg-4', at:'end', type:'hotspot', preGate:true, ...},
  {scene:'seg-6', type:'sequence', preGate:true, ...}   // 开头门禁考的是前面讲过的步骤
];
```

这是**页面自己的控制器数据结构**（runtime 不认识 `GATES`，它只认 DOM 上的
`data-interaction` 配置）。范本里的字段：`scene`（挂哪个场景）、`at`（缺省=场景
开头，`'end'`=末句播完）、`type`、`preGate`、`q`，加上按题型四选一的题面数据
`opts` / `spots` / `items` / `seq:{items,correct}`（`recall` 用第五种 `a`=参考答案）
和可选 `fb`。`bucket` 的判定字段在**条目自身**上：每个 `items` 项带
`correct`（该项应放入的筐 id，范本筐是 `'same'` / `'diff'`）和可选 `feedback`
（该项答错时单独给的反馈）；**不要**在 `items` 外另写 `answer` / `fb`——
那是 runtime 的 `data-interaction` 层契约（runtime.md §5），`buildBucket`
只认条目上的 `correct` / `feedback`；配错格式的后果是门禁开出来没有答案、
被运行时 fail-closed（`[gate] 门禁打开失败`）。页面把每一项
翻译成对应卡片的 `data-interaction` JSON 后调用 `window.coursewareStudioWire()`
重新接线；调用点必须在**揭开门禁浮层之前**——契约抛错时浮层还挂着 `hidden`，
学习者不会看到一张永远点不动的半开门禁。runtime 的可选文案键（`wrong_text` /
`hit_text` / `unplaced_text` 等）见 runtime.md §5。

`preGate` 只负责短暂过渡，不承担新的学习内容。

单槽位是**页面门禁控制器**的约定（runtime 对"门禁"一无所知）：同一时间只有一道卡
可见——常驻多卡切 `hidden` 或换入换出都可以，`#gate-host` 不要求只存在一张卡；
同一个 scene 最多挂一个 gate，重复配置会被 QA 判错。

门禁浮在画布内。开门禁时舞台会抬高下限保证卡片装得下（契约与理由见
layout.md §2）。不改成盖在画布上方的悬浮层——那样点击目标会飘。播放器行保留在
下面，但变灰且 `inert`（键盘也绕不过，见 layout.md §5），避免绕过门禁。手机上
卡片靠竖滑看全，作答靠点选（sequence / bucket
的触屏通路见 runtime.md §2，别指望手指拖）。

答对后给明确的“继续”按钮，不自动跳走。

## 5. 错答 / 对答状态

页面观察：

```js
MutationObserver → data-locked
```

错误：

```text
反馈出现 → 不锁 → 继续隐藏
```

正确：

```text
data-locked="1" → 禁用当前题目 → 显示继续
```

## 6. 提示文案

反馈只回答：为什么错、为什么这次对。

不要把完整讲稿再塞进题目卡里；门禁是一个判断点，不是第二条字幕轨。

## 7. 自检

- [ ] 题型与认知动作匹配；
- [ ] 题面只考已经讲过的内容；
- [ ] 锚点在句首或句尾，不截断旁白；
- [ ] 错答不写 `data-locked`；
- [ ] 对答写 `data-locked="1"`；
- [ ] 对答后继续按钮明确可见；
- [ ] 没有把门禁题面重复写成字幕；
- [ ] `choice` / `hotspot` 恰好一个正确项；
- [ ] `sequence` 的 `correct_order` 与全部条目一一对应；
- [ ] `bucket.answer` 完整覆盖全部条目，且只引用已存在的筐。
